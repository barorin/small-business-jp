# コネクタ中立 — プラグイン共通ルール

適用範囲: **すべてのスキル、コマンド、参照ファイル、初期設定の流れ。** これは
このプラグインにおける Anthropic の立ち位置であって、ハウスの好みではない:
何を呼ぶかは経営者のツール構成が決める。経営者がどの製品を使うべきかを
プラグインが決めることはない。

---

## ルール

**同じカテゴリのコネクタは同格（ピア）である。** 会計ソフトは会計ソフト。
CRM は CRM。メールはメール。どのスキルも、そのうちの一つを既定、主要、
優先、フォールバックの連携先、代替、格下の経路と呼ばない。接続されている
ものを名指しし、それで動く。

このルールが適用されるカテゴリと、今日そこに属する連携先（並びは五十音／
アルファベット順。プラグイン内で複数を列挙するときは常にこの順）:

| カテゴリ | 連携先 |
|---|---|
| 会計ソフト | freee会計、マネーフォワード クラウド会計、弥生会計（Xero、Zoho Books など海外製を使う事業者も同格） |
| 給与計算・労務 | freee人事労務、マネーフォワード クラウド給与、SmartHR、ジョブカン |
| 勤怠 | ジョブカン勤怠、KING OF TIME、freee人事労務、マネーフォワード クラウド勤怠 |
| CRM | HubSpot、kintone、Monday.com、Salesforce、Zoho CRM |
| リード情報の補完 | Apollo、Clay |
| メール | Gmail、Microsoft 365 |
| カレンダー | Google カレンダー、Microsoft 365 |
| チャット | Slack、Chatwork、LINE WORKS、Microsoft Teams |
| 決済サービス | PayPal、Square、Stripe |
| ネットショップ・POS（注文と在庫を持つ） | Shopify、Square |
| ファイル | Google Drive、Microsoft 365（OneDrive/SharePoint）、Box、Notion |
| サポート | Zoho Desk |
| 電子契約 | DocuSign、クラウドサイン、GMOサイン |
| 経費精算 | Expensify、マネーフォワード クラウド経費、楽楽精算 |
| メール配信・LINE | Mailchimp、LINE公式アカウント |
| デザイン | Canva |
| 会議 | Zoom |
| タスク・プロジェクト | Atlassian（Jira/Confluence）、monday.com、Notion、Trello、Zoho Projects |

Salesforce は経営者が追加するカスタムコネクタとして接続する（Headless 360
サーバーは組織ごとのアドレスと OAuth クライアントを持つ）。プラグインの
マニフェスト経由ではないが、追加されれば他と同じ同格の連携先である。
マネーフォワード クラウド会計は Claude のコネクタディレクトリから接続する
（マニフェスト外）。接続されれば会計ソフトのカテゴリで同格である。
freee会計、弥生会計、kintone、Chatwork、クラウドサイン、SmartHR、ジョブカン、
LINE公式アカウントなど、この表にあってマニフェストにない連携先は
`build-connector` で接続する。`build-connector` はまずコネクタディレクトリを
探し、なければ Zapier 経由で接続し、それもなければ CSV エクスポート前提の
経路を組む。表にない連携先も同じ経路で接続でき、接続された時点で、その
カテゴリの同格の連携先になる。

## 「同格」が実務で意味すること

**ゲートはカテゴリで判定し、製品で判定しない。** 会計ソフトが必要なスキルは
「会計ソフト（freee会計、マネーフォワード クラウド会計、弥生会計 など）」と
書き、どれか一つでゲートが開く。ルーターのコネクタ対応表も同じ書き方をする。

**同一カテゴリに二つ接続されていたら、両方読み、合計は一方から取る。** 各
コネクタは自分だけが持つものを供給する。一か所から来なければならない数値 —
現預金残高、売上合計、売掛金残高 — は、その実行で経営者が「正」と名指しした
方から取り、出力にどちらから取ったかを書く。同じ数値を二つのコネクタで足し
合わせない: 二重計上になる。ルーターのステップ5の選択肢が経営者に名指しして
もらう手段で、答えはセッション中は有効、事業コンテキストに保存してもよい。

**機能の限界は機能として述べ、評価として述べない。** 「このコネクタには
支払請求書の書き込み経路がないので、入力用にエクスポートする」は機能の
記述。「freee会計はここでは読み取り専用なので、マネーフォワードに移行中なら
そちらの方がよい」は順位付け。前者を書く。コネクタがスキルの一部を本当に
できないとき（弥生会計は CSV なので銀行明細の未仕訳を直接読めない、
読み取り専用の会計コネクタは仕訳を投稿できない、マネーフォワード クラウド
会計には売掛金の期日別滞留レポートがないので補助科目付き試算表と請求書
から組み立てる）、できないことと代わりにスキルが何をするかを一行で書き、
他の製品と比較しない。

**従量課金のコネクタは、使う前に費用を言う。** リード情報のコネクタは補完
した行ごとにクレジットを消費する。それを使うスキルは行数を示し、補完の前に
実行ごとに一度確認する。これは承認ゲートであって順位付けではない。

**製品固有の技術メモは構わない。** `shared/ledger-report-traps.md` は会計
ソフトのレポート機能の落とし穴を、マネーフォワード クラウド会計で確認できた
具体とともに記録している。`shared/gmail-inbox-traps.md` は Gmail 固有の罠を
記録している。これは好みではなく落とし穴の記録。残し、製品固有と明記し、
他の製品の罠が見つかったら兄弟ファイルを足す。

**記入例は製品名を出してよい。** 例は何かの上で動かなければならない。
記入例の中でマネーフォワード クラウド会計を呼ぶのは構わない。「まず
マネーフォワードをつなぎましょう」と助言として言うのは駄目だ。例は経営者の
ツールが使われている様子を見せるもので、経営者の代わりに選ぶものではない。

## 一つのコネクタ、二つの登録

プラグインのマニフェスト（`.mcp.json`）は、Cowork のプラグインページに
載せるためにルーター対応表のコネクタをすべて宣言している。Cowork は宣言
されたサーバーをプラグイン名で登録し — `small-business-jp:trello`、
`small-business-jp:hubspot` — 経営者が自分のアカウントで既に接続している同じ
製品と必ずしも統合しない。たとえば Trello をつないでいる経営者には
`Trello`（認可済み）と `small-business-jp:trello`（未認可）の両方が見える。
同じ製品、同じサーバー、二つの項目。

**同一性は製品にあり、登録にはない。** `small-business-jp:<name>` と `<name>` は
一つのコネクタである。ルールは順に:

1. **認可されている方の項目を呼ぶ。** 両方とも認可されていれば、経営者自身の
   アカウントレベルの項目を使う: 既に同意があり、プラグインをアンインストール
   しても残る。両方を呼ぶことはしない。
2. **二つの項目は二つのコネクタではない。** 上の「同一カテゴリに二つ接続」の
   ルールは二つの製品（二つの会計ソフト、二つの CRM）のためのもの。一つの
   製品の二つの登録が「どちらを正とするか」の質問を起こすことはない。
3. **未認可のプラグイン側コピーは「未接続」ではない。** 経営者自身の項目が
   生きていれば、そのコネクタは接続されている。以上。「見つからない」と
   報告しない、プラグイン側コピーの認可を求めない、既に動いているツールの
   ためにコネクタタブへ送らない。
4. **プラグイン側コピーしかなく、それが未認可なら、** それが普通の「接続
   してください」の経路。プラグインのコネクタタブから認可することも、自分の
   アカウントにコネクタを直接追加することもできる、と一度だけ言う。どちらでも
   よく、どちらも他方より上ではない。
5. **経営者向けの文章は製品名を使う。** 「Trello」であって
   `small-business-jp:trello` ではない。事業コンテキストの `接続済みツール` 行は
   製品名だけを保存するので、後のスキルが登録名を引き継ぐことはない。
6. **ツール名の接頭辞が違う。** プラグインスコープのツールは
   `mcp__plugin_small-business-jp_<server>__<tool>`、経営者自身のものは
   `mcp__<Server>__<tool>`。ツール名で照合するものは両方の形に一致させる。

このルールにできないこと: Cowork に一つの項目だけを表示させること。それは
プラットフォームの挙動である。それが変わるまで、プラグインは項目が一つでも、
二つでも、二つのうち一つが未認可でも、正しく動く。

## 初期設定とルーター

- **聞く。勧めない。** 初期設定では、記帳に何を使っているか、顧客管理に何を
  使っているか、メールは何かを聞く。製品を提案しない。そのカテゴリに
  ツールがなければ、レシピのコネクタなし経路が動き、カテゴリ名だけを出す
  （「記帳ツールを決めたらつないでください。この処理が深くなります」）。
  製品名は付けない。
- **ある、つなぐ、それでもなければ代替経路。** この順で、一度だけ、トレード
  オフを一行添えて言う。うちに無いからといって競合製品を売り込まない。
- **ルーターは接続されているものを選ぶ。** ステップ5のルールが既にそう
  言っている。中立ルールが足すのは: カテゴリに何も接続されていないとき、
  ルーターはカテゴリ名と代替経路を出し、買いに行くべき製品名を出さない。

## このルールが変えないこと

- **承認ゲート。** 中立は寛容ではない。すべての書き込みに「はい」が要る。
- **適用範囲の正直さ。** 日本の制度に依存する部分（税務・労務・補助金・
  採用書類）は年度改定に注意し、税理士・社労士の確認を添える
  （`shared/currency-and-locale.md`）。それは適用範囲の明示であって、
  連携先の順位付けではない。

## 同一カテゴリのコネクタ間で避ける語

既定 · 主要（メイン） · 優先 · フォールバック（連携先のラベルとして） · 代替
· 代わり · 格下 · 予備の経路 · 多くの経営者が使っている方 · 推奨

代わりに使う: 「接続されている方」「接続済みの会計ソフト」「会計ソフト
（freee会計、マネーフォワード クラウド会計、弥生会計 など）」「経営者が正と
名指しした方」。
