# 文書形式の設定 — プラグイン共通の既定値と上書き

**対象:** 会話の外に持ち出す文書を経営者に渡すスキル — 提案書、求人票、採用
資料一式。ダッシュボード、架電リスト、チャットの中で一度読んで行動するものは
対象外だ — それらは `shared/artifact-style.md` 自身の出力ルールがすでに扱って
おり、このファイルはそれを変えない。

---

## 設定の中身

`smb-onboard` で一度だけ設定し、Cowork のセッションメモリディレクトリに
`## Business context` ブロックの「出力形式」行として保存する（ブロックの書式は
`skills/smb-onboard/reference/onboard-checklist.md`）。保存される値は
`visual artifacts`、`docx`、`md`、`notion`、`canva`、`best for skill` の 6 つで、
以下の 6 つの選択肢がこの順に対応する：

6 択で、選択式で聞く：

- **ここに整ったページ（HTML アーティファクト）** — 既定値で、ほとんどの経営者
  がほとんどの場面で望むもの。見やすく、リンクで共有しやすく、ダウンロード
  不要。
- **Word 文書（.docx）** — 印刷する、添付で送る、送る前に Word で手直しする
  経営者向け。
- **プレーンな Markdown またはテキストファイル** — ファイルをそのまま送るので
  はなく、自分のツール（求人媒体、採用管理システム、CMS）に内容を貼り付ける
  経営者向け。
- **Notion ページ** — 文書は Notion コネクタでページとして作成する。保存先は
  経営者が指定し、既存ページは決して上書きしない。この実行で Notion が接続
  されていなければ、そう伝えて HTML アーティファクトに戻す。成果物を止めない。
  書き込みのルールは `shared/artifact-style.md` が `notion` 設定に定めている
  ものと同じ。
- **Canva Doc** — 文書は Canva コネクタで Canva Doc として作成する。実行の
  たびに新規デザイン、日付付きの名前、内容はそのまま配置。この実行で Canva が
  接続されていなければ、そう伝えて HTML アーティファクトに戻す。成果物を
  止めない。書き込みのルールと内容の制限（Canva Doc には表・グラフ・リンクを
  入れない）は `shared/artifact-style.md` が `canva` 設定に定めているもの。
- **その時々で合うもの** — 文書ごとの判断に任せてよい、という経営者。設定なし
  と同じに扱う。

## 既定値

**保存された設定がない、または「その時々で合うもの」→ HTML アーティファクト。**
このファイルが管轄するすべてのスキルは、文書をハウススタイルのアーティファクト
として描画し、それ以外は出さないのが既定。例外は、経営者の保存された設定が
別の形式を指定しているか、後述のとおり特定の提出先の仕組みが設定にかかわらず
実ファイルを要求する場合だけ。

## 上書き — 設定に関係なく実ファイルが必要なとき

HTML を希望する設定は、*仕組み上* 必要なファイルを取り除くことはない。取り除く
のは、単に礼儀として存在していた形式のファイルだけだ。具体的には：

- **電子契約への回付**（DocuSign）は添付する実際の文書が必要 — 設定が HTML
  のみでも作成し、一行でそう伝える：*「こちらは DocuSign 用に実ファイルが
  必要なので .docx を作ります。先に確認用のページもそのまま残しています。」*
  クラウドサイン・GMOサインを `build-connector` で接続した場合も同じ。
- **ファイルしか受け付けない提出先**（求人媒体のアップロード欄、jGrants の
  申請様式（Word/Excel 指定））も同じ — 提出先の要件が勝つ。それを一度だけ、
  簡潔に述べる。

この区別こそがこのファイルの要点：**設定が決めるのは礼儀としてのコピー。
外部の本物の要件は決して任意ではない。**

## 現在このファイルが管轄するスキル

- `proposal-builder` — ステップ5。DOCX と PDF は設定が求めるときだけ作成する。
  HTML アーティファクトが既定で、設定にかかわらず常に提示する。
- `job-post-builder` — 求人票と面接ガイドは設定に従う（どちらも通常は貼り付ける
  か読むもので、ファイルとして保管しない）。内定通知書・労働条件通知書は既定
  で実ファイルのまま。フェーズ6で DocuSign に回付するからで、これは上の上書き
  ルールそのものであって、例外ではない。

**意図的に触らないもの:** `contract-review` の修正案 DOCX（経営者が明示的に
求める弁護士向けの赤入れ形式で、既定ではない）、`report-builder`／
`report-pack` の XLSX（作業用のデータ付録で、体裁の選択ではない）、
`grant-rfp-writer`（提出形式は交付元のポータルが決めるもので、経営者ではない）。
第三者が特定の形式で要求するファイルに個人の好みの設定を当てはめるのは、誤った
修正だ。

## スキル実行時に設定が未設定なら

他の不足コンテキストと同じように、一度だけ手短に聞く：
*「ひとつだけ — ここにページで出しますか、Word 文書ですか、Notion か Canva の
ページですか、それとも場合によりますか？」*
答えは `## Business context` ブロックの「出力形式」行に保存し、二度と聞かない
ようにする。答えを待って
成果物を止めない — 経営者が作業中で、あとで答えたいなら、この実行は HTML
アーティファクトを既定とする。
