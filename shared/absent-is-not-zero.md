# 「無い」はゼロではない

これらのスキルが自信たっぷりに間違った答えを出す、最も多い原因。

以下の欠陥はすべて、テスト用の固定データではなく本物の連携先に対して現れる。理由は構造的だ:
**固定データは作りとして完全で、本物のデータは穴だらけ。** スキルが何も教わっていなければ、
穴は良い知らせに読める。

---

## この間違いの形

フィールドが空、ゼロ、切り詰め、追跡なしで返ってくる。スキルはそれを、データについての事実
ではなく、事業についての事実として読む。出てくる答えはきれいで、自信があり、問題を隠す方向に
間違っている — これは最悪の方向だ。何も確認が必要そうに見えないから。

| データがしたこと | スキルが出した結論 | 本当のこと |
|---|---|---|
| 滞留一覧が上位10件に切り詰められた | 売掛金合計 370万円 | 530万円。しかも唯一の91日超の債権が抜けていた |
| PL サマリーが費用を省いた | 費用ゼロ、粗利率100% | 下の明細行に 1億4,200万円の費用 |
| 返信日時が未来の日付 | パイプラインで一番熱いリード | 壊れたレコード。最近の接点はまったくない |
| 商談に活動日がない | 商談は新しい、パイプラインはきれい | 誰も一度も触っていない |
| ラベル ID 検索が0件 | 受信箱にリードなし | そのラベルの下に 201件の本物の問い合わせ |
| バリエーションの在庫追跡がオフ | 誰も買わない商品、発注不要 | カタログで一番売れているコーヒー豆 |
| 4回分の給与計算が未確定 | 給与計算は1回分が期日 | 4期間分、誰にも給与が支払われていない |
| 売上高フィールドが `0.0` | 売上のない会社 | データ提供元に数字がないだけ |
| 決済サービスの残高 `available: 0` | この決済サービスにお金はない | 入金待ち 46万円、2日後に着金 |
| マネーフォワードの試算表で 0 の科目が返らない | 科目が存在しない、設定漏れ | 全項目 0 の科目は仕様で省かれる。科目はある |

10件の事例、連携先はばらばら、間違いは一つ。

## ルール

**数字を報告する前に、事業が健全ならどうしてこう見えるのか、データが壊れているならどうして
こう見えるのかを問う。二つを見分けられないなら、どちらかを選ぶのではなく、見分けられないと
言う。**

具体的には、効く頻度の順に:

1. **絞り込んだ呼び出し、ページ分割した呼び出しは、自分の切れ端を語る。全体は語らない。**
   合計は絞り込みのないソース — 貸借対照表の行、全件数 — から取るか、一部だとラベルを付ける。
   上位N件のサマリーを帳簿全体の合計として出さない。

2. **サマリーオブジェクトは便利機能であって、ソースではない。** payload がサマリーと、その元に
   なった明細行の両方を持っているなら、明細行を合計する。自分の明細行と矛盾するサマリーを
   返す連携先がいくつもある。

3. **ゼロと「無い」は別の事実で、ほとんどの API は両者を混同する。** 売上高 `0.0`、空の日付、
   `null` の件数 — どちらがもっともらしいかを判断する。売上のない会社はまれで、数字を持って
   いないデータ提供元はよくある。ゼロがもっともらしくないなら、不明として読み、不明と言う。
   逆に、マネーフォワードの試算表のように全項目 0 の科目を省く仕様なら、「返らない＝ゼロ」と
   読んでよいが「科目が無い」とは読まない。

4. **空は新しいではない。** 活動日のないレコードは一度も触られていない。それは最も健全な状態
   ではなく、最悪の状態だ。日付比較は空のフィールドを黙って除外するので、一番困っている
   レコードが、それを見つけるために作った一覧から落ちる。「無い」を最も古い日付より上に
   並べ、別の名前で呼ぶ。

5. **今日より後の日付は壊れている。** 新しさのスコアはそれを「最も新しい」と読み、壊れた
   レコードが上に浮く。スコアを付ける前にすべての日付を今日と比べ、未来のものは空として扱う。

6. **空の結果と失敗したクエリは見分けがつかない。** 「何もない」と報告する前に突き合わせる:
   ラベル検索が0件でも、ラベル自体はメッセージを持っていると言うなら、間違っているのは
   クエリで、受信箱ではない。「結果なし」は事業についての主張であり、他の主張と同じ精査に
   値する。

7. **ある件数が別の件数と合わないのは発見であって、丸め誤差ではない。** 同じものを表す二つの
   エンドポイントが桁で違うなら、片方は別のものを測っている。黙って選ばず、どちらを使い、
   なぜかを言う。

## うまく伝える

経営者に仕組みは要らない。どの数字を信じてよいかが要る。

> *「帳簿上の売掛金は 20社で 530万円です。うち ビストロ真珠通り が 91日超で 6万7,000円 —
> 本当に古い債権はこれだけです。」*

「売掛金は 370万円です」ではない。それは切れ端については本当で、事業については嘘だった。

> *「Shopify の在庫レポートは売上レポートよりずっと少ない販売数を示しているので、ほとんどの
> バリエーションで追跡がオフになっているようです。販売速度には売上の数字を、手元在庫には
> 在庫の数字だけを使いました。」*

一文で、経営者はその数字をどこまで信じてよいか正確に分かる。

本当に判断できないものは、そう言って止まる。**名前の付いた穴は役に立つ。でっち上げたゼロは
沈黙より悪い。** 経営者がそれに基づいて動くからで、この出力は金融機関、経営会議、顧問税理士に
転送される。
