# 円・決算月・消費税区分 — プラグイン共通ルール

適用範囲: **金額、本文中の日付、期間（「今四半期」「年度累計」）を出力するすべてのスキル。**
このプラグインは日本の中小企業向けに作られている。通貨は円、制度は日本の税務・労務が
前提だが、**事業形態・決算月・消費税の区分は事業者ごとに違う。** 3月決算と決めつけない。
暦年と決めつけない。課税事業者と決めつけない。

---

## 値の出どころ

`## Business context` ブロックの次の 5 行。`smb-onboard` が取得する
（形式は `skills/smb-onboard/reference/onboard-checklist.md`）:

```
- **事業形態:** <法人（株式会社／合同会社 など）または 個人事業主>
- **決算月:** <例: 3月。個人事業主は 12月（暦年）>
- **消費税:** <課税事業者／免税事業者、適格請求書発行事業者の登録番号の有無（番号自体は書かない）、簡易課税／本則課税>
- **通貨:** <JPY。海外取引があれば追加通貨（USD など）>
- **顧問税理士:** <有／無。有なら事務所名>
```

**聞く前に会計ソフトから読む。** 会計ソフトのコネクタが生きていれば、事業者の設定にこれらの大半がある。

- **マネーフォワード クラウド会計:** `currentOffice` が事業者名と会計期間
  （`accounting_periods`、開始日の降順の配列）を返す。`getTermSettings` が会計年度設定
  （開始日の降順）を返すので、**決算月と期首はここから読む。** `getTaxes` が税区分の
  一覧を返すので、消費税の区分（課税・非課税・不課税・免税、インボイス経過措置の区分）は
  ここから読む。課税事業者か免税事業者か、簡易課税か本則課税かは事業者設定の側にあり、
  コネクタが返さなければ聞く。経営者が API キー認証なら `identification_code`
  （事業者コード XXXX-XXXX）が必須。
- **freee会計:** 事業所の設定に会計期間（期首・決算月）と消費税の設定（課税方式、簡易課税
  の有無、インボイス登録の有無）がある。コネクタが返す範囲で読み、返さないものだけ聞く。
- **弥生会計（CSV 前提）:** 残高試算表 CSV のヘッダーに会計期間が出る。消費税の設定は CSV から読めないので聞く。

コネクタによって項目名は違う。コネクタが返すものを取り、返さないものだけ聞く。
**顧問税理士の有無だけは、どのコネクタにもない。** 一度だけ聞く。

**スキル実行時にこれらの行がなければ、一度だけ、一つの質問で聞く。** *「法人ですか、個人事業主
ですか。決算月は何月ですか。消費税は課税事業者ですか（インボイス登録はお済みですか）。」* 答えを
ブロックに保存し、二度と聞かない。成果物を止めない: 経営者が作業の途中で「あとで保存する」と
言うなら、このセッションはその答えで動く。

**事業形態や決算月を推測しない。** 株式会社だから 3月決算とは限らない。個人事業主でも
消費税の課税事業者であることは普通にある。事業形態は事業者名（「株式会社」「合同会社」）や
勘定科目（「事業主貸」「事業主借」があれば個人事業主）から読めることが多い。読むか、聞く。

## 金額

- **円は `1,240円`。** 半角数字＋3桁区切り＋「円」。小数は使わない（円に補助単位はない）。
  本文では `¥` や `JPY 1,240` ではなく「円」を使う。`JPY` は事業コンテキストの `通貨` 行と、
  外貨と並べる表の列見出しにだけ使う。
- **文中の大きな金額は万円表記でよい。** `120万円`、`1,500万円`、`3.2億円`。
  表・スプレッドシート・アーティファクトの数値列は全桁 `12,000,000円`。同じ表の中で
  万円と全桁を混ぜない。
- **税込／税抜を必ず明記する。** `110,000円（税込）`、`100,000円（税抜）`。請求書・
  見積書・売上集計では税率ごと（10%・軽減税率 8%）の内訳を示す。会計ソフトの経理方式
  （税込／税抜）を読み、どちらで集計したかを書く。
- **スプレッドシートの表示形式は `#,##0"円"`。** 負数は赤、はそのまま。`$#,##0.00` のような記号付きの形式は使わない。
- **外貨は ISO コード前置。** `USD 1,200`、`EUR 850`。記号だけ（`$`、`€`）を付けない:
  記号は複数の通貨で共用され、等幅の数値列で崩れる。

## 判断のしきい値

スキルには丸めや注目のしきい値が書かれている（「差異が 100円を超えたらフラグ」
「領収書のない 3,000円超の経費」「30万円以上の支払いは二重確認」）。

- **しきい値は円の実務感覚で書く。** 差異の許容は `1円`（円は整数なので端数差は 1円単位）〜
  `100円`、領収書なし経費の注目ラインは `3,000円`、高額支払いの注意ラインは `30万円`。
  **これらは判断の目安であって法定基準ではない。** 事業の規模に合わせて経営者が動かしてよい、と書く。
- **法定基準には法律名を添える。** 支払調書の対象は同一人への年間支払合計 5万円超
  （所得税法）。インボイスの少額特例は 1万円未満（基準期間の課税売上高 1億円以下、
  2029年9月30日まで）。少額減価償却資産は 30万円未満（中小企業者等の特例、年 300万円まで）。
  電子帳簿保存法の少額特例は別物。「外注費のしきい値」という一般概念はない: 数字は制度に属する。
- **法定の数値は年度改定される。** 金額・税率・期限を書くときは「令和8年（2026年）時点」の
  ように時点を添え、顧問税理士の確認を促す。

## 日本の制度に依存する部分

税務・労務・補助金・採用書類は日本の制度で書かれている。制度は毎年変わる。スキルはそれを隠さない:

- **制度に依存する経路を動かす前に、改定を意識する。** 税率、社会保険料率、最低賃金、
  補助金の公募要領、求人票の必須記載事項は年度・改定で変わる。数値や期限を出すときは
  「最新の公的情報（国税庁、厚生労働省、中小企業庁、各自治体）で確認」と一行添え、税務は
  顧問税理士、労務は社会保険労務士の確認を促す。例: *「納税資金の見積もりは令和8年度の
  税率で概算しています。中間申告の要否と最終的な税額は顧問税理士にご確認ください。」*
- **概算に確定のラベルを付けない。** 自信ありげなラベルの付いた間違った税額こそ、この
  ルールが防ぐ失敗。「概算」「目安」「税理士確認前」と書く。
- **制度依存が強いスキル:** `tax-season-organizer` と `/tax-prep`（法人税等・消費税の
  納税資金、支払調書・法定調書合計表）、`grant-rfp-writer` の公募情報源（jGrants、
  ミラサポplus、自治体サイト）、`hiring-screener` の入社手続き書類、`job-post-builder` の
  求人票・労働条件通知書（職業安定法・労働基準法の必須記載事項）、`payroll-prep` と `plan-payroll`
  （社会保険料率・源泉所得税の税額表）。輸出免税や海外の外注先への支払いなど海外取引の税務は
  計算対象外とし、金額の事実だけを揃えて顧問税理士に渡す。

## 期間・日付

- **「今四半期」「年度累計」「前期」は `決算月` を基準に解決する。** 暦年ではない。
  経営者が「暦年で」と言ったときだけ暦年。年度の期間は実行ごとに一度解決し、使い回す。
  3月決算の事業者が「第1四半期」と言えば 4〜6月。**個人事業主は暦年（1〜12月）固定。**
- **本文の日付は `2026年9月16日`。** ファイル名は ISO `2026-09-16`。公的書類（申告書、
  届出）に触れるときは和暦を併記する: 「令和8年（2026年）」。
- **タイムゾーンは Asia/Tokyo（JST）。** 日本国内に時差はないが、カレンダー連携の payload に
  オフセットが付いていればそれを信じる。海外顧客との会議は相手側の時刻を併記する。
- **期限は制度に属する。** 「3月15日まで」は個人事業主の確定申告の期限で、法人には当て
  はまらない（法人は決算日から 2か月以内）。期限には、どの事業形態のどの制度の期限かを書く。
- **銀行休業日と混雑日を織り込む。** 土日祝と 12月31日〜1月3日は銀行が動かない。**五十日
  （ごとおび。5日・10日・15日・20日・25日・月末）**は振込が混む。年末年始・ゴールデンウィーク・
  お盆は取引先も休む。資金繰り・督促・発注のタイミングはこれを前提に置く。月末が休業日なら、
  支払期日を「翌営業日」「前営業日」のどちらで扱うか取引先ごとに確認する。

## 外貨取引

- **出力する金額は原則 `通貨`（JPY）。** 決済サービスが別の通貨で精算する場合（Stripe の
  USD 入金、PayPal の外貨残高、Airwallex の多通貨口座）は、**精算通貨のまま表示し、通貨名を
  明記する。** 黙って換算しない。
- **換算が必要なら、会計ソフトの仕訳レートを正とする。** 会計ソフトに取り込まれる前の外貨
  入金は `USD 1,200（未換算）` と書き、円換算額は仕訳後の値を読む。為替差損益は税理士の領分。
- **`通貨` 行に追加通貨があれば、その通貨の入金・売掛金は別行で集計する。** 円建てと
  外貨建てを一つの合計に足さない。

## 参照ファイル内の例示金額

プラグインの参照ファイルには例示の金額が多数ある。これらは形と調子の例であって出力ではない。
**例示金額は円に統一する。** 元の `USD 1,240` のような金額は、日本の中小企業の規模感に合う円の
金額（月商 300万〜3,000万円の事業を想定）に置き換える。厳密な換算は不要で、自然な数字にする。
外貨の例が必要な文脈（海外送金、Stripe の外貨入金）だけ、ISO コード前置で外貨を出す。
上のルールは実際の事業者に向けてスキルが出力するものを律し、参照ファイルの例示はその形に合わせる。
