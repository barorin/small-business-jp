# データソース

どのコネクタがパルスのどの部分に答えるか。すべて一括の並列バッチで取得する。

---

## HubSpot — ファネル

このスキルの背骨。なければファネルの転換率は出せず、パルスは代わりに売上推移に寄りかかる。

| 視点 | 取得するもの |
|---|---|
| ファネルの転換率 | ステージ別の商談。作成日と成約日つき |
| リード数 | 期間内に作成されたコンタクト。流入元プロパティつき |
| 流入元の構成 | コンタクトを元の流入元（original source）でグループ化 |
| 受注率 | 受注（closed-won）÷ 決着した商談（受注＋失注） |
| 商談期間 | 作成から成約までの日数の中央値。受注した商談のみ |
| 止まっている商談 | 14日以上活動のない商談、または成約予定日が過去でまだ開いている商談 |
| 対応の速さ | コンタクト作成から最初に記録された活動までの時間 |

**商談金額に注意。** それは見込みであって売上ではない。加重パイプラインを稼いだ金として提示しない。

**フォールバック:** CRM の商談一覧の CSV エクスポートで同じファネルの視点が得られる。kintone や Salesforce を使う経営者も同様に CSV から。

## 売上の取得元

| 取得元 | 向いている用途 |
|---|---|
| 会計ソフト（freee会計、マネーフォワード クラウド会計、弥生会計 など） | 確定した売上 — 帳簿と一致する数字。マネーフォワードなら推移表 `getReportsTransitionProfitLoss` で月次推移、freee会計なら「月次推移」、弥生会計は残高試算表 CSV |
| Stripe、PayPal | 入金のタイミング、決済手数料、返金、定期課金の売上 |
| Square | 店頭売上と店舗別売上 |
| Shopify | 注文数、SKU 別売上、リピート購入率 |

**パルスごとに売上の取得元を一つ選び、どれを選んだかを言う。** 会計ソフトが接続されていればそれが正 — 決済サービスとネットショップは、チャネル別・商品別の内訳を補うだけ。取得元をまたいで合計すると二重計上になり、ときに倍以上になる。

**会計ソフトの数字は全社売上であって、広告が届く範囲の売上ではない。** ひかり珈琲焙煎所の月商 1,200万円のうち Shopify の EC は約 30万円。会計ソフトの合計は文脈として載せ、EC 広告の ROAS や転換率の分母には使わない。比率はそのチャネルが実際に届く売上（Shopify の注文額、検索広告経由の受注額）で計算し、両方の数字を併記する（`../../../shared/chain-seams.md`）。

**そのうえで、一つの取得元の中の二重計上も防ぐ。** 会計ソフトの得意先別売上や補助科目付きの残高試算表（マネーフォワードなら `with_sub_accounts: true`）は、親（勘定科目・親得意先）の合計行と子（補助科目・案件）の行を同じ金額で返す。顧客を順位付けしたり集中度を計算したりする前に、合計行・親行を除く。さもないと同じ顧客が順位に二度現れ、集中度が高く出る（`../../../shared/ledger-report-traps.md`、罠3）。

## 広告プラットフォーム

| 取得元 | 取得するもの |
|---|---|
| TikTok広告 | ネイティブコネクタ。`report_integrated_get` をキャンペーン単位で直近 7日とその前の 7日: 広告費、表示回数、クリック数、成果数、成果単価。先に `advertiser_info_get` でアカウントを確認する。読み方と罠は `ad-manager` と同じ（`../../ad-manager/SKILL.md`）。最初の呼び出しの前にそちらを読む |
| Google 広告、Yahoo!広告、Meta広告、LINE広告 | このスキルにはネイティブコネクタがない — `build-connector` で作った連携があればそれを、なければ管理画面からの CSV エクスポートを頼む。コネクタの扱いは `ad-manager` にある |

**Yahoo!広告を忘れない。** 日本の検索広告は Google 広告と Yahoo!広告の二本柱で、「エアコン 修理」のような地域の検索は Yahoo! 側にも相当量ある。Google 広告の CSV だけで「検索広告の成果」を語らない。

**帰属の正直さ。** 広告プラットフォームは自分が主張する成果数を報告する。CRM は受け取ったリード数を報告する。この二つはめったに一致せず、その差は不具合ではない。見栄えのよい方を選ぶのではなく、両方を報告して差を名指しする。

## Mailchimp — チャネルとしてのメール

| 視点 | 取得するもの |
|---|---|
| キャンペーンの費用対効果 | 売上帰属つきのキャンペーン分析 — キャンペーンごとの開封、クリック、帰属売上 |
| チャネル推移 | EC 分析。売上のうちメール帰属の部分 |
| リード数 | オーディエンス増減の分析 — 期間内に増えた購読者と減った購読者 |

**同じ帰属の正直さが当てはまる。** Mailchimp の帰属売上は Mailchimp の主張であり、
広告プラットフォームの主張と CRM の記録の隣に置く。メールチャネル自身の数字として
報告し、差を名指しする。一つの混ぜ合わせた数字に畳まない。

**Mailchimp の呼び出しの形。** `get_capabilities` には `user_request`（経営者がやろうと
していることを言葉で）と `category` の両方が要る（`../../../shared/connector-call-shapes.md`）。

**このプラグインでは Mailchimp は読み取りと下書きのみ。** ここに送信の経路はなく、
キャンペーンプランナーは単一キャンペーンの依頼を拒む — 生成するのはマルチチャネルの
計画だけ。オーディエンス一覧そのものは、呼び出しが実際に返さない限り、エクスポート
不可として扱う。

**認証やログインのエラーはコネクタの健康状態であって、データの欠落ではない。** Mailchimp の
呼び出しがログイン期限切れや認可エラーで失敗したら、付記の行は「メールデータなし」ではなく
「Mailchimp: 再認可が必要 — コネクタ設定で再接続して再実行」と書く。直し方を名指しし、
メールの視点なしでパルスを続ける。その行を書く前に、エラーがプラグイン側の登録
（`small-business-jp:intuit-mailchimp`、マニフェストのキー）から来たもので、経営者自身の Mailchimp の
項目が生きていないかを確認する — 経営者の項目が動くならそれを使い、再接続について何も言わない
（`../../../shared/connector-neutrality.md`「一つのコネクタ、二つの登録」）。

## ローカル集客と SNS（コネクタなし。数字は経営者から）

| 取得元 | 取得するもの |
|---|---|
| Googleビジネスプロフィール | 「パフォーマンス」画面の表示回数（**検索と地図は別に数える**）、経路検索、電話タップ、Web サイトのクリック。CSV か貼り付け |
| Instagram | インサイトのフォロワー純増、リーチ、プロフィールからのリンククリック |
| LINE公式アカウント | 友だち追加数、ブロック数、メッセージの開封・クリック。`build-connector` があればそこから、なければ管理画面の数字を貼り付け |

これらは問い合わせ数の前段にある指標で、売上ではない。フォロワーや友だち数の増減は「流入の勢い」として読み、顧客数や売上と混ぜない。

## 評判

| 取得元 | 取得するもの |
|---|---|
| 公開されている口コミ | Web 調査で直近の口コミ — Googleマップ、食べログ・ホットペッパー、楽天・Amazon のレビュー、業界サイト、Instagram・X の言及 |
| PayPal、Stripe | 異議申し立てとチャージバックの件数と理由 |
| Gmail または Microsoft 365 | 受信した苦情、解約の申し出、返金の依頼 |
| HubSpot | 問い合わせ（チケット）の件数とテーマ。顧客対応を CRM で回している場合 |

評判はこのパルスの先行指標だ。売上より先に動く。だからこそ入れる価値がある。

## アップロードされたファイルの道筋

正規のモードであって、劣化版ではない。この規模の経営者の多くは、成長側にきれいなコネクタを一つも持っていない。

何を頼むか、平易な言葉で:

- 「CRM から商談一覧をエクスポートしてください」 — ファネルの転換率
- 「今月の売上レポートをエクスポートしてください」 — チャネル別・商品別の成績
- 「広告の管理画面からキャンペーン別成果の CSV をダウンロードしてください」 — キャンペーンの費用対効果（Google 広告と Yahoo!広告は別々に）
- 「最近の口コミを貼り付けてください」 — 評判

ヘッダー行を読み、列を対応付け、同一のパルスを組み立てる。必要な列がなければ名指しする — 「流入元の列がないので、リードをチャネル別に分けられません」 — 黙って視点を落とさない。CSV の金額が税込か税抜かを確認し、パルス内で混ぜない。

## 並列取得のルール

すべての呼び出しを一括で送る。このパルスは日常的に五つか六つのシステムに触れる。

失敗は内部で記録し、付記に一度だけ列挙する。ブリーフの途中でコネクタのエラーを表に出さない — 経営者が聞いたのは成長のことで、連携のことではない。
