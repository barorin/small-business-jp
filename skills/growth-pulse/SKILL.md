# グロースパルス

集客と販促の仕組みが回っているか、そして今週それにどう手を打つかを、一枚で答える。

経営者は「三つの管理画面から数字を拾ってきて、自分でストーリーを探している」と口をそろえる。ここでの成果物はそのストーリーであって、管理画面の複製ではない。

## ステップ1 — すべて並列で取得する

コネクタ呼び出しはすべて一括で送る。指標とツールの対応は `reference/data_sources.md` を読む。直列で取りに行くと、誰も二度は付き合わない待ち時間になる。

- **HubSpot** — ステージ別の商談、新規コンタクト、リードの流入元、受注率、商談期間、止まっている商談
- **PayPal、Stripe、Square** — 売上推移、取引件数、返金
- **Shopify** — 注文数、SKU 別売上、リピート購入率
- **会計ソフト（freee会計、マネーフォワード クラウド会計、弥生会計 など）** — 確定した売上。帳簿と一致する数字。ただし **全社売上であって、広告が届く範囲の売上ではない**（ステップ2 の分母の注意を読む）
- **TikTok広告** — 先週の広告費、表示回数、クリック数、成果数、キャンペーン別の成果単価を、ネイティブコネクタ（`report_integrated_get`、直近 7 日と前の 7 日）から。広告費が、それが生んだと主張する売上の隣に並ぶようにする
- **Google 広告、Yahoo!広告、Meta広告、LINE広告** — ネイティブコネクタはない。`build-connector` で作った連携か、管理画面からの CSV エクスポート
- **Mailchimp** — キャンペーン、EC、オーディエンス増減の分析。キャンペーンごとの売上帰属つき
- **Gmail または Microsoft 365** — 問い合わせの件数と返信までの時間
- **公開されている口コミ** — 直近の評価点と口コミ本文を Web 調査で（Googleマップ、食べログ・ホットペッパー、楽天・Amazon のレビュー、Instagram・X の言及）

取得元がエラーを返す、あるいは存在しない場合は記録して先へ進む。このスキルは、コネクタ一つでも役に立つことを、六つなら卓越したことを言えるように設計してある。

**コネクタゼロも正規の道筋。** エクスポートを頼む — CRM の商談一覧、売上レポート、広告成果の CSV — そしてファイルから同じパルスを組み立てる。止まらずに、そう率直に言う。

## ステップ2 — 五つの視点を計算する

しきい値は `reference/thresholds.md` を読む。各視点を計算し、ステータスを付ける。

1. **チャネル推移** — チャネル別の売上を前期比で、可能なら前年同期比でも
2. **ファネルの転換率** — 流入したリード、有望化、商談化、受注。各段階の間の転換率と、最も大きく落ちる段階
3. **キャンペーンの費用対効果** — キャンペーンごとの広告費と帰属売上、そして獲得単価（CPA）
4. **商品の成績** — 売上と伸び率それぞれの上位 3 つと下位 3 つ
5. **顧客の評判** — 直近の口コミ点数、口コミの傾向、チャージバック・異議申し立て、離反の兆候

データのない視点は「n/a」とし、付記で名前を挙げる。黙って消さない。

**分母の罠（`../../shared/chain-seams.md`）。** 会計ソフトの全社売上を、EC 広告の ROAS の分母にしない。ひかり珈琲焙煎所は月商 1,200万円だが、Shopify の EC は約 30万円（2〜3%）で、カフェ 4 店舗と卸が残りを占める。広告費 8万円を全社売上で割れば、本当は 4.7倍の ROAS が 150倍に化ける。比率は、そのチャネルが実際に届く売上を分母に計算し、両方の数字を併記する。

## ステップ3 — 本当のストーリーを見つける

このスキルの価値はここで決まる。五つの視点を並べただけでは、まだ管理画面だ。仕事はそれらをつなぐこと。

最も重要なつながり：

- **広告費が増えながら獲得単価も上がっている**なら、チャネルは飽和しているのであって、伸びているのではない
- **リードは多いのに受注率が落ちている**なら、原因はリードの質か対応の速さで、マーケティングではない
- **一つの商品が推移全体を支えている**なら、成長は合計が示すより脆い
- **売上は保っているのに評判が落ちている**のは、二か月後に売上に現れる早期警報
- **ファネルが急落する段階**は、たいていどんな新キャンペーンより価値がある

この期間を説明する一文を探す。それを冒頭に置く。

## ステップ4 — 三つの施策を書く

パルスは必ず、ちょうど三つの施策で終わる。五つでも、気づいたこと全部の羅列でもない。

施策には三つの要素が要る。欠けていれば施策ではない：

- **何をするか** — 今日から始められる具体性
- **なぜ** — それを裏付けるこのパルスの数字
- **いくらの価値か** — 機会またはリスクのおおよその大きさ

影響の大きさで順位付けする。やりやすさではない。何が簡単かは経営者が判断できる。何が大きいかはこのパルスにしか言えない。

正直な答えが「変えるべきことはない」なら、そう言う。毎週三つの施策をひねり出すパルスは、経営者に無視することを教える。

## ステップ5 — 組み立てる

`reference/output_template.md` の構造をそのまま使う。実データのあるセクションだけ載せる。

書き方のルール：

- 数字が先、言葉が後。「Meta広告は好調だった」ではなく「Meta広告から 41件、1件 4,300円。前月の 7,400円から改善」。
- すべての数字に比較対象を添える。基準のない数字は、取り逃した気づきだ。
- キャンペーン、商品、チャネル、顧客を固有名で挙げる。「一部のキャンペーンが不調」では使い物にならない。
- 経営者が使わないマーケティング用語を使わない。「トップオブファネルのベロシティ」ではなく「新規リードが何件、どれくらいの速さで来たか」。
- 言うべきことのないセクションは「大きな変化なし」と書いて先へ進む。

## ステップ6 — パルスのページを届ける

チャットのパルスに加えて — 置き換えではなく追加で — 経営者が保存した出力形式に従ってパルス全体を届ける。Markdown ファイルを既定にしない。`## Business context` ブロックの「出力形式」を確認する（共通スタイルガイド `../../shared/artifact-style.md` のルール）：

- **visual artifacts（既定）：** ハウススタイルの HTML ページとしてパルスを描画する。五つの視点それぞれにパネルを一つ。売上推移、獲得単価、受注率は数値タイルにし、比較値を文脈行に置く。キャンペーンの費用対効果と商品の成績は表にし、広告費と売上の列は tabular-nums。各視点のステータスはステータスピル（good、warn、critical、または n/a を平文で）。三つの施策は順位付きで、独立したパネルとしてページを締める。
- **docx / md / notion / canva：** 同じ内容をその形式で届ける — DOCX または Markdown ファイル、コネクタ経由で作る Notion ページ（指定された保存先に。上書きしない）、Canva コネクタで作る Canva Doc（毎回新しいデザイン、日付付きの名前。表は箇条書きにする）。Notion や Canva が未接続なら visual artifacts にフォールバックし、その理由を言う。
- **best for skill：** visual artifacts を使う — 五つの視点は一画面で横並びに比較するのが最も分かりやすい。

## ステップ7 — 保存を一度だけ提案する

提示したあと、パルスをファイルに保存するか Slack に投稿するかを一度だけ提案する。Slack への投稿は外向きの書き込みなので、明示的な「はい」があったときだけ実行する — この提案が承認ゲートだ。「はい」なら実行する。「いいえ」か無反応なら先へ進む。二度は聞かない。

続けて、パルスが見つけたことを一行で締め、最も関連する次の一手と、近いものを最大二つ添える：

- 施策がコンテンツや販促を指しているなら：「何を推すべき」で `content-strategy` が動く。
- ファネルが問題なら：「ファネルを埋めたい」で `/grow-pipeline` が動く。
- 財務側の双子は：「会社の調子はどう」で `business-pulse` が動く。

提案は最大三つ。このセッションで経営者が断った提案は繰り返さない。

## 範囲の変形

経営者はパルス全体ではなく一部だけを求めることが多い：

- **「キャンペーンの結果は」** — キャンペーンの費用対効果だけ。評判のチェックを添える
- **「パイプラインの調子は」** — ファネルの転換率と止まっている商談だけ
- **「何が売れてる」** — 商品の成績だけ
- **「口コミは増えてる？」** — 評判だけ
- **「来月どこに使うべき」** — チャネル推移とキャンペーンの費用対効果。三つの施策は予算配分に寄せる

求められた部分を渡す。狭い質問にパルス全体を押し付けない。

## やってはいけないこと

- **データを取る前に許可を求めない。** スキルは呼び出された。動かす。
- **帰属をでっち上げない。** キャンペーンの売上が追えないなら、推測で売上を割り当てるのではなく「帰属は不明」と言う。偽の帰属が本物の予算を動かしてきた。
- **CRM の見込み金額を売上として報告しない。** 商談金額は希望で、請求書は事実。どちらがどちらかを明記する。
- **取得元をまたいで二重計上しない。** Stripe で決済された Shopify の注文は一件の売上。売上の取得元を一つ選び、それを名指しする。
- **一つの取得元の中でも二重計上しない。** 会計ソフトの得意先別売上や補助科目付き試算表は、親（勘定科目・親得意先）と子（補助科目・案件）の両方の行を返す。顧客を順位付けしたり集中度を計算したりする前に親行を除く。さもないと同じ顧客が一覧に二度現れ、集中度が高く出る（`../../shared/ledger-report-traps.md`、罠3）。
- **全社売上を狭いチャネルの分母にしない。** ひかり珈琲焙煎所の月商 1,200万円で EC 広告の ROAS を計算すれば、数字は巨大で、見栄えがよく、完全な作り話になる。EC の売上 30万円に対して計算し、両方を書く（`../../shared/chain-seams.md`）。
- **緊張感を演出しない。** 成長が安定しているなら、パルスも安定して読めるべきだ。
- **会計ソフトの PL サマリーから費用や粗利を読まない。** 行を合計する（`../../shared/ledger-report-traps.md`、罠2）。

## 一覧にないツールを使う

このスキルで名前を挙げたコネクタは検証済みの道筋であって、壁ではない。経営者が未接続・未掲載のツールでこの流れを動かしたいなら、`build-connector` を提案する — まずコネクタディレクトリを確認し、なければ Zapier 経由で接続する。生の API に手作りで当たることはしない。接続ができれば、そのツールは他の任意コネクタと同じく、同じ承認ゲートのもとでこのスキルに加わる。
