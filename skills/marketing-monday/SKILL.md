週次の成長ブリーフを、二つのスキルをチェーンして実行する — `growth-pulse` で仕組みが回っているかを、`review-reputation` で顧客が何と言っているかを — そのうえで Web 調査による競合スキャンを加える。三つの部分は一つに統合したブリーフに流れ込む。三つの報告書をホチキスで留めたものではない。

コネクタ：PayPal、Shopify、HubSpot のいずれか一つあれば動く。Apollo、Clay、Mailchimp、Square、Stripe、TikTok広告はそれぞれ層を一つ加える。TikTok広告は growth-pulse 経由でステップ1 に有料広告の層を加える：先週の広告費、成果数、成果単価を売上推移の隣に置き、プラットフォーム自身の主張として CRM のリード数と並べて報告し、決して混ぜない（`../growth-pulse/reference/data_sources.md`）。Google 広告・Yahoo!広告・Meta広告・LINE広告は `build-connector` で作った連携か CSV エクスポートから。Mailchimp はステップ1 にメールのチャネルを加える（`get_capabilities` の呼び出しには `user_request` と `category` が要る。`../../shared/connector-call-shapes.md`）— 売上帰属つきのキャンペーン分析とオーディエンス増減の数字。このブリーフでは読み取り専用で、ここから下書きも送信もしない。帰属売上はメールチャネル自身の主張としてプラットフォームと CRM の数字の隣に報告し、一つの数字に混ぜない。どれもなければ CSV エクスポートと貼り付けた口コミが入力になり、競合スキャンはコネクタなしで Web 調査として動く。

既定の期間：パルスは直近 7 日、口コミは直近 90 日、競合ウォッチリストは前回の実行以降。

月曜が祝日なら火曜の朝に回し、「今週」は火曜始まりで読む。

## ステップ1 — 仕組みは回っているか（growth-pulse）

`growth-pulse` スキルのワークフローを起動する。すべてのコネクタを一括の並列バッチで取得する。直列で取りに行くと、誰も二度は付き合わない待ち時間になる。

**入力:** 接続されているものすべて、またはエクスポート。**出力:** チャネル推移、ファネルの転換率、キャンペーンの費用対効果、商品の成績、顧客の評判 — それぞれにステータスを付け、欠けているものは黙って落とさず「n/a」と記す。

**引き継ぎ:** この期間を説明する一文と、ファネルで最も大きく落ちる段階と、推移全体を支えている商品があればそれを持ち越す。五つの視点のダッシュボード全体を統合ブリーフに持ち込まない。

**ここにゲートはない。** コマンドは呼び出された。動かす。データを読むことは承認に値する行為ではない。

## ステップ2 — 顧客は何と言っているか（review-reputation）

`review-reputation` スキルのワークフローを起動する。

**入力:** 公開されている口コミ（Googleビジネスプロフィール、食べログ・ホットペッパー、楽天・Amazon のレビュー）、PayPal の異議申し立て、HubSpot のチケット、苦情の言葉を含むメールのスレッド、そして直接読めるものがないときは貼り付け・エクスポートされた口コミ。**出力:** 原文の引用を添えたテーマ三〜五つ、返信が必要な口コミ、静かになった顧客。

**引き継ぎ:** テーマと評価点の向きを持ち越す。下書きした返信はブリーフの内容としてではなく、別の承認キューとして持ち越す。

**ゲート:** 経営者が先に読まない限り、公の場には何も投稿しない。口コミ一件ずつ。このゲートはチェーンの中でも無傷で残る — 統合ブリーフは、経営者の名前で返信してよいという包括承認にはならない。

静かになった顧客の一覧に取り組む価値があるなら、このブリーフの中で掘り起こしの下書きを始めるのではなく、`/reactivate` を指す。

## ステップ3 — 競合は何をしたか（Web 調査）

この工程はインラインで回す — コネクタは要らない。経営者が保存した競合ウォッチリストを確認し（初回は三〜四社の名前を聞いて保存する）、公開情報をスキャンする：競合の Web サイトと料金ページ、SNS と広告の動き、求人票、プレスリリースや報道。HubSpot が接続されていれば HubSpot の受注・失注メモを加える。

**出力:** 何が変わったか。観察した事実と推論を分けてラベルを付け、すべてに日付を入れる。推論を観察として提示しない。

**引き継ぎ:** 重要な変化だけを持ち越す。静かな週は静かな週として報告する — 三行、水増しなし。その正直さがあるから、本当に何かが起きた週が強く響く。

**ゲート:** 情報に基づいて何も実行しない。値下げもキャンペーンも経営者の判断だ。

## ステップ4 — 一枚のブリーフに統合する

このコマンドを持つ価値を決めるステップなので、近道をしない。

出力は **一枚のページ** であって、三つのセクションをそのまま渡したものではない。三つの入力を一緒に読み、互いを説明し合っている場所を探す。たいてい重要になるつながり：

- 売上は保っているのに評判が落ちているのは、二か月後に売上に現れる早期警報。
- 利益率がすでに薄い商品に対する競合の値下げは、メモではなく決断。
- リード数は多いのに受注率が落ちていて、口コミに対応の遅さの苦情があるなら、同じ話が二度語られている。
- 静かになった顧客の一覧が伸びているのと同時に競合の新店舗ができたなら、原因に名前のある離反。

構成：

1. **見出し** — 今週最も重要なこと一つを、一文で
2. **成長の成績** — 数字、それぞれに比較対象を添えて
3. **顧客の声** — 原文の引用を添えたテーマ
4. **周囲で変わったこと** — 競合の動き、観察した事実と日付つき
5. **今週やる三つのこと** — ちょうど三つ、影響の大きさで順位付け

施策には、何をするか、それを裏付けるこのブリーフの数字、いくらの価値かが要る。影響で順位付けし、やりやすさでは付けない — 何が簡単かは岡本さん自身が判断できる。何が大きいかはブリーフにしか言えない。

正直な答えが「変えるべきことはない」なら、そう言う。毎週三つの施策をひねり出すブリーフは、経営者に全部を無視することを教える。

## ステップ5 — 定期実行を一度だけ提案する

これを毎週回すことを提案する。聞くのは一度。「はい」なら曜日と時刻を確認する。**ただし、このプラグインにスケジューラはない**（`../../shared/chain-seams.md`「誰も設定していない定期実行」）。実行環境に本物の定期実行の仕組みがあればそれを作ってから「設定しました」と言う。なければ率直にそう言い、Google カレンダーの繰り返し予定（「月曜 8:00: マーケティング月曜便を実行」。祝日の月曜は火曜）を提案する。「いいえ」か無反応なら先へ進み、同じ実行の中で二度と聞かない。

定期実行のたびに前回と比較し、基準を先へ転がす。変化は基準があって初めて意味を持つ。

## 承認ゲート（必ず守る）

- 口コミへの公開返信は、口コミごとの承認なしに投稿しない。
- このコマンドから掘り起こしのメッセージを送らない — それは `/reactivate` の仕事。
- 競合情報に基づく価格やキャンペーンの行動を取らない。提案して止まる。
- 定期実行は明示的な「はい」があったときだけ設定する。
- コネクタが失敗したら、取得元の行に名前を挙げて続ける。名指しされた欠落は情報だが、黙った欠落は良い知らせに見える。

## やってはいけないこと

- **三つの報告書をホチキスで留めない。** 最後に三つの施策が付いた一枚の統合ブリーフが成果物だ。出力が、成長のセクション、口コミのセクション、競合のセクションと並び、間をつなぐ一文がなければ失敗している。
- **静かな週を水増ししない。** 「重要な変化なし」が、何かが起きた週の信頼性を守る。
- **帰属や競合の動きをでっち上げない。** どちらも他の人に繰り返し伝えられる。
- **CRM の見込み金額を売上として報告しない。** 商談金額は希望で、請求書は事実。
- **定期実行について二度以上聞かない。**
- **施策を三つより多くしない。** 四つは誰も手を付けないやることリストだ。
- **会計ソフトの PL サマリーから費用や粗利を読まない。** サマリーの費用合計は実際の行があるのに 0 になり得る。行または月次内訳を合計する（`../../shared/ledger-report-traps.md`、罠2）。

## 出力

チャットに一枚、三つの施策を最後に。ファイルに保存するか Slack に投稿するかを一度だけ提案し、それ以上は聞かない。

あわせて、統合ブリーフを経営者の保存された出力形式で届ける — Markdown ファイルを既定にしない。`## Business context` ブロックの「出力形式」を確認する（共通スタイルガイドのルール、`../../shared/artifact-style.md`）：

- **ビジュアルアーティファクト（既定）:** ブリーフをハウススタイルの HTML ページとして描画する。一枚で、統合を映す：見出しの数字は成長の数値タイル、原文の引用を添えた顧客の声のパネル、日付つきで観察と推論を分けてラベルした競合の変化の一覧、そして最後に三つの施策のパネル。チャットのサマリーは残す — アーティファクトは追加であって、唯一のコピーにはしない。
- **docx / md / notion / canva の出力形式:** 同じ内容をその形式で届ける — DOCX または Markdown ファイル、コネクタ経由で作る Notion ページ（指定された保存先に。上書きしない）、または Canva コネクタで作る Canva Doc（毎回新しいデザイン、日付付きの名前。表は箇条書きにする）。Notion や Canva が未接続ならビジュアルアーティファクトにフォールバックし、その理由を言う。
- **best for skill:** ビジュアルアーティファクトを使う — 週次ブリーフは眺めるものであって、ファイルに綴じるものではない。

## 締めの提案

届けたものを一行で述べる — 今週の見出しと三つの施策。次に最も関連する一手をトリガー語句付きで示す。静かになった顧客の一覧に取り組む価値があるなら、通常は「休眠顧客を掘り起こしたい」（`/reactivate`）。ほかにルーターの表から最大二つ：「何を売り込むべき？」（`content-strategy`）や「誰に電話すべき」（`lead-triage`）。提案は最大三つ。このセッションで経営者が断ったものは出さない。

## 一覧にないツールを使うとき

このスキルに書かれたコネクタは検証済みの経路であって、壁ではない。経営者が接続されていない、または一覧にないツールでこの流れを回したいなら、`build-connector` を提案する — まずコネクタディレクトリを確認し、なければ Zapier 経由で接続し、生の API に対して手組みはしない。接続ができれば、そのツールは他の任意コネクタと同じく、同じ承認ゲートのもとでこのスキルに加わる。
