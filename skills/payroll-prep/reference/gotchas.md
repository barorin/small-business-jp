# 落とし穴

誰かを過少支給する、期間を二重に払う失敗。給与の誤りは会計の誤りではない — 25日に誰かの銀行口座に着地する。

---

## 落とし穴：退勤打刻の漏れを埋める

**なぜ重要か：** これはこのスキルがやり得る最も有害なことだ。埋めた打刻は完全に普通に見える給与を生むので、誰も確かめない。推測が低ければ誰かがただ働きし、高ければ経営者は払いすぎに永遠に気づかない。

### 悪い例

```
佐藤さん、8月12日（水）：6時40分 〜 15時10分（退勤は推定、いつもの時刻）
所定内 8.0時間
```

### 良い例

```
佐藤さん、8月12日（水）：6時40分に出勤打刻、退勤打刻なし。
時間不明 — 下の総支給はこのシフトを完全に除いています。
実際には何時まで働きましたか？
```

---

## 落とし穴：休憩を二重に引く、または引かない

**なぜ重要か：** 8名で一日 1時間、一か月なら 160時間以上になる。アップロードされたシートを見ただけでは、昼休みがすでに引かれているか分からない。

### 悪い例

アップロードされたシートの時間を総時間と決めつけ、一日 60分を引く。

### 良い例

一度聞く：「このシートは昼休みをもう引いてありますか、それともこちらで引きますか？」そのうえで一貫して適用し、どちらにしたかを準備シートに書く。

---

## 落とし穴：社会保険料や税額を推定する

**なぜ重要か：** 経営者はその合計で給与を払えるかを判断する。総支給に対する割合での推定は正確に見えて数万円ずれ得るし、資金が苦しいときにはまさにその差が効く。

### 悪い例

```
法定福利費（推定 15%）   480,000円
必要資金               3,680,000円
```

### 良い例

```
法定福利費   給与計算ソフトの計算待ち（前月実績 480,000円）
総支給（概算）   3,200,000円
25日までに差引支給の 2,525,000円、翌月末に社会保険料の労使合計分が口座に必要です。
```

---

## 落とし穴：単価の変更を黙って受け入れる

**なぜ重要か：** 動いた単価は、経営者が与えた昇給か、データの誤りかのどちらかだ。両方よくある。聞かずに計算すればどちらでも間違った額を払い、給与の訂正は巻き戻すのが本当につらい。

### 悪い例

記録から 1,750円を読み、それを使い、何も言わない。

### 良い例

```
鈴木さんの時給が今期 1,750円、前期は 1,650円です。月に 16,000円ほどの差です。
昇給ですか、それとも入力ミスですか？
```

---

## 落とし穴：フラグの確認を一括にする

**なぜ重要か：**「フラグ 3件、どれも軽微に見えます、進めますか？」は「はい」をもらう。一つずつ聞かれたフラグには本当の答えが返る。経営者が一人のことを一度に考えるからだ。

### 悪い例

```
異常 3件を検出。確認のうえ進めてください。
```

### 良い例

三つの別々の質問。それぞれ本人、日付、金額を名指しし、一つずつ答えてもらって記録する。

---

## 落とし穴：給与を確定する・振込を実行する

**なぜ重要か：** 総合振込が実行されれば取り消すのは非常に難しく、取り消し自体が本人に見える。準備と確定の間は、誤りをただで捕まえられる最後の場所だ。

### 悪い例

経営者が準備シートに「はい」と言ったから、給与計算ソフトで確定し、ネットバンキングで振込を実行する。

### 良い例

準備し、給与計算ソフトに投入できる CSV が整ったと経営者に伝え、確定と振込のボタンは経営者に押してもらう。理由も言う：何かを捕まえられる最後の無料の機会だからだ。

給与計算ソフトや銀行に書き込めるコネクタがあっても同じルールだ。書き込み権限があることは給与を払う許可ではなく、そこでの取り消しも楽にはならない。

---

## 落とし穴：月末をまたぐ期間

**なぜ重要か：** 8月 31日締めで 9月 25日払いの給与は二つの月にまたがる。推測を誤れば、その月の労務費が過小になるか、資金が違う月に着地する。

### 悪い例

働いたのはその月だからと、仕訳全体を締め日の日付で登録する。

### 良い例

未払計上しているかを一度聞く。普通預金は支払日で登録する。未払計上しているなら給与手当を分け、していないなら、未払計上のなかった帳簿に未払費用の仕訳を作らない。

---

## 落とし穴：名簿にない人に払う

**なぜ重要か：** 入社記録のない名前が勤怠データに現れるのは、誰も設定していない新人か、誤りのどちらかだ。先に払ってあとで整理すると、源泉徴収・社会保険・雇用区分の問題になる。

### 悪い例

シートに新しい名前、時間は普通に見える、含める。

### 良い例

```
「コバヤシ」がシートに 22時間で載っています。入社記録がありません。
新しい見習いの方ですか、それとも既存の誰かに合わせるべき名前ですか？
```

---

## 落とし穴：作った労務費率で労務費を配賦する

**なぜ重要か：** 会社のすべての工事の粗利がその数字を引き継ぐ。推測した 22% の上乗せはすべてを同じ方向に狂わせ、それは最も気づきにくい種類の誤りだ。

### 悪い例

工事原価が完全に見えるように、標準の上乗せ率を適用する。

### 良い例

総支給のまま配賦し、「上乗せなし」と表示し、経営者に労務費率を一度聞く。そして記憶する。

---

## 落とし穴：個人情報を準備シートに写す

**なぜ重要か：** 給与計算ソフトの CSV にはマイナンバー、生年月日、住所、口座番号が含まれる。準備シートやチャットに写した瞬間に、それは経理の文書ではなく漏えい事案になる。

### 悪い例

給与計算ソフトの従業員一覧をそのまま貼り付けて「確認してください」と出す。

### 良い例

名前、雇用区分、時間、単価、支給額だけを載せる。個人情報の列は読み飛ばし、必要なら「マイナンバー 収集済／未収集」のフラグだけを置く（`../../../shared/personal-data.md`）。
