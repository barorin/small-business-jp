# 決算・法定調書の整理

> **位置づけ：** このスキルが作るのは顧問税理士に渡す準備資料であって、税務アドバイスではない。
> 冒頭でそう言い、すべての前提を明示して、税理士が調整できるようにする。

## クイックスタート

経営者がどちらのモードを必要としているかを判定し、該当データを取得し、計算または集計し、
税理士がそのまま作業に入れる構造化された文書を渡す。

```
経営者：「今期の税金、いくらくらい準備しておけばいい？」
→ 会計ソフトから年度累計の損益（残高試算表 PL）を取得
→ 法人税等（目安税率）＋消費税（課税方式に応じて）を年換算で見積もる
→ 納付済みの中間納付・予定納税を差し引く
→ 納付期限と前提を明記して、今から積み立てるべき月額を示す
→ 出力：「決算納付の目安 約420万円（5月末納付）— 内訳と前提は以下」

経営者：「支払調書を出さないといけない」
→ 会計ソフト＋PayPal＋Stripe から報酬・料金・外注費・地代家賃の支払いを取得
→ 源泉徴収対象の報酬区分（所得税法204条）を判定し、支払先別に年間合計を集計
→ 同一人 5万円超（不動産使用料は 15万円超）を支払調書候補に
→ マイナンバー・住所の未収集、インボイス登録番号の未確認をフラグ
→ 出力：支払調書候補一覧＋源泉徴収税額の突合＋未収集情報の対応リスト
```

## ステップ0 — 事業形態・決算月・課税方式を先に確認する

以下の二つのパスはいずれも **事業形態と決算月で計算の土台が変わる**。モードを選ぶ前に、`## Business context` ブロックから `事業形態`・`決算月`・`消費税`・`顧問税理士` を読む（ルール：`../../shared/currency-and-locale.md`）。無ければ一度だけ聞く。

- **法人（株式会社・合同会社 など）** → 法人税等＋消費税。年度は決算月基準。
- **個人事業主** → 所得税・住民税・個人事業税＋消費税。年度は暦年（1〜12月）固定。
- **消費税の課税方式**（本則課税／簡易課税／2割特例／免税事業者）が不明なら、マネーフォワードでは `getTaxes` の税区分設定を手がかりにしつつ、経営者に確認する。

会計ソフトから読めるものは読む：マネーフォワード クラウド会計なら `currentOffice`／`getTermSettings` で事業者名と会計期間を取り、事業者名が経営者の会社と一致することを確認する（`../../shared/tenant-scope.md`）。金額はすべて円。5万円・15万円のラインは所得税法の法定基準なので、そう明記する。

## モードの判定

経営者のメッセージと文脈から、どちらのパスかを決める：

- **納税資金の見積もり** — キーワード：納税資金、税金の積立、いくら残しておく、中間申告、予定納税、決算の納付、消費税いくら
- **法定調書・支払調書の準備** — キーワード：支払調書、法定調書、合計表、外注先、報酬、源泉徴収、マイナンバー、1月末
- **両方** — 「年末の整理」「決算前にまとめて」と言われたら両方必要。支払調書の準備を先に実行する（期限が近く、対応項目を最も多く生む）。納税見積は後。

意図が曖昧なら聞く：「今期の納税資金の見積もりですか、外注先への支払調書の準備ですか — それとも両方でしょうか？」

## パス1：納税資金の見積もり

### 1. 年度累計の損益を取得する

接続済みの会計ソフト（freee会計、マネーフォワード クラウド会計、弥生会計 など — 同格、`../../shared/connector-neutrality.md`）から、期首から直近の締め済み月末までの損益を取得する。マネーフォワードなら `getReportsTrialBalanceProfitLoss` を期間指定で呼ぶ。取るもの：
- **売上高**（税抜。経理方式が税込なら明記）
- **費用合計**（売上原価、販売費及び一般管理費、営業外費用）
- **税引前当期純利益** = 売上高 − 費用（＋営業外収益）

会計ソフトが未接続なら、残高試算表を CSV でアップロードするか、主要な数字を貼ってもらう。会計ソフト別の項目名と取得方法は [reference/connector-queries.md](reference/connector-queries.md)。

### 2. 納付済みの税額を聞く

計算前に聞く：「今期すでに納めた中間納付（法人）や予定納税（個人）はありますか？」分からなければ、年間の見込み税額を出し、納付済み分は経営者または税理士が差し引けるようにする、と伝える。前期の確定税額も聞く — 中間申告・予定納税の要否がそれで決まる。

### 3. 見込み税額を計算する

計算の全体と、出力に必ず含める前提表は [reference/calculation-assumptions.md](reference/calculation-assumptions.md)。

**まず年換算する。** 計算は年度累計ではなく、通期の見込み利益で走らせる：
`年換算利益 = 年度累計利益 ÷ 経過月数 × 12`。両方をラベル付きで示す。季節変動のある事業は直線で伸ばさず、経営者に聞く。

短縮版。六つのステップはすべて **年換算した** 税引前利益に対して走る：
1. **法人税等の目安**（法人）= 所得 800万円以下の部分 × 約23〜25% ＋ 800万円超の部分 × 約33〜34%（目安。均等割は別途）／**所得税等の目安**（個人）= （利益 − 青色申告特別控除）に累進税率 ＋ 住民税 10% ＋ 個人事業税
2. **消費税の目安** = 本則：売上税額 − 仕入税額／簡易課税：売上税額 × (1 − みなし仕入率)／2割特例：売上税額 × 20%／免税事業者：0
3. **年間の見込み税額** = 法人税等（所得税等）＋ 消費税
4. **中間申告・予定納税の要否** = 前期の確定税額で判定（法人税は前期 20万円超、消費税は前期 48万円超、個人は予定納税基準額 15万円以上 — 税理士確認）
5. **今後の納付額** = 年間の見込み税額 − 納付済み額。納付期限ごとに分けて示す
6. **積立の目安** = 今後の納付額 ÷ 納付期限までの月数。「利益の 30% 前後を別口座に」は目安であって法定ではない、と添える

**納付期限をすでに過ぎて未納なら**、名指しして追納分を別行に出す。延滞税・加算税は税理士の領域 — かかることをフラグし、金額は見積もらない。消費税の預り分は自社の資金ではない、と毎回言う。

### 4. 前提を明記して出力する

節ごとの文書構造は [reference/output-formats.md](reference/output-formats.md)。

譲れないことが二つ：**事業年度（または暦年）をヘッダーに書く**こと、**前提の節にすべての前提を列挙する**こと — 事業形態、決算月、消費税の課税方式、税率は目安、所得控除は未反映、地方税の超過税率は未反映、繰越欠損金は未反映。税理士はそのレバーから調整するので、一つ抜けると組み直しになる。

## パス2：法定調書・支払調書の準備

### 1. 報酬・料金の支払いをすべての情報源から取得する

接続済みの各情報源から、**暦年（1月1日〜12月31日）の役務提供に対する支払い**をすべて取得する。法人の決算月が3月でも、法定調書は暦年で作る。物品の購入、返金、自社口座間の振替は含めない。

**会計ソフト — まずコネクタ、だめなら CSV。** マネーフォワードなら `getAccounts` で外注費・支払手数料・支払報酬・地代家賃・顧問料などの勘定科目 ID を特定し、`getJournals` を期間と勘定科目で絞って `getTradePartners` の取引先と突き合わせる。freee会計なら「取引」を勘定科目・取引先で絞る。弥生会計は仕訳日記帳 CSV。判定ロジック、依頼の文言、会計ソフト別の列対応は [reference/connector-queries.md](reference/connector-queries.md)。

**PayPal：** 「商品・サービス」として送金した支払いをすべて取得する。海外のフリーランスへの支払いが混ざっていたら、非居住者への源泉徴収の論点があるので別枠でフラグし、税理士に判断を委ねる。

**Stripe：** 外部（Connect アカウント等）への送金があればすべて取得する。自社口座への入金（payout）は対象外。

**Square：** コネクタ経由では外部への支払いを持たない（入金は自社口座へ、給与は別）。黙って落とさず「情報源として確認したが該当なし」と名指しで書く。決済手数料は支払手数料だが支払調書の対象外。詳細は [reference/connector-queries.md](reference/connector-queries.md)。

**CSV アップロード：** 経営者が直接 CSV を渡した場合、列を対応付ける：支払先名、金額、日付、支払方法、勘定科目、マイナンバー・法人番号の収集状況。

### 2. 支払先ごとに集計する

情報源を横断して合算し、個人または法人ごとに年間合計を出す。名寄せは名前で行う（「佐藤 健」と「佐藤 健一」、「山本デザイン」と「山本 美咲」のような揺れは、自動で統合せず、重複の可能性として人の確認に回す）。

### 3. 報酬区分と 5万円のラインを当てる

- **支払調書の候補（報酬・料金）：** 所得税法 204条の区分（原稿料、講演料、デザイン料、弁護士・税理士・司法書士・建築士等の報酬、外交員報酬 など）に該当し、同一人への年間支払いが **5万円超**
- **支払調書の候補（不動産の使用料等）：** 個人の大家への家賃・地代・権利金が年間 **15万円超**（支払先が法人なら賃借料は対象外、権利金等のみ — 税理士確認）
- **対象外だが一覧に残すもの：** 工事の請負・運送・物品購入など 204条に該当しない外注費。「対象外」と理由付きで書く
- **ライン付近の注意：** 年間 3万〜5万円の支払先は、計上漏れがないか税理士が確認したい可能性があるのでフラグ

法人への支払いは源泉徴収は不要だが、区分に該当すれば支払調書の提出は必要 — 自動で除外せず、税理士の確認に回す。

### 4. 源泉徴収税額とインボイスを確認する

フラグした支払先ごとに、次を確認する：
- **源泉徴収：** 報酬から 10.21%（同一人への1回の支払いが 100万円超の部分は 20.42%）が差し引かれているか。会計の預り金（源泉所得税）の報酬分の合計と、納付書（毎月 10日、または納期の特例なら 7月10日・1月20日）の納付額を突合する
- **マイナンバー・住所：** ✅ 収集済（会計ソフトの取引先情報に登録あり）／⚠️ 未収集 — 調書作成前に依頼が必要／❓ 不明 — データからは判定できない。**番号そのものは絶対に出力しない**
- **インボイス：** 適格請求書発行事業者の登録番号（T＋13桁）の有無。免税事業者への支払いは仕入税額控除の経過措置 **80%（〜2026年9月30日）→ 50%（2026年10月1日〜）** で、消費税の見積もりにも効く

### 5. 法定調書パックを渡す

節ごとの構造は [reference/output-formats.md](reference/output-formats.md)。

いちばん重いのは、**未収集情報の対応リスト**（これが無いと調書が作れず、法定調書合計表の期限は 1月31日）と、**源泉徴収税額の突合**（会計の預り金と納付額が合わなければ、納め忘れか計上漏れのどちらかで、税理士が先に知りたい）。給与側の年末調整・源泉徴収票・給与支払報告書は `payroll-prep` の領域なので、そちらに引き渡す一文を添える。

## ガードレール

- **事業年度（暦年）をすべての出力に書く。** [reference/calculation-assumptions.md](reference/calculation-assumptions.md) の税率・控除額・期限は **令和8年（2026年）時点の目安** だ。別の年度を扱うなら、数字を出す前にそう言い、国税庁サイトの最新値を引くか経営者に聞く。**税率、控除額、期限を創作しない。**
- **税務アドバイスではない。** すべての成果物を「顧問税理士の確認用に準備した資料 — 税務アドバイスではありません」で始める。チャットだけでなく文書のヘッダーに入れる。
- **すべての前提を明記する。** 目安税率を使ったならそう言う。所得控除を反映していないならそう言う。税理士が調整する — レバーを渡す。
- **支払先を自動で統合しない。** 重複の可能性は人の確認に回す。
- **何も提出しない。** 出力は準備資料。e-Tax での提出や納付は対象外。
- **法人への支払いの扱いは判断事項。** 源泉徴収不要でも支払調書は要ることがある。注記し、自動除外しない。
- **マイナンバー、銀行口座番号・カード番号の全桁を出力しない** — パック、チャット、描画ページのいずれにも。法人番号は公開情報なので出してよい（`../../shared/personal-data.md`）。

## 追加の情報源

- **給与計算ソフト（freee人事労務、マネーフォワード クラウド給与、SmartHR、ジョブカン など。CSV エクスポート）** — 実際に計算された給与、源泉徴収税額、賞与。両モードに効く — 納税見積は人件費を推測しなくて済み、法定調書側では給与分の源泉所得税と報酬分を分けて納付額と突合できる。給与計算ソフトが源泉徴収票や支払調書をすでに出力していれば、二重に作らずフラグする。
- **マネーフォワード クラウド請求書／請求書 CSV** — 受領した請求書の登録番号（インボイス）と支払日。支払調書は支払日基準なので、12月に受領して1月に支払った請求書は翌年分になる。
- **法人カード明細（会計ソフトのカード連携）、Expensify** — 経費側の詳細で、納税見積の費用の裏付けと、支払先一覧の漏れ確認に使う。Expensify の領収書なしフィルタは、電子帳簿保存法と税務調査で突かれる経費を先に見つける — 税理士が申告前に最も欲しいフラグだ。
- **海外製会計ソフト（Xero、Zoho Books、NetSuite など）** — 同格に扱う。損益と取引先別の支払いが読めれば同じ手順。マイナンバー・登録番号の項目は持たないことが多いので、収集状況は経営者に聞く。

同じ計算、同じ税理士向けパック。情報源が増えるほど、明記すべき前提が減る。

## 出力

**見積もりまたは法定調書パックは、経営者が保存した出力形式で渡す — 既定で Markdown ファイルにしない。** `## Business context` ブロックの `出力形式` を確認する（共通スタイルルール、`../../shared/artifact-style.md`）：

- **visual artifacts（既定）：** 概要をハウススタイルの HTML ページとして描画する — 見積額または支払調書の件数を先頭の統計タイルに、前提表、未収集情報を1行ずつピル付きで、期限を最上部に。「税務アドバイスではありません」の一文で始める。税理士向け文書そのものは `reference/output-formats.md` の構造を保つ。
- **docx / md / notion / canva：** 同じ内容をその形式で渡す — DOCX または Markdown ファイル、コネクタ経由で作成する Notion ページ（指定された保存先、上書きしない）、Canva コネクタ経由の Canva Doc（実行ごとに日付付きの新規デザイン、表はリストに）。Notion や Canva が未接続なら visual artifacts にフォールバックし、その理由を言う。
- **best for skill：** visual artifacts を使う — この出力は税理士向け文書の上に載るステータスページだ。

## パックの後

見積もりまたは法定調書パックは、前提付きで税理士の手元にある。自然な次の一手は「月次決算」— `/close-month` で、次の見積もりを生の帳簿ではなく確定した数字の上で回す。近くにあるもの：「資金繰り」（`cash-flow-snapshot`）で納付日に資金が足りるかを確認、「未入金の確認」（`invoice-chase`）で回収が納付を賄う必要があるとき。提案は最大三つ、このセッションで経営者が断ったものは出さない。

## 一覧にないツールを使う

このスキルに名前のあるコネクタは検証済みの経路であって、壁ではない。経営者が未接続・未掲載のツールでこの流れを使いたいなら、`build-connector` を提案する — まずコネクタディレクトリを確認し、なければ Zapier 経由で接続する。生の API に対して手組みはしない。接続ができれば、そのツールは他の任意コネクタと同じ承認ゲートの下でこのスキルに加わる。
