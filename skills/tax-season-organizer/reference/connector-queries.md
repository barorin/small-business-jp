# コネクタ別のデータ取得ガイド

各モードで、各コネクタから正しいデータを引く方法。会計ソフトは同格
（`../../../shared/connector-neutrality.md`）：接続されているものを使う。両モードとも
事業形態・決算月・課税方式が土台なので、スキルのステップ0の確認をこの前に済ませる。

---

## マネーフォワード クラウド会計 — 納税見積モード（損益）

`getTermSettings` で会計年度（開始日降順）を読み、期首と決算月を確定する。次に
`getReportsTrialBalanceProfitLoss` を期首から直近の締め済み月末までの期間で呼ぶ。
取るのは三つ：売上高、費用合計（売上原価＋販管費＋営業外費用）、税引前当期純利益。

- 列は `opening_balance`、`debit_amount`、`credit_amount`、`closing_balance`、`ratio` 固定。
  **全項目 0 の科目は返らない**（「無い」と「0」を区別する。`../../../shared/absent-is-not-zero.md`）。
- `include_tax` は経理方式が「税抜（内税）」のときだけ効く。税込経理なら売上高に消費税が
  含まれるので、消費税の見積もりでは税抜に戻して計算し、そう明記する。
- 未実現仕訳は含まれず、常に全部門合計。部門別の見積もりは `getDepartments` を使っても
  この試算表からは出ない。
- 季節変動の確認は `getReportsTransitionProfitLoss`（月次推移）。直線で年換算してよいか、
  月ごとの売上の山を見てから判断する。

事業コンテキストに `決算月` や `消費税` が無ければ、`currentOffice` で会計期間を、
`getTaxes` で税区分の設定（課税・免税・簡易課税の手がかり）を先に読む。3月決算なら
「年度累計」は 4月〜、個人事業主は暦年 — 期間を一度解決し、どの基準で見積もったかを書く。

**初回の実行前に、この節のツール名を必ず確認する。**

## マネーフォワード クラウド会計 — 法定調書モード（報酬・料金の支払い）

三つの読み取りを、この順で：

1. **`getAccounts`** — 外注費、支払手数料、支払報酬、顧問料、地代家賃、広告宣伝費
   （デザイン料が混ざる）、雑費（講演料が混ざる）の勘定科目 ID を特定する。補助科目で
   「報酬」「デザイン」「税理士」などに分かれていれば `getSubAccounts` も読む。
2. **`getJournals`** — 暦年（1月1日〜12月31日）を期間に、上記の勘定科目で絞る。各仕訳行の
   `trade_partner_code`（取引先）、`value`、`tax_id`（税区分）、`invoice_kind`
   （`INVOICE_KIND_QUALIFIED`／`INVOICE_KIND_UNQUALIFIED_80`／`_50` 等 — インボイスの
   有無と経過措置の区分がここに出る）を取る。**支払日基準で年を割り当てる：** 支払調書は
   支払った年で作るので、12月に計上して1月に支払った請求書は翌年分。年の境目の前後
   両方の期間を引き、取引先ごとに支払年で合計する。
3. **`getTradePartners`** — 取引先の名称、法人番号の有無、住所の登録状況。マイナンバーは
   会計ソフトに登録しない運用が多いので、「未収集」ではなく「❓ 不明」から始め、経営者に
   聞く。**番号自体は取得しても出力しない。**

源泉徴収税額の突合には、`getAccounts` で預り金（源泉所得税）の科目と補助科目（給与分／
報酬分）を特定し、`getJournals` で貸方（徴収）と借方（納付）を月別に集計する。

実例（形だけ）：

```
マネーフォワード 支払先別集計、2025年分：
  佐藤設計事務所        840,000円   建築士報酬（204条2号）  登録番号あり  法人番号あり
  山本 美咲              76,000円   デザイン料（204条1号）  登録番号なし  マイナンバー未収集
  鈴木 拓也           1,520,000円   工事請負 — 204条の対象外（外注費）  登録番号なし（経過措置 80%）
```

ここから先の集計・5万円のライン・収集状況の判定は、他のすべての情報源と同じ。

### コネクタが取引先別の内訳を返さないとき

まずコネクタを試し、だめならフォールバック。三段階：

1. **コネクタを試す。** `getJournals` を勘定科目で絞って取引先別の行を取る。取引先名、金額、
   勘定科目が行ごとに返れば、それをそのまま使い、以降は飛ばす。

2. **集計値しか返らないことを検知する。** 返ってきたのが科目合計だけ — 「外注費：
   7,500,000円」で取引先の内訳がない — なら、この事業者では取引先別の取得ができない。
   エクスポートを依頼する：

   > 「会計ソフトからは科目ごとの合計しか取れませんでした。支払調書の一覧を作るには
   > 支払先ごとの明細が必要です。**取引先別の補助元帳**（または仕訳帳を外注費・支払手数料・
   > 支払報酬・地代家賃で絞ったもの）を、対象の暦年で CSV エクスポートしてここに
   > アップロードしてください。こちらで処理します。」

3. **CSV を処理する。** 列を対応付ける：支払先名、金額、日付、支払方法、勘定科目、
   マイナンバー・法人番号の収集状況。ここから先の集計とライン判定は、データの出どころに
   かかわらず同じ。

コネクタが後日取引先別の支払い一覧を直接返すようになれば、段階1が成功してフォールバックは
飛ばされる。スキルの変更は不要 — 「まず試す」の順序がそれを吸収する。

## freee会計 — 両モード

ツール名は出さず、概念で書く。

**納税見積モード。** 「試算表（損益計算書）」を期首から直近の締め済み月末までで取る。
売上高、費用合計、税引前当期純利益の三つ。「月次推移」で季節変動を見る。税区分の設定と
「消費税の申告区分」（本則・簡易・免税）は事業所設定から読める。

**法定調書モード。** 「取引（支出）」を勘定科目（外注費、支払手数料、支払報酬料金、
地代家賃）と暦年で絞り、「取引先」ごとに合計する。決済日（支払日）基準で年を割り当てる。
取引先マスタの「インボイス登録番号」の有無と、事業者区分（適格／免税）を収集状況の
シグナルにする。源泉徴収は取引の「源泉徴収」項目から拾える。

## 弥生会計 — 両モード（CSV 前提）

- **納税見積モード：** 残高試算表（損益計算書）の CSV を、期首から直近の締め済み月末までで
  エクスポートしてもらう。
- **法定調書モード：** 仕訳日記帳 CSV を暦年で、または補助元帳 CSV を外注費・支払手数料・
  支払報酬・地代家賃の科目で。取引先は摘要または補助科目から拾う — 表記揺れが多いので
  名寄せは人の確認に回す。

列名は「日付」「借方勘定科目」「借方補助科目」「借方金額」「貸方勘定科目」「摘要」など。
一致しなければ、ヘッダー行を見せて支払先名と金額の列を経営者に指定してもらう。

## PayPal — 法定調書モード

暦年に **「商品・サービス」として送金した支払い**（受け取りではない）をすべて取る。

主な項目：
- 受取人の名前／メールアドレス
- 受取人ごとの年間合計
- 取引種別 = 「支払い」または「ビジネス支払い」
- 日付

**除外：** 個人間送金（「友達や家族」）、返金、異議申立て、自社口座への振替。

**海外への支払いの注意：** 受取人が海外のフリーランスなら、非居住者への報酬として
源泉徴収（原則 20.42%）の論点がある。国内の支払先とは分けて一覧にし、税理士に
判断を委ねる。PayPal の決済手数料は支払手数料だが支払調書の対象外。

---

## Stripe — 法定調書モード

**外部アカウントへの送金**（Connect の連結アカウントへの transfer など、外注先への支払い）
があればすべて取る。自社の銀行口座への入金（payout）は対象外。

主な項目：
- 受取人の名前／ID
- 受取人ごとの年間送金合計
- 説明／メタデータ（役務提供の対価であることを確認する）

**除外：** 自社口座への payout。

**手数料の注意：** Stripe の決済手数料は支払手数料に計上されるが、支払調書の対象では
ない。インボイスの観点では Stripe からの請求書の登録番号を確認する。

---

## Square — 両モード

Square は決済サービスとして PayPal・Stripe と同格だが、このスキルが必要とするデータは
少ない。できないことを一行で言って、先に進む。

**納税見積モード：** 損益は会計ソフトから取り、Square からは取らない。Square の決済一覧
（全店舗 — `ListPayments` を `location_id` 無しで呼ぶと本店分しか返らない）は期間のカード
売上総額を返し、会計ソフトの売上高に店舗の抜けがないかの突合にだけ使う。損益の代わりに
しない。

**法定調書モード：** Square はコネクタ経由で外部への支払いを持たない — 入金は自社口座へ、
従業員の給与は給与計算ソフト側で、コネクタは届かない。支払調書候補には何も寄与しない。
黙って落とさず、情報源の節に名前を挙げてそう書く。

**手数料の注意：** Square の決済手数料は経費だが支払調書の対象外。売上側では、決済
サービス経由の受取総額が申告する売上高と整合するように、税理士向けに注記する。

## 法人カード明細（会計ソフトのカード連携）— 両モード

会計ソフトに連携したカード明細（マネーフォワードなら `getConnectedAccounts` で連携先を
確認し、`getTransactions` を期間指定で。`journalizing_statuses` で `none`（未仕訳）を絞れる）。

- **納税見積モード：** 未仕訳のカード利用は損益に載っていない費用。黙って混ぜず、
  「未仕訳の経費 ○○円は反映していない」と調整項目として名指しする。`start_date`〜
  `end_date` は 366 日以内。
- **法定調書モード：** カードで支払った外注費・デザイン料は支払先一覧の漏れ確認に使う。
  カード明細は突合用であって、真の情報源ではない。

**このスキルは何も書き込まない。** 読み取りのみ。

## Expensify — 両モード

**読み取り専用の検索。** 経費精算、個別の経費、領収書、請求書、出張、カテゴリ別合計、
承認状態。

- **納税見積モード：** カテゴリ別の経費合計で、費用側の裏付け。
- **領収書の有無は第一級のフィルタ。** 領収書が添付されていない経費を検索し、合計と件数を
  報告する。税理士が動くのはその行 — 領収書のない経費は、電子帳簿保存法と税務調査で
  否認され得る。
- Expensify は支払調書の一覧に使える支払先詳細を持たない。ここから一覧を作らない。

## 給与計算ソフト（CSV）— 法定調書モード

freee人事労務、マネーフォワード クラウド給与、SmartHR、ジョブカン などの給与台帳・
源泉徴収税額の CSV を暦年でエクスポートしてもらう。用途は二つ：

- 会計の預り金（源泉所得税）を **給与分と報酬分に分ける**。報酬分の徴収額と納付書の
  金額を突合するには、給与分を除く必要がある。
- 年末調整・源泉徴収票・給与支払報告書は `payroll-prep` の領域。ここでは扱わず、
  「給与側は給与計算準備で」と引き渡す。

**マイナンバー・生年月日・住所・口座番号を含む列は読んでも出力しない。**

---

## 海外製会計ソフト（Xero、Zoho Books、NetSuite など）— 両モード

国内の会計ソフトと同格に扱う。損益レポートが取れれば納税見積モードは同じ手順。取引先別の
支払い（請求書・経費）が取れれば法定調書モードも同じ手順で、支払日基準で年を割り当てる。

**できないこと：** 日本の源泉徴収区分、インボイス登録番号、マイナンバーの収集状況を
項目として持たないことが多い。「❓ 不明」から始め、経営者に聞く。レポート機能が無く
請求書・経費の一覧から組み立てる場合は、「請求書ベースの集計であって試算表ではない」と
出力に書き、税理士に基準を確認してもらう。

## CSV フォールバック

コネクタが使えなければ、経営者に次を依頼する：
1. 会計ソフトから残高試算表（損益計算書）を CSV でエクスポート（freee会計：レポート →
   試算表 → エクスポート、マネーフォワード クラウド会計：会計帳簿 → 残高試算表 →
   エクスポート、弥生会計：集計 → 残高試算表 → 書き出し。法定調書モードでは、取引先別の
   補助元帳、または外注費・支払手数料・支払報酬・地代家賃で絞った仕訳帳）
2. PayPal の取引履歴をエクスポート（アクティビティ → ダウンロード → CSV）
3. Stripe の送金レポートをエクスポート（ダッシュボード → 送金 → エクスポート）

アップロードされた CSV を読むときは、次の列を探す（名前はエクスポート元で異なる）：
- 試算表：`勘定科目`、`借方金額`／`貸方金額`、`残高`、`科目区分`（収益／費用）
- PayPal：`名前`、`タイプ`、`金額`、`日付`、`取引 ID`
- Stripe：`Description`、`Amount`、`Created date`、`Status`

列が一致しなければ、支払先名と金額の列を経営者に指定してもらう。
