# 内定通知書を DocuSign に回す

フェーズ6のみ。経営者がフェーズ1で DocuSign を選んだときだけ行う。

Claude in Chrome で DocuSign の画面を操作するので、経営者が手で DocuSign を触る必要は
ない。クラウドサイン・GMOサインを `build-connector` で接続している事業者も、以下の
ルール（下書き保存 → 経営者の確認 → 送信）は同じだ。

---

## 絶対のルール

**封筒は下書きとして保存し、決して送信しない。** 経営者が封筒を確認し、送りたいと明示的に
言うまで、フェーズ6は「下書きとして保存」から先に進まない。経営者が読む前に内定通知書が
候補者に届いてしまったら、取り返しがつかない。

もう一つ。**労働条件通知書の電子交付は候補者本人が希望した場合に限る**（労基法施行規則
5 条）。本人の希望を確認していなければ、封筒は作らず、書面（印刷して郵送・手渡し）が既定
だと伝える。

---

## API ではなくブラウザを使う理由

DocuSign の API は、アカウントにすでにあるテンプレートか、認証なしで取得できる URL から
しか文書を受け付けない。ファイルのアップロードはできない。内定通知書には氏名と賃金が
書かれているので、コネクタの都合で公開アドレスに置くことは、どんな理由でも選択肢に
ならない。

ブラウザの流れならこれを回避できる：ファイルは経営者自身のログイン済みセッションから
アップロードされ、何も公開されない。だからこのフェーズは画面操作として書いてある。

---

## ブラウザの流れ

1. `https://app.docusign.com` を開く。経営者はすでにログインしているはずだ。ログイン
   画面が出たら止まり、ログインを依頼してから続ける。
2. **Start**、次に **Send an Envelope** をクリックする。UI のバージョンによっては
   **New** や **Use a Template** という表示のこともある。
3. **内定通知書をアップロードする。** 「Upload Documents」をクリックし、フェーズ5で作った
   `[職種]-内定通知書.docx` をアップロードする。
4. **署名者を追加する。** Recipients で候補者を役割「Signer」の署名者として追加する。
   候補者の氏名とメールアドレスがまだなければ聞く。
5. **送信者を CC に追加する** — 経営者が控えを望むなら。不明なら聞く。
6. **件名を設定する：** `採用内定のご通知 — [職種名]（[会社名]）`
7. **メッセージを添える。** 候補者の氏名に「様」を付け、丁寧語で二行：内定をお伝えできて
   嬉しいこと、ご都合のよいときに内容を確認のうえ署名いただきたいこと、質問は歓迎する
   こと。
8. **署名欄を配置する。** 文書の末尾にある内定承諾書の署名行に Signature フィールドと
   Date Signed フィールドを置く。
9. **下書きとして保存する。** 送信しない。

そのうえで下書きのリンクを渡し、署名欄の位置を確認して、送る準備ができたらここで
そう伝えてほしいと経営者に頼む。

---

## 代替経路

DocuSign が使えない、またはブラウザの流れがどこかで失敗したら、接続済みのメール
コネクタ（Gmail または Microsoft 365）で、内定通知書を添付し「DocuSign に手動で
アップロードしてください」と添えたメールを下書きする。

**送る前に下書きを経営者に見せる。** 代替経路は承認の基準を下げない。同じゲートに別の
道で着くだけだ。

どちらの経路も動かなければ、ディスク上の `.docx` が完成した成果物だ。回付はできなかったと
伝えてファイルを渡す。
