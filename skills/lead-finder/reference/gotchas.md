# 落とし穴

誰も電話しないリスト、あるいはもっと悪く、経営者に損害を与えるリストができる失敗パターン。

---

## 落とし穴: 経営者に理想顧客像を語らせる

**なぜ重要か:** 経営者は「売りたい相手」を語る。データは「実際に払っている相手」を語る。この二つは重要なところで違い、そのギャップこそがたいてい洞察のすべてだ。

### 悪い例

```
Claude: 「理想のお客さんはどんな会社ですか？」
経営者: 「中堅の法人、というか品質を分かってくれるところなら誰でも。」
```

これでは使えるフィルタが一つもない検索になる。

### 良い例

```
Claude: [会計ソフトから顧客 340 社を読み、価値で並べ、四分位を比較]
        「上位のお客さんは、管理棟数 3〜15 棟の商業ビル管理会社で、30 km
        圏内、紹介で来た会社です。下位は検索広告から来た戸建ての緊急修理
        です。合っていますか？」
経営者: 「合ってる — ただ、15 棟を超えると大手のビルメンテナンス会社に行く。」
```

経営者の仕事はプロフィールを修正することであって、発明することではない。

---

## 落とし穴: 500 行のリスト

**なぜ重要か:** 巨大なリストは、選別の仕事を経営者に押し戻す。それは経営者が手放したかった仕事だ。開いて、どこから始めればいいか分からず、二度と開かない。

### 悪い例

50 km 圏内の同業種の会社を全部かき集める。512 行を納品する。

### 良い例

40〜60 行、それぞれに電話する理由を付け、点数順に並べる。何を除外し、なぜかを言う:

```
47 社が基準を満たし、他に 61 社が見つかったが適合が弱く除外。
```

---

## 落とし穴: 捏造したメールアドレス

**なぜ重要か:** このスキルで最も損害の大きい失敗だ。推測したアドレスに一斉送信すると、経営者の送信ドメインが迷惑メール扱いになる。本物の顧客メールが何か月も傷つき、経営者はそれを 6 週間前の見込み客リストと結びつけられない。特定電子メール法の例外（名刺交換、取引関係、Web 公開のアドレス）にも当たらない。

### 悪い例

```
連絡先: tanaka@omiya-bm.example.jp
```

命名パターンから組み立てたものを事実として出している。

### 良い例

```
担当者: 田中 美咲 様（施設管理部長）
ルート:   tanaka@omiya-bm.example.jp
確度:     推定 — この会社の他の 2 アドレスのパターンから当てはめたもので、
          未確認
```

下流の営業メールのステップは推定アドレスの扱いを変える。それができるのは、確度が正直に書かれているときだけだ。

---

## 落とし穴: 創作した購買シグナル

**なぜ重要か:** 経営者はそのシグナルで電話を切り出す。間違っていれば電話はその場で終わり、リストの全行を信用しなくなる。

### 悪い例

```
今すぐの理由: 業界の動向から見て拡大中と思われる
```

これは事実の衣装を着た推測だ。

### 良い例

```
今すぐの理由: 3月14日に 7 棟目（大宮西口ビル）の管理受託を自社サイトで公表
```

あるいは、正直に:

```
今すぐの理由: 特定のきっかけなし — 適合度は高い、冷たいアプローチ
```

シグナルのない行は問題ない。架空のシグナルがある行は問題だ。

---

## 落とし穴: 承認なしで CRM に書き込む

**なぜ重要か:** 会社 47 件と担当者 39 件を稼働中の CRM に一括登録すると、経営者が望んでいなければ戻すのに何時間もかかる。経営者が押せる「元に戻す」ボタンはない。

### 悪い例

レコードを作ってから、報告する。

### 良い例

何が作られるかを、タグと「既存は何も変わらない」という確認を含めて正確に述べる。「はい」を待つ。

---

## 落とし穴: 廃業した会社が載っている

**なぜ重要か:** 名簿は古くなる。3 回続けて不通なら、4〜47 行目がどれだけ良くても経営者はリストを見捨てる。

### 悪い例

団体の会員名簿を額面どおりに受け取る。

### 良い例

リストに載せる前に、各社がまだ存在し、営業中に見えることを確認する（Web サイト、法人番号公表サイトの閉鎖・合併履歴、Google マップの営業状況）。短時間で済み、最初の 10 行 — 信頼を得るチャンスのある唯一の行 — を守る。

---

## 落とし穴: Apollo がないことを障害と扱う

**なぜ重要か:** この規模の経営者の大半はデータ提供サービスを接続していないし、今後もしない。それなしでスキルが止まるなら、対象の大多数に対して機能しない。

### 悪い例

```
「見込み客リストを作るには Apollo の接続が必要です。」
```

### 良い例

```
「Apollo は未接続なので、公開情報から作ります — 建築計画のお知らせ、
不動産協会の会員名簿、口コミサイト、求人媒体です。データ提供サービスより
短いリストになりますが、1 行ずつ私が実際に確認した会社だけになります。」
```

Web から作ったリストは 1 行あたりの質がむしろ高いことが多い。道を詫びるのではなく、それを率直に言う。
