# 落とし穴

実際のリードや評判を失う失敗パターン。このスキルは速く、無人で動くので、誰かが気づく前に間違いが相手に届く。

---

## 落とし穴：定型の受付通知

**なぜ重要か：** 「お問い合わせありがとうございます。担当よりご連絡いたします」は、見込み客がすでに予想していたものだ。何の得にもならず、本物の答えが案件を取れたはずの一瞬を無駄にする。

### 悪い例

```
田中様
お問い合わせありがとうございます。内容を確認のうえ、担当者より追って
ご連絡いたします。
```

### 良い例

```
田中様
はい、複数棟をまとめて一つの保守契約でお受けしており、6 棟は十分に
対応できる規模です。
現地の確認に、木曜の午前中か金曜の 13 時以降に伺えます。ご都合は
いかがでしょうか。
```

相手が聞いた質問に答える。違いはそれだけだ。

## 落とし穴：空いていないカレンダー枠の提示

**なぜ重要か：** 見込み客が木曜を選び、経営者はすでに予定が入っていて、二度目のやり取りと謝罪が発生する — 速い返信が強みになるはずだったまさにその瞬間に。

### 悪い例

カレンダーを読まずに、もっともらしい日時を提案する。

### 良い例

実際のカレンダー（JST）を読む。営業時間と現場間の移動時間を尊重する。カレンダーが接続されていなければ、枠を作り出さずに相手の都合を聞く。

---

## 落とし穴：人の返信の下に重ねて返信する

**なぜ重要か：** 同僚が 20 分前に返信した。その下に自動の返信が届くと、見込み客には雑然として見え、実際に対応した人の立場を損なう。

### 悪い例

スキル自身の記録で未返信のものすべてに返信する。

### 良い例

スレッドを確認する。社内の誰かがすでに返信していれば、そのままにして、ダイジェストに記す。

---

## 落とし穴：対象外の問い合わせを無視する

**なぜ重要か：** 沈黙は無視と受け取られ、狭い市場では「誰も返事をくれなかった」という口コミを生む。30 秒の正直な返信は、代わりに紹介を生む。

### 悪い例

対象外に仕分けて、何も送らない。

### 良い例

```
率直に申し上げますと、業務用厨房の冷凍冷蔵設備は当社の資格の範囲外です。
この分野は大宮冷凍設備さんが得意です。担当の寺田さんに、岡本からの紹介
とお伝えください。
```

経営者からは、ここから紹介の流れが戻ってくるという報告が絶えない。

---

## 落とし穴：価格を下書きに書く

**なぜ重要か：** 経営者の名前のメールに書かれた数字は、見込み客がそれを根拠に迫ってくる約束になる。価格は、モデルには見えないもの — 点検口へのアクセス、機器の年式、作業員が現場で見つけるもの — に左右される。

### 悪い例

```
6 棟の保守契約ですと、月額 15万円前後（税抜）になります。
```

### 良い例

```
費用については率直に申し上げると、機器の年式と点検口へのアクセスに
よりますが、この規模であれば棟ごとの個別契約より安くなるのが通常です。
```

方向性を示す。数字は出さない。価格を書いた下書きにはダイジェストでフラグが付き、経営者が承認前に見る。

## 落とし穴：経営者が「もう送っちゃっていいよ」と言ったから送る

**なぜ重要か：** 修正なしで 30 通の下書きを承認した経営者が、もう聞くなと言うのは当然だ。それでも経営者の名前の返信は経営者の判断であり、下書きが間違っている一回こそ、経営者が見る必要があった一回だ。このスキルに自動送信モードはなく、「これからは送っちゃっていい」がそれを作ることもない。

### 悪い例

「簡単なものは送っちゃっていい」を恒久的な許可と受け取り、下書きの提示をやめる。

### 良い例

代わりにできることを一行で言い、一括分の提示を続ける：

```
私から送ることはしていません — 返信は一通残らず、あなたの「送って」を
待ちます。夜間の分は朝 7 時までに下書きと仕分けを済ませて一括で一回の
操作にしておきますし、急ぎの案件が届いた瞬間に Slack でお知らせします。
```

ダイジェストでの一括承認が速さのレバーだ。見ずに送ることではない。

---

## 落とし穴：夜間のフォームのループ

**なぜ重要か：** 壊れた Web フォームやボットは、数十件の送信を生む。経営者のドメインから 1 時間に 32 通の返信が出ると送信元の評判が壊れ、その後数か月、本物の顧客宛てのメールにまで響く。

### 悪い例

32 件すべてを処理し、32 通すべてを送る。

### 良い例

```
夜間に 32 件、普段の 6 倍で、19 件はほぼ同一です。フォームのループか
ボットのようです。まだどれにも返信していません — 本物に見える 3 件を
送りましょうか？
```

件数の異常は、どのモードでも必ず止まって聞く。

---

## 落とし穴：売り込みを問い合わせとして扱う

**なぜ重要か：** 問い合わせフォームには、自称「Web 制作会社」「SEO 業者」「助成金コンサル」からの営業メールも届く。これに丁寧な返信を下書きすると、経営者の承認の手間を増やし、返信すれば相手のリストで「反応あり」になって売り込みが増える。

### 悪い例

「ホームページのリニューアルをご提案します」を「不明」に仕分けて、「一点確認させてください」と下書きする。

### 良い例

本文に具体的な依頼内容（場所、建物、設備、時期）がなく、自社サービスの売り込みだけなら、下書きせずに保留に列挙する。迷惑メール扱いにするかは経営者が決める。判断に迷えば、返信ではなく保留にして経営者に見せる。

---

## 落とし穴：親しさの捏造

**なぜ重要か：** 誰も見ていないのに「ローズウッド不動産様のご活躍を拝見しております」と書くのは、テンプレートと同じ見抜かれ方をする。即時の返信ではなお悪い。そのタイミングでは誰も見られたはずがないと分かるからだ。

### 悪い例

```
以前よりローズウッド不動産様のお取り組みを拝見しており、大変感銘を
受けております。
```

### 良い例

相手が問い合わせに実際に書いたことだけを参照する。感心させるのは速さだ。飾りはいらない。

---

## 落とし穴：ホットな案件を埋もれさせる

**なぜ重要か：** ダイジェストは経営者を動かすために存在する。7 件の時系列の一覧で 4 番目に載ったホットな案件は、昼まで待たされるホットな案件だ。

### 悪い例

問い合わせを届いた順に並べる。

### 良い例

ホットが常に先頭、指示を一つ添えて。それ以外はそのあとに。
