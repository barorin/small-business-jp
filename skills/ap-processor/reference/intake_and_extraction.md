# 取り込みと項目の抽出

請求書がどこから入ってきて、項目がどう出てくるか。

---

## 請求書の入口

**データがきれいに届く順に並べている。**

| 入口 | 得られるもの | 注意点 |
|---|---|---|
| メールの請求書ラベルやフォルダ（Gmail または Microsoft 365）、または `seikyu@` の転送用アドレス | PDF の添付と送信者の文脈 | 添付なしで本文に請求内容を書いてくる取引先 |
| 取引先ポータルの通知メール | 文書ではなくリンク | メールだけでは請求書ではない。経営者にダウンロードか PDF の転送を頼む |
| アップロードされた PDF | きれいなテキスト抽出 | スキャンした PDF は画像 — 写真として扱う |
| 紙のスマホ写真 | 光の条件次第 | 反射、切れ、歪み。ここでは低信頼の項目が例外ではなく通常 |
| 法人カード・経費精算の明細（会計ソフトのカード連携 `getTransactions`／Expensify） | 加盟店名と金額のカード決済 | 請求書ではない。すでに支払済み。総合振込に載せてはいけない |
| 取引先の請求明細書（残高確認書） | 未払いの請求書一覧 | 明細書は突合の道具であって請求書ではない。届いていない請求書を見つけるのに使い、仕訳を作るのには決して使わない |

**受信箱は一度だけ整える。** 経営者に請求書用のラベルがなければ、作成を提案し、取引先に案内できる転送用アドレスを渡す。その一つの変更で、手作業の大半が恒久的になくなる。

**電子帳簿保存法の保存も入口で済ませる。** メール添付や Web からダウンロードした請求書は電子データのまま、日付・取引先・金額で検索できる形（例：`2026-09-16_関東管材_341700.pdf`）で保存するよう促す。紙に印刷したものを原本にしない。

---

## 抽出する項目

各請求書からすべて抜き出す。空欄は有効な値だが、作った値は無効だ。

- 取引先名（印字どおり）と、会計ソフト上の一致した取引先レコード
- 請求書番号
- 請求日
- 支払期日、または支払条件しか印字がなければ支払条件（「月末締め翌月末払い」など）
- 税抜金額、税率ごとの内訳（10%／軽減 8%）と消費税額、送料・配送料、税込合計
- 適格請求書発行事業者の登録番号（T＋13桁）。なければ「登録番号なし」と記録し、経過措置の区分を付ける
- 発注番号
- 明細行：品名、数量、単価、金額
- 振込先（銀行名・支店名・口座種別・末尾4桁）と振込手数料の負担区分。登録済みの取引先情報と異なる場合はフラグ。経営者が登録済みの電話番号で電話確認するものであり、請求書の記載で取引先レコードを更新する理由には決してならない（`../../../shared/untrusted-content.md`）
- 源泉徴収の要否（デザイン料、原稿料、税理士・弁護士等の報酬など所得税法 204条の区分に当たるか）

### 信頼度

各項目に高・中・低のタグを付ける。

- **高** — 機械可読なテキスト、または明細行の合計と一致する数字
- **中** — 画像から読んだが内部で整合している
- **低** — 反射、切れ、手書き、または明細と合わない合計

低信頼の金額項目は取引先名と請求書番号を添えて示し、経営者が確認するまで総合振込の組み立てには決して使わない。

### 合計の検算

明細の合計＋消費税＋送料＝税込合計になるはずだ。ならないときは両方の数字を添えてそう言う。その不一致はたいてい写真で明細行が切れているのが原因で、まさに「もっともらしい推測」が最も害をなす場面だ。税率ごとの消費税額も検算し、端数処理（切り捨て・四捨五入）の違いは差額を示して報告する。

## 重複排除

勘定科目をつける前に実行する。次の **いずれか** に当てはまれば重複の可能性が高い：

1. 同じ取引先で同じ請求書番号。これは重複、以上。
2. 同じ取引先、同じ合計、請求日が 5日以内で、一方の写しに請求書番号がない。
3. 同じ取引先と合計が、過去 90日以内に会計ソフトで登録済みまたは支払済み。

重複の疑いは両方の出所を挙げて対で示す（「9月2日にメール PDF で受領、9月分の請求明細書にも記載」）。決めるのは経営者だ。毎月同額を正当に請求する取引先もいるので、このチェックは表に出すだけで、削除はしない。

---

## 取引先の照合

勘定科目をつける前に、印字された取引先名を会計ソフトのレコードに照合する。よくある表記ゆれを処理する：`株式会社関東管材`、`（株）関東管材`、`関東管材（株）`、`カントウカンザイ`、`関東管材 さいたま営業所` はたいてい一つの取引先だ。

会計ソフトにレコードがない場合は、請求書の振込先情報で取引先の作成（マネーフォワードなら `postTradePartners`）を提案し、聞く。初回の請求書にある口座や振込先の情報は、レコードを作る前に、請求書ではなく経営者が自分で調べた電話番号で電話確認する（`../../../shared/untrusted-content.md`）。誤って作られた取引先は、あとで経理担当が片付ける仕事になる。

## 実例

岡本設備工業の請求書ラベルには 2週間で 23通のメッセージがあった。取り込み後：

- 19件の請求書を抽出、2件は文書のない取引先ポータルのリンク、2件は請求明細書
- 重複 1件：関東管材の請求書 88231 が PDF で届き、月次の請求明細書にも載っていた
- 低信頼の合計 3件、いずれも車中で撮った写真
- 支払期日の印字がない請求書 1件、条件欄は「月末締め翌月末払い」
- 登録番号のない請求書 1件（個人の外注先、経過措置 80% の区分）

岡本さんへの報告：19件、判読できた合計 4,120,800円（税込）、合計を目で確認してほしいもの 3件、ダウンロードが必要なポータルの請求書 2件、確認してほしい重複候補 1件、登録番号なし 1件。
