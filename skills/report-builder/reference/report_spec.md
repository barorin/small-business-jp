# レポート仕様の形式

すべてのレポートは、データを引く前にこの構造に落とす。保存されるのはこの仕様で、レポートを繰り返し使えるようにするのもこの仕様だ。

---

## 形式

```
レポート名:   <短く、経営者が見て分かる名前>
頻度:         単発 | 週次 | 月次 | 四半期
期間:         <各実行が対象にする窓>
比較:         <前期 | 前年同期 | 目標 | なし>
集計軸:       <軸、またはなし>

指標:
  <名前>  =  <計算式>  [ソース]
  <名前>  =  <計算式>  [ソース]

ソース:       <使うコネクタ、または「アップロードしたファイル」>
メモ:         <経営者が明確にしたことすべて>
```

---

## 記入例1 — 定番

**経営者の言葉:** 「毎週月曜に: 店舗別の売上を前年比で、売掛金の滞留、人件費率。」

```
レポート名:   月曜の経営パック
頻度:         週次、月曜
期間:         直近7日
比較:         前年の同じ7日
集計軸:       店舗

指標:
  売上          =  売上高の合計（税抜）                           [マネーフォワード クラウド会計]
  売掛金の滞留  =  未入金の請求書を期日超過 0-30 / 31-60 / 61日超で区分   [請求書 CSV（マネーフォワード クラウド請求書）]
  人件費率      =  人件費（給料手当＋法定福利費＋雑給）/ 売上高    [マネーフォワード クラウド会計]

ソース:       マネーフォワード クラウド会計、請求書 CSV
メモ:         人件費率は総費用ではなく売上高に対する比率（確認済み）。
              売掛金の滞留は会社全体で、店舗別には分けない。
              店舗別は推移表が常に全部門合計のため、仕訳を部門で集計する。
```

何を推測し、何を聞いたかに注目する。指標、集計軸、比較はその一文からそのまま取れた。人件費率の分母と、滞留の集計軸だけが質問を要した。

## 記入例2 — コネクタなし

**経営者の言葉:** 「どの工事種別が一番儲かっているか、毎月見えるレポートが欲しい。」

```
レポート名:   月次 工事種別 採算
頻度:         月次、第1営業日
期間:         前暦月
比較:         前月
集計軸:       工事種別（空調設置 / 給排水 / 保守点検）

指標:
  売上      =  工事種別ごとの請求金額の合計（税抜）     [アップロードした売上 CSV]
  件数      =  工事種別ごとの完了件数                   [アップロードした売上 CSV]
  粗利率    =  (売上 - 原価) / 売上                     [アップロードした売上 CSV]

ソース:       アップロードしたファイル — 月次の売上エクスポート
メモ:         エクスポートに原価列が必要。なければ売上と件数だけを
              報告し、粗利率は算出不可と言う。
```

コネクタなしの経路でも、まったく同じ形の仕様になる。データ自体が欠けている箇所以外、レポートは何も劣化しない。

## 記入例3 — パイプライン、複数ソース

**経営者の言葉:** 「パイプラインがどれだけ成約につながっていて、実際いくらの価値があるのか、毎月見せて。」

```
レポート名:   月次 パイプライン転換
頻度:         月次
期間:         前暦月
比較:         前月
集計軸:       商談ステージ

指標:
  新規商談        =  期間内に作成された商談の件数              [HubSpot]
  成約            =  期間内に成約（closed-won）した商談の件数  [HubSpot]
  成約率          =  成約 / 決着した商談                       [HubSpot]
  加重パイプライン =  (商談金額 x ステージ確度) の合計           [HubSpot]
  実現した売上    =  期間内に入金された請求書の合計            [マネーフォワード クラウド会計]

ソース:       HubSpot、マネーフォワード クラウド会計
メモ:         実現した売上は意図的に CRM ではなく帳簿から取る。
              CRM の商談金額は予測で、請求書は事実。
```

---

## 仕様を正直に保つルール

**すべての指標にソースを書く。** ソースのない指標は、来月誰も再現できない指標だ。

**計算式は省略せず書き出す。** 「人件費率」だけでは何も意味しない。「人件費を売上高で割る」なら検算できる。

**曖昧さは黙って解決せず、メモに記録する。** 経営者が何かを明確にしたら、その言葉を書き留める。半年後、その数字がなぜその計算になっているかの唯一の記録がそのメモだ。

**一つのレポート、一つの目的。** 経営者が無関係な指標を八つ挙げたら、それはたぶん二つのレポートだ。読めない一つのパックを作るより、分割を提案する。
