# 落とし穴

正しく見えて、静かに間違っているレポートを生む失敗のパターン。危険なのはこれらだ — 経営者はこのレポートを金融機関、経営会議、顧問税理士に転送する。

---

## 落とし穴: 途中期間を丸ごとの期間と比べる

**なぜ重要か:** 7月27日の時点で、月初来の売上を前月の丸ごとと比べると 20% の急落に見える。実際は違う。経営者はこの誤りで人員配置を決めてきた。

### 悪い例

```
売上 — 9,870,000円、6月比 -19%
```

6月は丸ごと一か月。7月はまだ 3日足りない。この比較は無意味で、経営者は危機と読む。

### 良い例

```
売上 — 9,870,000円、7月27日までの月初来
        （6月の 27日まで: 9,140,000円、+8%）
```

同じデータ、正直な比較、正反対の結論。

## 落とし穴: 同じ売上を二回数える

**なぜ重要か:** Stripe で決済され、会計ソフトに計上された Shopify の注文は三つのシステムに存在する。接続済みのソースをまたいで合算すると売上が膨らむ。ときに二倍以上に。

### 悪い例

```
会計ソフト + Shopify + Stripe から売上を引き、三つを合算する。
レポートは 38,700,000円。実際の売上は 12,900,000円だった。
```

### 良い例

```
売上のソースを一つ決める。どれかを言う:

売上 — 12,900,000円（ソース: マネーフォワード クラウド会計。Shopify と Stripe は
        出荷と手数料の明細にのみ使用）
```

目安: 帳簿が接続されていれば、売上のソースは帳簿。決済サービスは手数料と入金タイミング。ネットショップ・POS は商品別の内訳。

## 落とし穴: グループがゼロと出ずに消える

**なぜ重要か:** 三宮店が今週何も売らず、行が消えると、経営者はデータが壊れたと思って探しに行く。ゼロは情報で、欠けた行はノイズだ。会計ソフトの試算表は全項目 0 の科目を返さない（`../../../shared/ledger-report-traps.md` 罠8）ので、ゼロの行は自分で補う。

### 悪い例

```
店舗別売上:
  元町店     1,820,000円
  御影店     1,900,000円
```

三宮店は先週あった。どこへ行った？

### 良い例

```
店舗別売上:
  元町店     1,820,000円
  御影店     1,900,000円
  三宮店             0円   （今期の売上計上なし）
```

## 落とし穴: 集計行が合計と合わない

**なぜ重要か:** 列を足して違う数字になった経営者は、その後に出すすべてのレポートを信用しなくなる。

### 悪い例

合計と内訳を、一致の確認なしに出す。

### 良い例

届ける前に合計を確認する。本当に合わないなら、理由を言う:

```
班別売上の合計は 3,110,000円。売上合計は 3,240,000円。
差の 130,000円は、部門が未設定の仕訳です。
```

差を名指しするほうが、隠すより信頼を得る。

## 落とし穴: 保存済みレポートについて再び聞き取る

**なぜ重要か:** このスキルの約束はまるごと「一度だけ説明する」だ。毎月同じ五つの質問をすれば約束は破れ、経営者は使わなくなる。

### 悪い例

```
経営者: 「月曜のレポートを回して。」
Claude: 「承知しました — どの指標にしますか？ 期間はどうしましょう？」
```

### 良い例

```
経営者: 「月曜のレポートを回して。」
Claude: [saved_reports.md を読み、見つけ、実行する]
        「月曜の経営パック — 7月20日の週…」
```

必ず `saved_reports.md` を先に読む。

## 落とし穴: 欠けた数字にもっともらしい数字を入れる

**なぜ重要か:** このスキルで最も深刻な失敗だ。レポートは経営者が行動し、転送する文書だ。もっともらしく見える創作の数字は、誰かが気づくまでに何人もの手を渡る。

### 悪い例

```
人件費率 — 売上のおよそ 30%
```

どこから来た？ どこからでもない。給与関連の科目は返ってこなかった。

### 良い例

```
人件費率 — n/a（今回の実行では会計ソフトの給与関連科目を取得できませんでした）
```

推定しない。推測の方向に丸めない。前期の数字を黙って持ち越さない。

---

## 落とし穴: 表から始める

**なぜ重要か:** 経営者がレポートを頼むのは判断のためだ。数字の壁は分析を経営者に投げ返す。それこそ経営者が手放そうとした仕事だ。

### 悪い例

40 行の表で始め、その下にサマリー。

### 良い例

重要な一文、見出しの指標三つ、所見三つで始める。残りはすべてワークブックへ。

## 日本の実務とコネクタの癖で加わる落とし穴

以下は短く書く。詳細は各行の参照先にある。

### 絞り込んだ呼び出しの summary を帳簿全体として読む

**なぜ重要か:** 滞留一覧を上位 10 件に絞ると、レスポンスの `summary` は返ってきた 10 件だけで計算される。「一部です」とはどこにも書いていない（`../../../shared/ledger-report-traps.md` 罠1）。

```
悪い: 売掛金合計 — 3,700,000円、91日超の滞留なし   （上位10件の summary をそのまま引用）
良い: 売掛金合計 — 5,300,000円（貸借対照表の売掛金の行）。滞留の上位は上位10件のみ
```

合計は帳簿全体を返す呼び出しから、順位は絞った一覧から。両方に出所を書く。

### 分母が違う世界から来る

**なぜ重要か:** 会計ソフトの全社売上は、Shopify にしか届かない広告の分母にならない。ひかり珈琲焙煎所の四半期売上 1億4,000万円のうち EC は 340万円 — 2.4% だ（`../../../shared/chain-seams.md`「二つのスキル、二つの世界、一つの数字」）。

```
悪い: 広告費の回収率（ROAS） — 194倍   （全社売上 ÷ 広告費）
良い: EC 売上 — 3,400,000円（四半期売上 140,000,000円のうち）。ROAS — 4.7倍（EC 売上に対して）
```

比率はそのチャネルが実際に届く母数で計算し、出力は両方の数字を名指しする。

### 税込と税抜が混ざる

**なぜ重要か:** 会計ソフトの試算表は経理方式によって税抜、Shopify や Square の売上は税込で返る。並べて前年比を取ると、10% の税率ぶんが「成長」に化ける。

```
悪い: 売上 — 10,900,000円、前年同月比 +9%   （今年は Square の税込、前年は試算表の税抜）
良い: 売上 — 9,910,000円（税抜）、前年同月比 -1%
```

すべての金額を税抜（または税込）に揃え、表記に「（税抜）」を添える。マネーフォワードの `include_tax` は経理方式が「税抜(内税)」のときしか効かない（`../../../shared/ledger-report-traps.md` 罠9）。渡したパラメータではなく、返ってきた数字で判断する。

### 四半期と年度を暦で切る

**なぜ重要か:** 3月決算の事業の「第2四半期」は 7〜9月であって、暦の 4〜6月ではない。「年度累計」も 4月起点だ。暦で切ると、経営者や顧問税理士の手元の数字と一致しない。

```
悪い: 第2四半期（4〜6月）の売上 — 40,200,000円
良い: 第2四半期（7〜9月、3月決算基準）の売上 — 43,800,000円
```

決算月は `getTermSettings`（マネーフォワード）か事業コンテキストの `決算月` から一度解決し、実行中は使い回す。個人事業主は暦年（1〜12月）固定。期間のラベルに、どちらの基準かを必ず書く。

### 前年同月比の暦のズレと祝日

**なぜ重要か:** 同じ月でも、土日の並び、祝日、ゴールデンウィーク・お盆・年末年始の休業で営業日数が 1〜2日違う。店舗や工事の売上は営業日数にほぼ比例するので、-5% の大半が暦のせいということがある。

```
悪い: 売上 — 13,300,000円、前年同月比 -5%
良い: 売上 — 13,300,000円、前年同月比 -5%（営業日数 20日 vs 21日。営業日あたりでは -0.3%、ほぼ横ばい）
```

営業日数を併記するか、営業日あたりで補正する。週次レポートでは祝日を含む週にそう書く。

### Shopify の `createdAt` を注文日として使う

**なぜ重要か:** 他システムから移行した注文や API 経由で登録した注文は、`createdAt` が Shopify に登録された日になる。実際の注文日は `processedAt` だ。移行した月に過去の注文が積み上がり、その月の売上が跳ね、前後の月がへこむ。

```
悪い: 2026年3月の EC 売上 — 4,100,000円   （移行した 14か月分の注文が 3月に入っている）
良い: 2026年3月の EC 売上 — 320,000円（processedAt で期間を絞った）
```

期間の絞り込みは常に `processedAt`。`createdAt` と大きく食い違う注文があれば、移行やインポートがあったと一行で言う。
