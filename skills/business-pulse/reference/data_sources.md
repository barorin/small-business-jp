# データソース

パルスの各セクションと、それを生む MCP ツールの正確な対応。**すべての呼び出しを一つの並列バッチで出す** — 直列で引かない。

## お金（会計ソフト）

接続されている会計ソフトがこのセクションを支える — freee会計、マネーフォワード クラウド会計、弥生会計（CSV）。同格だ（`../../../shared/connector-neutrality.md`）。マネーフォワードの表が先頭にあるのは、実在するツール名で書けて最も長いからにすぎない。freee会計と弥生会計の表は同じ指標を対応させている。金額は円（`../../../shared/currency-and-locale.md`）。しきい値も円。海外製の会計ソフト（Xero、Zoho Books、NetSuite など）を使う事業者も同格に扱い、同じ指標をそのコネクタが返す範囲で読み、返さないものはエクスポートを求める。

### マネーフォワード クラウド会計

| 指標 | ツール | 備考 |
|---|---|---|
| 事業者名・会計期間 | `currentOffice` / `getTermSettings` | 最初に呼ぶ。事業者名の確認（`../../../shared/tenant-scope.md`）と、「今月」「年度累計」の基準になる決算月 |
| 現預金残高 | `getReportsTrialBalanceBalanceSheet` | 現金・預金科目の `closing_balance` を合計。前週比は `end_date` を一週間前にしたもう一回の呼び出しから取る。全項目 0 の科目は返らない — 返らない＝ゼロ |
| 月初来売上 | `getReportsTransitionProfitLoss`（`fiscal_year`＋月） | 当月 vs 前月。売上高・費用は明細行から読む。`ratio` が `null` なら「算出不能」。税込／税抜は経理方式から判断して明記（`../../../shared/ledger-report-traps.md` 罠9） |
| 売掛金残高 | `getReportsTrialBalanceBalanceSheet`（`with_sub_accounts: true`） | 売掛金の補助科目＝取引先別残高。科目の行（合計）と補助科目の行（内訳）を足さない |
| 売掛金の滞留・期日超過 | マネーフォワード クラウド請求書、または請求書 CSV | 期日別の滞留レポートは会計側にない。請求書単位の期日から 0〜30、31〜60、61日超に区分し、顧客名＋金額＋超過日数を名指し |
| 未仕訳の明細 | `getTransactions`（`journalizing_statuses: none`） | `start_date`〜`end_date` は 366日以内。件数と金額。多いほど上の数字は暫定値（罠12） |

**会計ソフトの状態の扱い**: 現預金の読み取りがエラー、空のレスポンス、「未接続」状態を返したら、お金のセクション全体を「n/a — 会計ソフト（名指し）が利用不可」として先へ進む。再試行しない。ただし試算表で科目が返らないのはゼロであって、エラーではない。

### freee会計

| 指標 | ツール | 備考 |
|---|---|---|
| 現預金残高 | 試算表（貸借対照表） | マネーフォワードの現預金の読み取りと同じ役割 |
| 月初来売上、損益の推移 | 月次推移 | 当月 vs 前月 |
| 未入金、滞留、期日超過 | 請求書（未入金で絞る） | 顧客名＋金額＋超過日数を名指し |
| 未仕訳の明細 | 明細（未処理の明細） | マネーフォワードの `none` と同じ位置づけ |

### 弥生会計（CSV）

| 指標 | ツール | 備考 |
|---|---|---|
| 現預金残高、売掛金残高 | 残高試算表 CSV | エクスポート日の残高。前週比は前回パルスの保存値から、なければ省略 |
| 月初来売上 | 仕訳日記帳 CSV または残高試算表 CSV（損益） | 当月 vs 前月は月別に二つのエクスポートが要る |
| 取引先別の売掛金 | 補助元帳 CSV | 顧客名別。期日は請求書 CSV から |
| 未仕訳の明細 | 読めない | 銀行明細の未仕訳は CSV に出ない。「未仕訳は確認できない」と書く |

給与計算ソフト、経費精算、決済サービスは別のコネクタで、下のそれぞれのセクションを支える。ここではない。

## 売上（PayPal / Square / Stripe）

| 指標 | ツール | 備考 |
|---|---|---|
| 直近 7日間の入金合計 | PayPal の取引一覧 | 期間内の完了した精算入金を合計 |
| 売上の推移 | PayPal の取引一覧 | 直近 7日 vs その前の 7日。差分を計算 |
| 失敗・保留の取引 | PayPal の取引一覧 | 3万円超にフラグ（`thresholds.md`） |
| Square の入金 | Square（接続時） | PayPal と同じ — 合計＋推移。決済一覧は呼び出しごとに 1店舗なので店舗を順に回す |
| Stripe の売上 | Stripe `list_invoices`（接続時） | 期間内の支払済み請求書。USD 精算なら換算せず `USD 1,200` と精算通貨で書く |
| Stripe の決済失敗 | Stripe の API 読み取り — charges／payment intents（接続時） | 期間内の失敗した決済。3万円超にフラグ |
| Stripe のチャージバック | Stripe の API 読み取り — disputes（接続時） | 期間内に開いたチャージバックは名指しで要対応リストへ |

使える決済コネクタをすべて使う。PayPal と Square の両方が接続されていれば、合計とソース別の両方を報告する。

## 営業（HubSpot）

| 指標 | ツール | 備考 |
|---|---|---|
| ステージ別パイプライン | `search_crm_objects` type=deals（`get_crm_objects` は明示の ID が必要。`../../../shared/connector-call-shapes.md`） | 商談ステージで集計。金額を合計 |
| 今週成約した商談 | `search_crm_objects` | closedate が期間内、ステージ = closed-won で絞る |
| 冷めた商談 | `search_crm_objects` | `notes_last_updated` が 7日超前、かつ開いているステージ。これが HubSpot の商談の「最終活動日」だ — `hs_last_activity_date` や `hs_lastactivitydate` というプロパティは存在しない |
| 今週の新規リード | `search_crm_objects` | createdate が期間内 |
| 停滞・期日超過の商談 | `search_crm_objects` | closedate < 今日で、まだ開いている商談 |

## 今週の予定（Google カレンダー）

| 指標 | ツール | 備考 |
|---|---|---|
| 今週の主要な予定 | `list_events` | 今週に絞る。顧客との打ち合わせ、期限、重要な仮押さえを出す |
| 向こう 7日間 | `list_events` | 前を向く視点。社外の相手がいるものを強調 |

時刻は Asia/Tokyo（JST）で印字し、payload のオフセットを信じる。カレンダーの既定タイムゾーンが海外のままの設定ミスがあれば、選ばずにそう言う（`../../../shared/chain-seams.md`）。祝日・銀行休業日（土日祝、12月31日〜1月3日）と五十日（5日・10日・15日・20日・25日・月末）は、その週の入金・支払いの着金日に効くので、予定と並べて出す。

## 要対応（Gmail または Microsoft 365）

| 指標 | ツール | 備考 |
|---|---|---|
| 至急のスレッド | `search_threads` | クエリ: `is:important OR is:starred newer_than:7d` |
| 顧客のエスカレーション | `search_threads` | クエリ: 「クレーム」「苦情」「解約」「返金」「キャンセル」「至急」「催促」のような語、直近 7日 |
| 期限のある依頼 | `search_threads` | クエリ: `is:unread` ＋「期限」「本日中」「至急」「ASAP」のような語 |
| 口コミの通知 | `search_threads` | Googleビジネスプロフィールからの「新しいクチコミ」通知。★3以下は名指しで要対応へ（口コミ専用のコネクタはないので、通知メールが経路） |

**Gmail のフォールバック**: Gmail の呼び出しがエラーになったら（認証が不安定）、要対応を黙って飛ばし、付録に「Gmail 利用不可」を加える。パルスの本文にエラーを出さない。

## リスクスキャン

指標の取得と並行して回す — 指標が終わるのを待たない。

| リスク | ソース | 条件 |
|---|---|---|
| 期日超過の売掛金 | 会計ソフトの請求書／取引先別残高 | 期日から 30日超、未入金。60日超は 🔴 |
| 未仕訳の明細が溜まっている | 会計ソフトの銀行・カード明細 | 未仕訳が 30件超 |
| 今週の支払予定が重い | 給与＋仕入先振込＋借入返済＋税金 | 合計が手元資金の 50%超 |
| 停滞した商談 | HubSpot | 開いている商談で 7日以上動きなし |
| 期日超過の商談 | HubSpot | 開いている商談で成約予定日が過去 |
| 至急のメール | Gmail または Microsoft 365 | `is:important` またはエスカレーションの語 |
| 決済の失敗 | PayPal / Square / Stripe | 失敗または保留が 3万円超 |
| 新しいチャージバック | Stripe / PayPal | 期間内に開いたものはすべて — 常に要対応 |
| 未署名のまま放置 | DocuSign | 送信済みで 3営業日超 未署名 |
| 領収書なしが積み上がる | Expensify | 期間内に領収書のない経費が 5件以上 |
| 低評価の口コミ | Googleビジネスプロフィールの通知メール | ★3以下の新しい口コミ |
| 未返信の問い合わせ | Zoho Desk、メール | 24時間超 未返信 |

## 並列化

上のすべてを一つのツール呼び出しバッチで発火する。完全なパルスはふつう 8〜15 の並列呼び出しになる。一つがエラーでも残りは通常どおり進み、失敗したソースはパルス末尾の「利用できなかったソース」に現れる。
