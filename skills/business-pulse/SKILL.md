# ビジネスパルス

一つの依頼で、一枚のページ。接続済みのすべてのツールから生きたデータを引き、ひと目で読める一枚のブリーフにまとめ、今日いちばん手を打つべき一件を浮かび上がらせる。作業をするのはこちらだ — データ探しを経営者に手伝わせない。

## ステップ1 — データを並列で引く

**すべてのコネクタ呼び出しを一つの並列バッチで出す** — ツールと指標の正確な対応は `reference/data_sources.md` を見る。直列で引かない。待ち時間で 30秒のスキルが苦痛な待ちに変わる。

同時に試すコネクタ:

- **マネーフォワード クラウド会計** — 現預金残高（残高試算表の貸借対照表）、月初来の売上（推移表）、売掛金の取引先別残高（補助科目付き試算表）、未仕訳の明細件数（銀行・カード明細）
- **freee会計** — 同じ会計ソフトの読み取りを freee の事業者向けに: 試算表の現預金、月次推移の売上、請求書の未入金・期日超過、未処理の明細
- **弥生会計** — CSV 前提の同じ読み取り: 残高試算表 CSV の現預金と売掛金、補助元帳 CSV の取引先別残高、請求書 CSV の期日（銀行明細の未仕訳は直接読めないので、そう言う）
- **PayPal / Square** — 直近 7日間の入金（精算）、売上の推移、失敗・保留の取引
- **Stripe** — 入金と売上の推移、決済の失敗、新しいチャージバック（異議申し立て） — 新しいチャージバックはそのまま要対応リストへ（接続時）
- **給与計算ソフト（CSV）** — 次回の給与支払日と概算額。今週最大の支払い予定（事業コンテキストの給与行、または給与計算ソフトのエクスポートから。接続時）
- **TikTok広告** — 先週の広告費、成果、成果単価。広告費が、それが生んだと主張する売上の隣に並ぶように（接続時）
- **Expensify・法人カード明細** — 先週のカード利用額と、領収書のない経費。読み取り専用。月次締めの駆け込みより前に支出の異変を出すため。法人カードは会計ソフトのカード連携明細として読む（接続時）
- **HubSpot** — ステージ別パイプライン、動いた・成約した商談、冷めた商談、新規リード
- **Google カレンダー** — 主要な打ち合わせ、期限、今週と向こう 7日間の予定。時刻は JST で、payload のオフセットを信じる（`../../shared/chain-seams.md`）
- **Gmail または Microsoft 365** — 至急のスレッド、顧客のクレーム、期限のある依頼、Googleビジネスプロフィールの口コミ通知
- **Slack** — 社内の急ぎのシグナル、経営者の判断待ちのスレッド（Chatwork・LINE WORKS・Microsoft Teams は `build-connector` 経由で同じ役割）
- **DocuSign** — 未署名のまま置かれている契約書。数日以上経ったものにフラグ — 署名待ちのお金だ（接続時）
- **Zoho Desk** — 未解決の問い合わせ、エスカレーション（接続時）
- **Shopify** — 注文、売上、売上推移、出荷の遅れ。EC の事業者が自分の実際の一日を見られるように（接続時）
- **Square** — 出荷・引き渡しの遅れ（接続時）

コネクタがエラーを返す、またはデータを返さないときは、内部で記録して先へ進む。一つの不調な連携でパルス全体を止めない。

**会計ソフトのフォールバック**: 会計ソフトが想定外の状態を返したら（未接続、同期待ち、空のレスポンス）、お金のセクションを「n/a — 会計ソフト（名指し）が利用不可」として先へ進む。再試行しない。再接続を経営者に頼まない。ただしマネーフォワードでは **全項目 0 の科目は返ってこない** — 返らない科目はゼロであって、エラーではない（`../../shared/ledger-report-traps.md` 罠8）。

**Gmail のフォールバック**: Gmail の認証は断続的に不安定だ。呼び出しがエラーになったら、要対応のセクションを黙って飛ばし、付録に「Gmail 利用不可」と記す — パルスの途中でエラーを見せない。

**何も接続されていないのは正規の経路であって、失敗ではない。** すべてのコネクタが使えなくても、止まらず、ツールを接続しに行けと言わない。パルスを支える数字を、短いメッセージ一つで一度だけ聞く:

- 今の預金残高と、一週間前のおおよその残高
- 期日を過ぎているもの — 未入金の請求書、未払いの支払い
- 今週の売上と、普段の週との比較（ざっくりでよい）
- 今週すでに気になっていること

その答えから同じ一枚のパルスを組み、出所の行に「経営者の申告値、コネクタからの取得ではない」と記し、数字のなかったセクションは省く。数字を打ち込むのが面倒なら、ファイルのエクスポートで動く兄弟スキル — `cash-flow-snapshot` と `report-builder` はどちらも CSV を受け付ける — を案内し、それは全体像ではなく部分的な絵になる、と率直に言う。

## ステップ2 — 指標を計算する

`reference/thresholds.md` で 🔴／🟡／🟢 の判定ラインを読む。計算するもの:

- **売掛金の滞留** — 会計ソフトの取引先別残高と請求書の期日を、期日からの経過日数で区分する（0〜30日、31〜60日、61日以上）。期日別の滞留レポートを持たない会計ソフトでは、請求書ソフトまたは請求書 CSV の期日から組む
- **パイプラインのカバー率** — HubSpot の加重パイプライン ÷ 月間売上目標
- **売上の推移** — 会計ソフトの今月売上 vs 前月（または PayPal／Square の直近 7日 vs その前の 7日）
- **未仕訳の明細** — 銀行・カード明細のうち仕訳されていない件数。多いほど、上の現預金と売上は暫定値だ
- **今週の支払予定** — 給与、仕入先への振込、借入返済、税金の合計を手元資金と比べる

各セクションに 🟢／🟡／🔴 のステータスを付ける。ソースが何も返さなかったら、その指標を「n/a」とし、付録に記す。

## ステップ3 — リスクを先回りして挙げる

手を打てる項目を探す。リスクの各項目は、特定のレコードと次の一手を名指しする — 「期日超過の請求書がいくつか」では役に立たない。「株式会社コーウィン商会 182,400円、34日超過、9月1日以降返信なし」なら動ける。

- 会計ソフトの請求書で期日を 30日超えたもの — 顧客名、金額、超過日数を名指し
- HubSpot の商談で 7日以上動きがないもの、成約予定日を過ぎてまだ開いているもの
- メールのスレッドで至急の印が付いたもの、「クレーム」「解約」「返金」「キャンセル」「至急」を含むもの
- PayPal／Square／Stripe の失敗・保留の取引で、`reference/thresholds.md` のライン（3万円）を超えるもの
- 今週の支払予定や入金予定が銀行休業日（土日祝、12月31日〜1月3日）や五十日（5日・10日・15日・20日・25日・月末）に当たるもの — 振込の着金がずれる。年末年始・ゴールデンウィーク・お盆は取引先も休むので、その前後の入金・支払いは日付を確認する

## ステップ4 — 出力を組み立てる

`reference/output_template.md` のテンプレートを正確に使う。実データのあるセクションだけを含める — 使えなかったコネクタの見出しは省く。深さは文脈に合わせる: 気軽な「調子はどう」には厚めの報告、「打ち合わせ前にサッと」には引き締めたものを。

コネクタ横断の統合が、このスキルの真価だ。Slack のメッセージが HubSpot の停滞した商談につながっているなら、そのつながりを「今日の最優先」に出す。統合があるから、パルスは各ツールを個別に見るより役に立つ。

書き方のルール:
- 数字が先、言葉が後。「売上は好調」とは書かない — 「今月 1,340万円、前月比 ▲ 8%」と書き、判断は経営者に委ねる。
- すべての数字に、取れる限り前期比の差分を添える。絶対値のスナップショット（預金残高）にも前週比を付ける。
- 形容詞ではなく、名前と金額。「株式会社コーウィン商会 182,400円、34日超過」は「気になる売掛金がいくつか」に勝つ。
- 埋め草を書かない。報告に値するものがないセクションは「特に変化なし」と書いて先へ進む。

## ステップ5 — パルスのページを届ける

チャットのパルスと並行して — 決してその代わりではなく — 経営者の保存された出力形式に従ってパルスの完全版を届ける。既定を markdown ファイルにしない。`## Business context` ブロックの `出力形式` を確認する（共通スタイルガイドのルール、`../../shared/artifact-style.md`）:

- **visual artifacts（既定）:** ハウススタイルの HTML ページとしてパルスを描画する。現預金残高、月初来売上、加重パイプラインはスタットタイルで、差分を文脈行に置く。各セクションの 🟢／🟡／🔴 はステータスピル（good、warn、critical）にする。要対応のリスクは金額列を tabular-nums にした表。今日の最優先はページ最上部の独立したパネル。使えなかったコネクタは付録の静かな一行。
- **docx / md / notion / canva の指定:** 同じ内容をその形式で届ける — DOCX または markdown ファイル、コネクタ経由で作る Notion ページ（指定の保存先に、上書きせず）、または Canva コネクタ経由で作る Canva Doc（実行ごとに新しいデザイン、日付を名前に。表はリストになる）。Notion や Canva が未接続なら visual artifact にフォールバックし、その理由を言う。
- **best for skill:** visual artifact を使う — パルスは目で走査するものであって、綴じるものではない。

## ステップ6 — 保存と共有（一度だけ）

パルスを提示したあと、一度だけ申し出る:
- 「ファイルとして保存しましょうか？」（ファイルのコネクタ — Google Drive または Microsoft 365 — があればそれを使う。経営者のドライブへのコピーであって、アーティファクトの横に HTML をもう一つダウンロードすることではない）
- 「Slack に投稿しましょうか？」（Slack が接続済みで、経営者が確認したときだけ — Slack への書き込みは明示の承認が必要）

「はい」なら実行する。「いいえ」または無反応なら先へ進む — 二度聞かない。

## 実行のあとに

パルスが何を対象にしたかを一行で締め、次に最も関連する次の一手を一つ、近いものを最大二つ添える:

- お金か売掛金が 🔴 なら: 「誰が払ってない」は `invoice-chase`。
- 成長の疑問が中心なら: 「マーケは効いてる？」は `growth-pulse`。
- 定例にするなら: 「月曜ブリーフ」は毎週 `/monday-brief`。

提案は最大三つ。このセッションで経営者が断った提案は繰り返さない。

## 範囲の絞り込み

経営者が狭い切り口を求めることがある:

- **「お金だけ」「資金の確認」** → お金のセクション＋売掛金関連のリスクのみ
- **「パイプラインだけ」「商談の確認」** → 営業のセクション＋停滞商談のリスクのみ
- **「要対応だけ」「急ぎのものは？」** → 要対応＋すべてのリスク。指標のセクションは出さない
- **「打ち合わせ前にサッと」** → 要点＋今日の最優先のみ。セクションの全文は出さない

## やってはいけないこと

- **データを引く前に許可を求めない。** スキルが起動されたなら、実行する。「会計ソフトを確認してもいいですか？」と聞くのは本末転倒だ。
- **数字をでっち上げたり推定したりしない。** ソースが何も返さなければ、「n/a」と明示する。空白を推測で埋めない。
- **差分を省かない。** 比較のない数字は洞察の取りこぼしだ。前期の基準がなければ、項目を省くのではなく「（前期の基準なし）」と書く。
- **パルスの途中でコネクタのエラーを見せない。** 付録に記録する。パルスは届けられたものから始める。
- **会計ソフトのサマリーオブジェクトを信用しない。** 費用、粗利、売掛金・買掛金の滞留区分は明細行または詳細の呼び出しから取る。返ってこない科目はゼロ、`ratio` の `null` は算出不能（`../../shared/ledger-report-traps.md`）。
- **未仕訳の明細を無視しない。** 未仕訳が残っている間、現預金と売上は暫定値だと明記する。

## 追加ソースと、定期のプリセット

対応は `reference/v2_sources.md` を読む:

- **Shopify** — 注文、売上、出荷状況。EC の事業者がパルスの中で自分の実際の一日を見られるように
- **会計ソフト** — freee会計、マネーフォワード クラウド会計、弥生会計（CSV）がお金のセクションを支える。同格だ（`../../shared/connector-neutrality.md`）。海外製の会計ソフト（Xero、Zoho Books、NetSuite など）を使う事業者も同格に扱う。二つ接続されているときは、経営者が合計の「正」となる一つを名指しする

パルスは変わらず、接続されているものから組み、自然に縮退する — コネクタ一つなら部分的なパルス、全部そろえば全体像。

### 定期のプリセット

このスキルは定期実行に向いていて、プリセットが形を決める:

| プリセット | いつ | 形 |
|---|---|---|
| 月曜 | 週の始まり | 完全なパルス。前を向く。何が来るか、何に手を打つべきか |
| 金曜 | 週の終わり | 振り返り。何が動き、何が決まり、何がずれたか |

月曜が祝日なら火曜の朝に回し、「今週」は火曜始まりで読む。年末年始・ゴールデンウィーク・お盆の明けの週は、休み中に溜まった要対応を最初に出す。

定期実行はこのスキルの属性であって、別コマンドを作る理由にはならない。**ただし、このプラグインにスケジューラはない**（`../../shared/chain-seams.md`「誰も設定していない定期実行」）。実行環境に本物の定期実行の仕組みがあればそれを作ってから「設定しました」と言う。なければ率直にそう言い、Google カレンダーの繰り返し予定（「月曜 7:00: ビジネスパルスを実行」）を提案する。

頻度の提案は、経営者が役に立ったと感じたパルスのあとに一度だけ。二度聞かない。

## 一覧にないツールを使う

このスキルで名指しされたコネクタは検証済みの経路であって、壁ではない。経営者がこの流れに未接続・未掲載のツールを使わせたいなら、`build-connector` を提案する — コネクタディレクトリを先に確認し、なければ Zapier 経由で接続する。生の API に対して手組みはしない。接続ができれば、そのツールは他の任意コネクタと同じ承認ゲートのもとでこのスキルに加わる。
