# freee会計 — 突合リファレンス

[moneyforward-reconcile.md](moneyforward-reconcile.md) と
[yayoi-csv-reconcile.md](yayoi-csv-reconcile.md) の兄弟ファイル。締めの手順もパックも同じ。
読み取り方と「要対応」シグナルが違うのは、freee会計のデータモデルとコネクタの範囲が
違うからだ。

freee会計の接続は、Claude のコネクタディレクトリにあればそれを、なければ `build-connector`
（Zapier）で作る。**どこまで読めて、どこまで書けるかは接続の作り方で変わる。接続後に
コネクタのツール一覧で読み書きの範囲を確認し、最初の締めで事業コンテキストに控える。**
このファイルはツール名を書かない。freee会計の用語（取引、口座振替、明細、勘定科目、
取引先、税区分、試算表、月次推移）で何を読むかを定義する。

---

## コネクタが持つもの、持たないもの

| 持つことが多いもの | 接続によっては持たないもの |
|---|---|
| 取引（収入・支出）、未決済取引、決済（消込） | 明細の一覧（自動で経理の未処理明細） |
| 口座振替、口座（銀行・カード・現金）と残高 | 試算表（損益計算書・貸借対照表）や月次推移のレポート |
| 勘定科目、税区分、品目、部門 | 仕訳帳そのもの（取引から組み立てる） |
| 取引先（インボイス登録番号の有無つき） | 証憑（ファイルボックス）の添付状態 |
| 請求書、見積書、経費精算 | |
| 事業所の設定：決算月、経理方式、課税区分 | |

パックに明記する：税理士は、どの部分がコネクタから来て、どの部分がエクスポートから来たかを
知る必要がある。

---

## 取得するレポート

### 試算表（損益計算書）— レポートが読めなければエクスポートから

接続に試算表の読み取りがなければ、ステップ2 の前に **試算表（損益計算書）のエクスポート**
（レポート → 試算表 → 対象月 → エクスポート）を頼む。接続されていても同じ。理由を一行で
言う：*「この接続では freee会計のレポートが読めないので試算表のエクスポートが必要です。
それ以外は直接読めます。」*

経営者がエクスポートできないときの代替：取引一覧から対象月の **収入の合計 − 支出の合計**。
出てくるところ全部に *「取引ベースの概算で、試算表ではない」* と表示する。

前月比は **月次推移** のエクスポート、または前月の試算表を二つ目として頼む。

### 取引・口座振替・明細 — 三つの一覧

| 部分 | 何を読むか | 持っている内容 |
|---|---|---|
| 取引 | 収入・支出の取引を発生日の範囲で。決済状況（未決済・決済済み）で絞れる | 売上・経費・仕入。勘定科目、税区分、取引先、金額、決済状況 |
| 口座振替 | 対象月の口座間の資金移動 | 銀行口座間の振替、カード引き落とし、現金の引き出し |
| 明細 | 自動で経理の明細。読めない接続では画面の件数を聞く | 銀行・カード連携で取り込まれた入出金。「未処理」か「登録済み」か |

下書きの取引（未確定）と削除済みの取引は締めから除く。一覧は最後のページまで読む。
1ページでは月にならない。

主な項目：

| 項目 | 注意 |
|---|---|
| 発生日、期日 | 取引の日付。期日は未決済取引の支払期限 |
| 決済状況 | 未決済（売掛金・買掛金に残る）／決済済み。決済日と決済口座がつく |
| 取引先 | 取引先マスタの名前。インボイス登録番号の有無を持つ |
| 金額、未決済残高 | 取引の総額と、まだ入金・支払いされていない残り |
| 証憑 | ファイルボックスの証憑が紐づいているか |
| 税区分 | 課税売上 10%／課税仕入 10%／8%（軽減）／非課税／不課税。免税事業者からの仕入れは「経過措置 80%／50%」の区分 |
| 品目・部門・メモタグ | 集計の切り口。締めでは品目で売上の集中を見る |

## 「要対応」シグナル：自動で経理の未処理明細

freee会計では、口座連携で取り込まれた明細が「自動で経理」に並び、経営者が取引として登録
するまで **未処理** のまま残る。それが要対応シグナル — お金は動いたが、まだ取引に落ちて
いないもの。

freee会計でのステップ2 はこう報告する：

```
未処理の明細：   9件、口座 2つ（三井住友 7件、ビジネスカード 2件）
```

接続によっては明細そのものを一覧できない。その場合は件数と口座を経営者に伝え、締めが
先へ進む前に freee会計側（自動で経理 → 口座 → 未処理）で登録してもらう。ステップ6 の
サマリーの「要対応」行はこの件数を載せる。

**「現金」口座の残高がマイナス、または不自然に大きい** ときは、実際の現金ではなく
未登録の立替（役員借入金・事業主借）か口座振替の漏れだ。手元資金としてではなく、
開いた項目として名指しする。

税区分が空のまま、または「対象外」のままの課税取引も同じ行に数える。

## 重複検出：取引を文書として走査する

請求書を二重に登録した場合、未決済の取引が二つ立つ。ステップ4 は収入と支出を分けて
走査する：

- 同じ取引先（収入なら顧客、支出なら仕入先）
- 同じ金額（円は整数なので完全一致）
- 発生日が 5暦日以内
- どちらも未決済か、片方が期間内に決済済み

自動登録ルールで作られた取引や、定期的な支出（サブスクリプション、家賃）が
よくある誤検知。ルール名や繰り返しの根拠を示して、経営者に理由が分かるようにする。

一つの取引に複数の行（複数の勘定科目）があるのは一つの取引だ。取引同士を比べ、
行同士を比べない。

## 証憑：まず取引を、次にフォルダを

freee会計のファイルボックスに証憑（領収書・請求書の画像や PDF）を入れて取引に
紐づけられる。注目ライン（3,000円）以上の経費について、接続が添付状態を返すなら先に読む：

- 紐づけあり → 「証憑あり（freee会計）」
- なし、または接続が返さない → フォルダ走査に戻し、それでもなければ経営者に聞く

「返さない」を「証憑なし」と断定しない。電子取引の証憑は電子帳簿保存法で電子データ保存が
義務なので、保存場所を聞く形で扱う。

## 決済サービスの入金：明細があれば検索、なければ CSV 突合

口座連携があれば、Stripe、Square、PayPal、Shopify ペイメントの入金は着金時に明細に載る。
ステップ3 は未処理の明細のうち取引内容に決済サービス名（カナ表記を含む）を含むものを
決済サービスごとに一覧にし、登録済みの入金は決済サービスの入金レポートと手数料差引後同士で
突合する。

接続が明細を読めないときは、[paypal-settlements.md](paypal-settlements.md) の CSV 突合へ
直接進む：決済サービスの入金レポートと、経営者が出す **銀行の入出金明細**。明細は試算表の
エクスポートと同時に頼む。

この柱でコネクタが供給できるものが二つ：

- 対象月の **決済（消込）** — 請求書・取引に対して登録された入金。決済サービスからの
  入金を消込として登録していればここに出る。
- 請求書の **決済方法** の設定 — どの決済サービス（Stripe、PayPal など）で受けるように
  設定したか。どの入金レポートを待つべきかが分かる。

## 事業所・会計期間・税区分

事業所の設定から **決算月**、**経理方式**（税込・税抜）、**消費税の課税区分**（課税事業者・
免税事業者、本則・簡易課税・2割特例）、**インボイス登録** の有無を読む。事業コンテキストに
まだなければ締めの最初に一度読み、パックの全金額の表記（税込・税抜）、しきい値、
ステップ9 で `/tax-prep` を提案するか（決算月の近さ）に使う。個人事業主は暦年（12月決算）
固定。ルールは `../../../shared/currency-and-locale.md`。

## 縮退運転 — freee会計が接続されていない

この経路を取るのは、どの freee会計の接続も動かないときだけ。コネクタディレクトリの接続が
認可切れで、経営者自身が作った接続が横にあれば、そちらを呼ぶ
（`../../../shared/connector-neutrality.md`「一つのコネクタ、二つの登録」）。

**三つのエクスポート** を頼む：**試算表（損益計算書）**、**仕訳帳**（または対象月の
取引一覧）、**銀行の入出金明細**。未処理の明細の件数は自動で経理の画面にしかないので、
四つ目として聞くか、パックに「未取得」と書く。

---

## ページングと上限

一覧は 1ページずつ返り、1ページの件数は接続によって上限が違う（接続後に確認する）。
最後のページまで進める。集計だけが要るときは試算表のエクスポートの方が安く正確で、
取引を全件並べて足すのは代替でしかない。
