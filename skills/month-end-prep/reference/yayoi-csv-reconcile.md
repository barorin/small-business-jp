# 弥生会計 — 突合リファレンス（CSV 前提）

弥生会計には公式コネクタがない。**仕訳日記帳 CSV、残高試算表 CSV、必要なら補助元帳 CSV
のエクスポート** を前提に締めを進める（`build-connector` で接続を作った場合も、読める
ものは同じ三つの帳票と考える）。

## 取得するレポート

### 残高試算表（損益計算書）

弥生会計の **残高試算表（損益計算書）** を CSV でエクスポートしてもらう：
- 期間：対象月の初日〜末日（月次で出す）
- 税抜・税込：事業者の経理方式に従う（どちらで出したかを聞き、パックに書く）
- すべての科目を含める（残高 0 の科目は出ないことがある — 「無い」と「0」を区別する）

下流で使う主な項目：
| 項目 | 注意 |
|---|---|
| `売上高` | 売上の合計 |
| `売上総利益` | 売上高 − 売上原価 |
| 粗利率 | 売上総利益 ÷ 売上高 で計算する |
| `営業利益`／`経常利益` | 利益。説明文の見出しには営業利益を使う |
| `販売費及び一般管理費` 計 | 販管費の小計 |

列は `前月繰越`、`借方`、`貸方`、`残高`（当月残高）の順が一般的。当月の損益は借方・貸方から
読み、前月比は前月の残高試算表 CSV をもう一つ頼む。

### 仕訳日記帳（取引一覧）

対象月の **仕訳日記帳** を CSV でエクスポートしてもらう。未処理のフラグ付けと重複検出に
使う行単位の明細がこれだ。

主な列：
| 列 | 注意 |
|---|---|
| `日付` | 取引日（入力日ではない）。和暦形式（R08/04/01）のことがある |
| `伝票No.`／`識別フラグ` | 同じ伝票番号の行は一つの仕訳。識別フラグ 2000 は単一仕訳、2111・2100・2101 は複合仕訳の先頭・中間・末尾 |
| `借方勘定科目`／`貸方勘定科目` | 勘定科目。複合仕訳では片側が `諸口` |
| `借方補助科目`／`貸方補助科目` | 取引先別の売掛金・買掛金はここ |
| `借方金額`／`貸方金額` | 税込の金額。3桁区切りの有無はエクスポート設定次第 |
| `借方税区分`／`貸方税区分` | 課対仕入 10%、課税売上 8%（軽）、非課税、対象外 など |
| `摘要` | 自由記述。取引先名や内容はここから読む |

## 未処理の仕訳を見つける

次のいずれかなら「未処理」としてフラグする：
- 勘定科目が `未確定勘定`（スマート取引取込で科目が決まらなかったもの）
- `仮払金`／`仮受金` のまま月末を越えている
- 勘定科目が空欄
- 課税取引なのに税区分が空欄または `対象外` のまま

## 文字コードと形式

弥生会計の CSV は **Shift_JIS（CP932）** で出ることが多い。読み込みで文字化けしたら
エンコーディングを指定し直し、UTF-8 に変換しない限り摘要の取引先名が壊れたまま突合に
使われる。日付が和暦なら西暦に直してから照合する。金額列に「円」やカンマが混ざっていれば
整数に正規化する。行数が多いときは月をまたがずに、対象月だけを出してもらう。

## よくあるデータの問題

**複合仕訳** — 一つの支払いを複数の科目に分けた仕訳は、同じ日付・同じ摘要で金額の違う行が
複数並び、片側が `諸口` になる。これは重複ではない。重複を探す前に `伝票No.`（または
識別フラグの並び）で行をまとめる — 同じ伝票番号の行は一つの仕訳だ。

**スマート取引取込と手入力** — 口座連携（スマート取引取込）から来た仕訳は摘要に銀行の
取引内容がそのまま入り、手入力の仕訳は摘要が短いか空のことが多い。どちらも単独では
問題の兆候ではないが、証憑がない理由の説明にはなる。

**PayPal・Stripe の入金がすでに仕訳されている** — 経営者が決済サービスの入金を口座連携
経由で取り込んでいれば、着金の仕訳はすでに仕訳日記帳にある。突合（ステップ3）で
二重に数えない。摘要に「PAYPAL」「STRIPE」「ペイパル」が入った入金行を先に確認する。

**前受金・着手金** — 顧客からの前受金は納品・役務提供が終わるまで売上ではない。
摘要に「着手金」「前受」「内金」とある入金や、対応する売上（請求書）のない大きな入金は、
経営者の認識のためにフラグする。
