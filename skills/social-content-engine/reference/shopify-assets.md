# Shopify の商品データをコンテンツへ

Shopify 接続時は、商品写真・商品名・説明・価格がそのままデザインの項目と
キャプションに流れ込む。経営者が挫折する2つの手順 — 写真を探すことと、
価格を打ち直して間違えること — がなくなる。

---

## 何を読むか

商品とそのバリエーションを読む。重要な項目：

| Shopify の項目 | 用途 |
|---|---|
| `title` | 見出しのスロット、キャプションの主題 |
| `body_html` | 利点の一文の元ネタ — タグを剥がす。生の HTML を貼らない |
| `images[].src` | デザインの画像スロット |
| `variants[].price` | キャプションや価格スロットの価格 |
| `variants[].compare_at_price` | 「通常価格 → セール価格」の唯一の根拠 |
| `variants[].inventory_quantity` | そもそも取り上げるかどうか |
| `tags`、`product_type` | 商品をテーマにまとめる |

**税込か税抜かをストア設定で一度確認する。** Shopify の「価格に税金を含める」
設定が有効なら `variants[].price` は税込、無効なら税抜だ。日本の消費者向けの
表示は総額表示（税込）が義務なので、税抜の値しかないなら投稿に価格を載せる前に
経営者に税込額を確認する。確認した設定は事業コンテキストに記録し、毎回
聞き直さない。

---

## 商品を投稿にする

1. **投稿する価値のある商品を選ぶ。** 在庫切れや、投稿が効いたら持たない量しか
   ない商品は外す。火曜に紹介した売り切れ商品は、水曜の苦情になる。
2. **画像を Canva に入れる。** Shopify の画像 URL からアップロードし、
   アップロードジョブを成功までポーリングし、返ってきたアセット ID を記録する。
   オートフィルの画像項目が受け付ける値はその ID だけだ。
3. **利点の一文は説明文「から」書く。説明文「で」書かない。** 商品説明は
   商品ページ用に書かれたもので、フィード用ではない。具体的な一点だけを取り、
   残りは捨てる。
4. **価格はそのまま通す。** API の応答から数字を写す。丸めない、換算しない、
   セール価格を推測しない。表記は `1,240円（税込）` の形。

---

## 価格と表現のルール

公開投稿の価格ミスは、このスキルが起こしうる最も高くつく失敗だ。100 人が見た
後で経営者がこっそり直すことはできない。

- コネクタが実際に返した価格だけを書く。
- 「通常価格 X 円 → Y 円」は `compare_at_price` があり、かつ `price` より高い
  ときだけ。Shopify が示していない割引率を計算しない。二重価格表示は景品表示法
  の対象で、「通常価格」は最近相当期間に実際に販売した価格でなければならない —
  `compare_at_price` が実売価格だったか経営者に一度確認する。
- 在庫数が裏付けない限り「残りわずか」「在庫僅少」と書かない。
- 価格が欠けていればそう言って聞く。前のセッションで見た価格に戻らない —
  価格は変わるし、カレンダーは長く生きる。
- 食品（コーヒー豆など）は軽減税率 8% の対象で、店内飲食は 10%。税込額を
  出すときは税率が混ざっていないか確認する。

## 1つのデザインに複数の商品

商品グリッドやカルーセルは商品ごとに画像スロットが1つある。生成前に個別に
列挙し、それぞれを特定の商品に対応づける：

```
スロット Product1_Image → 「ひかりブレンド 200g」              → asset_id 確認済み
スロット Product2_Image → 「シングルオリジン エチオピア 200g」  → asset_id 確認済み
スロット Product3_Image → —                                    → 未定、経営者に聞く
```

聞かずに同じ写真でスロットを埋めない。「3商品」グリッドに同じタイルが3枚
並べば間違いに見える。実際に間違いだからだ。

---

## Shopify がないとき

代替は経営者の写真フォルダとブリーフに書かれた内容。これも完全な経路だ —
アップロードと価格の手入力の手間がかかるだけで、その価格は公開前に必ず
声に出して確認する（税込かどうかも含めて）。
