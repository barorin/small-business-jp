# 落とし穴

お金を失う、または案件を失う失敗パターン。提案書・見積書は拘束力のある文書だ — ここでの間違いには円の値札が付く。

---

## 落とし穴：写真から推定した数量

**なぜ重要か：** 案件が赤字になる古典的な経路だ。基準となる物のない写真では寸法は分からず、30% 低く見積もった面積は、儲かるはずの案件を、経営者が再交渉できない損失に変える。

### 悪い例

```
写真から約 400㎡ と推定。
```

### 良い例

```
写真からは面積を決められません — 大きさの基準になるものが写っていません。
二択です：数字をいただくか、1台あたりの単価で出して、現地確認で調整する
一行を加えるか。
```

写真はメーカー、型番、状態、出入りの制約を教える。大きさは教えない。

---

## 落とし穴：「対象外」の節がない

**なぜ重要か：** 作業範囲の争いはサービス業で失われる粗利の最大の源で、そのすべてが誰も書き残さなかったことから始まる。

### 悪い例

作業範囲の節だけ。顧客はダクトの更新も含まれていると思い込む。含まれていなかった。

### 良い例

常識的な顧客が含まれていると思い込みそうで、実際は含まれないものの明示的な一覧。三行の手間で、口論を丸ごと防ぐ。

---

## 落とし穴：黙った前提

**なぜ重要か：** 経営者は知っていても顧客が一度も見ていない前提は、守りにならない。違っていたと分かった瞬間に、経営者の問題になる。

### 悪い例

はしごで出入りできる前提で価格を決める。経営者には伝える。文書には書かない。

### 良い例

```
本見積は、屋上への出入りが既存の外部はしごで可能であることを前提としています。
高所作業車またはクレーンが必要な場合は 180,000円（税抜）を追加いたします。
```

顧客に見える文章の中に、結果を名指しして。それが争いを、事前に合意した追加・変更に変える。

---

## 落とし穴：創作した単価

**なぜ重要か：** 人日単価は経営者の経済の核心だ。経営者が気づかない、もっともらしい数字は、案件を失わせるか、案件で損をさせる。

### 悪い例

```
4行目 — 中央監視（制御）との連携: 420,000円
```

何の根拠もなく導いたもの。

### 良い例

```
4行目 — 中央監視（制御）との連携: ______円

履歴に類似案件がなく、単価表にもありません。他はすべて金額が入っています。
数字をいただければ出せます。
```

空欄は正直で、経営者の五秒で済む。捏造した数字は気づくのに十分かかり、気づかれないかもしれない。

---

## 落とし穴：税抜と税込の混在

**なぜ重要か：** 明細は税抜、合計だけ税込、添え状には別の数字 — どれが本当の金額か分からない見積書は、顧客に「消費税分の値引き」を主張する隙を与え、着手金の請求書と合わなくなる。

### 悪い例

```
合計 2,046,000円
```

税込か税抜かの表示がなく、明細の合計（1,860,000円）とも一致しない。

### 良い例

```
小計（税抜）    1,860,000円
消費税（10%）     186,000円
合計（税込）    2,046,000円
```

積算は税抜、消費税は税率ごとに別記、合計は税込を併記。軽減税率の品目が混ざるなら 8% の行を分ける。添え状の数字も同じ表記に揃える。

---

## 落とし穴：経営者のテンプレートを作り直す

**なぜ重要か：** 他の提案書と同じに見えない提案書は手で作り直され、それはこのスキルが取り除くために存在する作業そのものだ。見慣れたものは、より良いものに勝る。

### 悪い例

経営者自身のものより、すっきりした現代的なレイアウトを作る。

### 良い例

テンプレートに完全に合わせる。改善できそうな部分も含めて。改善は、提案書が出て行ったあとに別途申し出る。

---

## 落とし穴：失格の公募に回答を書く

**なぜ重要か：** RFP・公募への回答はまる一晩の仕事だ。必須の参加資格を満たせないなら、その一晩が無駄になり、この層に余った夜はない。

### 悪い例

回答をまるごと書いてから、最後に保険の要件に触れる。

### 良い例

何かを下書きする前に、参加可否を先に：

```
参加可否：施設賠償責任保険 1億円以上が要件で、現在は 5,000万円。8日までに
増額できなければ失格です。残りを書く前に確認しておきますか？
```

---

## 落とし穴：リスクを顧客向け文書に埋める

**なぜ重要か：** 経営者には率直な見立てが要り、顧客には提案書が要る。混ぜると、顧客を不安にさせるか、経営者からリスクを隠すかのどちらかになる。

### 悪い例

リスクを和らげて提案書の前提条件の節に入れ、直接は何も言わない。

### 良い例

別々の二つのもの。提案書には中立で顧客にふさわしい言葉の前提条件が入る。経営者へのチャットのメッセージには、本当に心配なことを率直に書く。

---

## 落とし穴：明示的な承認なしに送る

**なぜ重要か：** 金額の入った提案書は資金、予定表、評判を拘束し、顧客が読んでしまえば取り消せない。

### 悪い例

経営者が「よさそう」と言ったので DocuSign に回す。

### 良い例

何が起きるかを述べる — 宛先、合計（税込）、契約ルート、受注したら何が動くか — そしてその特定の行動への「はい」を待つ。

---

## 落とし穴：結果を記録しない

**なぜ重要か：** 受注した提案書は明日の類似案件だ。失注はさらに価値があり、プラグインの他のどこもそれを捉えていない。

### 悪い例

送って、次へ。

### 良い例

受注、失注、返答なしを、最終金額と、分かれば理由とともに記録する：

```
ローズウッド不動産 — 失注。1,860,000円（税抜）。田中様によると競合は
160万円。当社は 1棟 300,000円、先方は 1棟あたり約 267,000円 と推定。
```

この一行が、この分野の今後のすべての見積を鋭くし、経営者自身は決して書き残さなかったはずのものだ。

---

## 落とし穴：標準より弱い着手金

**なぜ重要か：** 着手金の条件は資金繰りだ。機器の比重が大きい工事で 50% から 25% に黙って下げると、経営者が顧客の機器を立て替えることになりかねない。

### 悪い例

経営者が普段どうしているかを確かめずに、妥当そうな着手金を使う。

### 良い例

条件は過去の提案書から引き、弱めたところにはフラグを立てる：

```
通常は着手金 50% です。今回は準常連の顧客なので 40% にしてあります。
戻したければ変えてください。
```
