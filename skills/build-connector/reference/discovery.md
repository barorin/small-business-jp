# 探索

このファイルは、名指しされたツールへの接続方法を、決まった順番で探す手順を示す。あるセクションで一致が見つかったら、そこで止まる — 他の経路まで下りる必要はない。たいていの場合、何かが既に存在していて、それを見つけるのに十分、作るのに一時間かかる。

---

## 1. Claude のネイティブコネクタを探す

**主経路 — `ToolSearch`。** Claude が既にこのツールに届いているかを確認する:

1. 正確な製品名をクエリにして `ToolSearch` を呼ぶ。例: `ToolSearch({query: "kintone", max_results: 5})`。
2. 関係するものが返らなければ、ブランド名の代わりにベンダーのカテゴリで一度だけ再試行する（例: `"業務アプリ"`、`"CRM"`、`"勤怠"`）。日本の製品は英字表記と日本語表記の両方で試す（`"freee"` と `"freee会計"`、`"SmartHR"` と `"スマートHR"`）。

`ToolSearch` はこのセッションに既に設定されたコネクタしか見つけない — ここで外れても、まだ追加されていないだけのサーバーが存在する可能性は残る。一致は二重に返ることがある: 経営者自身の項目と、プラグインの `small-business-jp:<name>` 登録。それは一つのコネクタである: 認可されている方の項目を使い、両方なら経営者のものを使う（`../../../shared/connector-neutrality.md`「一つのコネクタ、二つの登録」）。

経営者に「もうつながっていますか」と聞くときは、登録名ではなく製品名で聞く: 「kintone は Claude のコネクタとして接続済みですか？ 接続済みなら、コネクタの一覧に kintone が見えているはずです」。`small-business-jp:kintone` のような登録名を経営者に見せない。

**副経路 — MCP レジストリを探す。** `ToolSearch` が空なら、公開エコシステムのどこかにこのツールの MCP サーバーがあるかを確認する:

1. `ToolSearch` で `SearchMcpRegistry` ツールを探す — ホストによってはネイティブに公開している。使えれば製品名で呼ぶ。
2. なければ `https://registry.modelcontextprotocol.io/v0.1/servers?search=<正確な製品名>` を `WebFetch` する — 同じデータを持つ、認証不要の公開 API。

上のいずれかで一致が見つかれば、それが答えだ: 経営者を接続まで案内することが仕事のすべてで、最良の結果である。見つからなければセクション2へ進む。

## 2. Zapier の接続を探す

**主経路 — Zapier MCP がある。** このプラグインは `.mcp.json` で宣言しているので、通常はこの状態:

1. `ToolSearch` で `discover_zapier_actions` — Zapier 自身のアプリ／アクション探索ツール — を探し、ステップ1の正確な製品名で実行する。
2. 載っていたら、アプリが Zapier にあるかだけでなく、このユースケースが要る特定のトリガーやアクションがあるかを確認する。Zapier にはあるが範囲が要る一つのアクションがないアプリは一致ではない — そう平易に言い、セクション3へ進む。

**日本のアプリについて。** freee、kintone、Chatwork、LINE、SmartHR、スマレジ、BASE、STORES、楽楽精算、Sansan などが Zapier にあるか、どのアクションがあるかは、この呼び出しの結果と Zapier のアプリ一覧で確認する。あると決めてかからず、ないとも決めてかからない。アプリがあってもアクションが英語名で、日本語の画面名と一致しないことがある — 画面ではなくアクションの説明とフィールドで判断する。

**代替 — Zapier MCP が入っていない、または届かない。** 代わりに公開アプリディレクトリを直接確認する:

1. `zapier.com/apps/<製品のスラッグ>/integrations.md` — HTML ページではなく Markdown ミラー — を WebFetch し、アプリが載っているか、何と連携できるかを見る。
2. これは MCP 経路より確度が低いものとして扱う — アプリが Zapier にあることは確認できるが、どのトリガーやアクションが使えるかは分からない。MCP 接続が使えるようになったら、そこで確認する。
3. どの面を使うべきかまだ不明なら、`zapier.com/llms.txt` と `zapier.com/.well-known/ai-catalog.json` が Zapier 自身の、探索面（MCP、SDK、アプリディレクトリ）の機械可読な索引 — どこを見るかの地図であって、検索ツールそのものではない。

**向き不向きと費用。** Zapier が合うのは、需要が単発の参照や操作で、量が少なく、代替が壊れやすい独自構築のとき。大量の過去データを引く用途や、タスク単位の費用が積み上がる場所には向かない — Zapier はタスク単位で課金する。この経路に決める前に `zapier.com/pricing.md` でプラン構成とタスクの課金方法を確認する。金額やプラン名を記憶から言わない。見積もりは経営者の前に出す（`use-zapier.md`「タスク課金の見積もり」）。

このアプリ・サービスの接続が見つからなければ、セクション3へ進む。

## 3. 文書化された API を探す

現代の SaaS のほとんどには API がある。料金ページに書いていなくても。これは技術的に何が可能かの文脈のためであって — スキル自身のルールにより、手組みする経路には決してならない。

1. `developer.<ベンダー>.com` や `docs.<ベンダー>.com` を WebFetch する — 多くのベンダーはこのどちらかで API ドキュメントを公開している。日本のベンダーは「〇〇 API リファレンス」「〇〇 開発者向け」で検索した方が早いことがある（freee、マネーフォワード、kintone、Chatwork、LINE、スマレジ はいずれも開発者向けサイトを持つ）。
2. どちらも解決しなければ、ベンダーのサポートページで「API」を検索し、経営者のアカウント設定に API キーの項目があるかを確認する — キーの項目があれば、文書化されていなくても API が存在する証拠になる。
3. それでも何もなければ、ベンダーのコミュニティやユーザー会で連携の質問を探す — API の存在は公式に文書化される前にそこで表面化することが多い。

見つかったら確かめること — 認証、エンドポイント、制限。SDK ドキュメント、チュートリアル、マーケティングページは飛ばす:

| 問い | なぜ重要か |
|---|---|
| 認証方式 | OAuth とトークンは問題ない。パスワードのみはフラグを立てる価値がある問題。 |
| レート制限 | 日次の取得が成り立つかを決める |
| 必要な特定のエンドポイント | API 全体ではなく、ステップ1で絞ったものだけ |
| 経営者のプランに API 利用が含まれるか | 上位プランに限られることが多い（kintone はコースにより API の可否が異なる）— 作る前に確認 |
| 書き込みに対応しているか | 何が可能で、どのゲートが要るかを決める |
| 認可の単位 | freee・マネーフォワードは事業所（事業者）単位で認可される。複数事業所を持つ経営者はどれを認可したかが問題になる |
| 変更履歴 | API がどのくらいの頻度で壊れるか — 何も作らないとしても、ツール全体の信頼性の文脈になる |

**プランは早めに確認する。** 経営者の契約に含まれない API に対して作るのは半日の無駄で、それはよく起きる。

**API があってもなくても、探索はここで止まらない — それは次に何を言うかの文脈であって、構築経路ではない。** セクション4へ進む。

## 4. 定期エクスポートを確認する

過小評価されているが、しばしば最良の答え。

多くのシステムは、レポートをメールで送ったり CSV を定期的に出力したりできる — 日次、週次、月次。需要が「毎朝、工事案件を引く」なら、監視している受信箱への定期エクスポートで、壊れるものがほとんどなく、Claude 側でつなぐものもなく済む — 経営者が自分の設定画面で構成する。

見る場所: レポート設定、定期レポート、配信設定、自動配信、CSV 出力予約。

**これは格下の選択肢ではない。** 失効するトークンがなく、レート制限がなく、ベンダー側の API 変更がなく、タスク単位の請求がない。一日一回の需要なら、ライブ連携より厳密に優れることが多い。弱点は遅延と静かな失敗の型 — 設定と鮮度チェックは `paths.md` セクション3。

## 5. 本当に何もない

見た目より珍しいが、実在する — 古いオンプレミスの業種特化システムには、外部への出口がまったくないものがある。

正直にそう言い、残っている選択肢を示す:

```
率直に言うと: 社内サーバーに置いた工事原価管理ソフトには API がなく、Zapier にも
ありません。きれいな方法はないです。

それでも動く方法が二つ:
  - 手動で CSV に書き出せます。週に一度そのファイルを置いてもらえれば、
    その先はすべてそれで動きます。
  - PDF をメールで送る定期レポート機能があります。読み取りは手間ですが、
    自動です。

CSV の方が確実です。試してみますか？
```

回避策付きの正直な「無理」は、経営者が保守できない壊れやすい画面スクレイピングより役に立つ。

## 見つけたことの報告

何かを作る前に、何が見つかり、それが時間の面で何を意味するかを述べる:

```
kintone は Claude のコネクタディレクトリにはありませんが、Zapier にあり、
必要な内容を満たすレコード検索のアクションがあります。

一つだけ: このボリュームだと Zapier の有料プランになりそうです。プランと
月額は Zapier の料金ページで確認してからお伝えします。

設定はそちら側の操作で、長くはかかりません。手順をご案内しましょうか？
```

（上は形式の例。kintone が Zapier にあるか、どのアクションがあるかは、実際の `discover_zapier_actions` の結果で判断し、例文をそのまま使わない。）

スキルのルールを忘れない: 探索で文書化されたきれいな API が見つかっても、それは文脈であって構築経路ではない — 構築経路は Zapier、Zapier にツールがなければ定期エクスポート。

費用、手間、障害を三行で。経営者が決めるにはそれで足りる。
