# 整備チェックリスト

`crm-autopilot` スキルが商談の整備で確認するフィールドと、各項目にフラグを立てるのに必要な証拠。経営者が特定の商談を指して「HubSpotを整理して」「Salesforceを整理して」「この商談は最新になっている？」と言ったときに実行する。

すべての項目を順に確認する。結果はレビュー一覧として提示し、経営者が承認したものだけ書き込む。

**以下のフィールド名は HubSpot のもの。** Salesforce では同じ確認を `Opportunity` の次のフィールドに対して、`salesforce-fields.md` にある discover → describe → dispatch_readonly の流れで行う：

| 確認項目 | HubSpot | Salesforce |
|---|---|---|
| 1. 最終活動 | `notes_last_updated` | `LastActivityDate`（null ＝ 一度も記録なし） |
| 2. 次のアクション | `hs_next_step` | `NextStep` |
| 3. ステージ | `dealstage` | `StageName` — フラグのみ、書き込まない |
| 4. 完了予定日 | `closedate` | `CloseDate` |
| 5. 金額 | `amount` | `Amount` — フラグのみ、書き込まない |
| 6. 関連付けられた連絡先 | 商談の関連付け | `OpportunityContactRoles` サブクエリ。不足している人物は `Contact` として作成（または既存の未変換 `Lead` として報告）してから役割を提案する |
| 7. メモ | 商談上のメモ | 商談に対する `Task` と `Event` レコード。補足のメモは `Status` = Completed の新しい `Task` として追加し、編集はしない |

## 1. 最終活動日

**確認：** 商談の `notes_last_updated` が、関連付けられた連絡先との最新の実際のやり取り（メールまたは打ち合わせ）より古くないか。

**フラグの証拠：** 直近 14 日以内に商談の連絡先との間で交わされたメールスレッドまたはカレンダーの予定が、`notes_last_updated` より新しい。

**提案する対応：** 記録漏れの活動を記録することを提案する。商談自体には手を付けない。活動を記録すれば `notes_last_updated` は自動で更新される。

## 2. 次のアクション（`hs_next_step`）

**確認：** 現在の `hs_next_step` は、最新のメールや打ち合わせで合意した内容を反映しているか。

**フラグの証拠：** フィールドに「見積書を送る」とあり、その後のメールで見積書が送付済みとわかる。またはフィールドが空欄で、直近の打ち合わせで次のアクションが明示的に決まっている。

**提案する対応：** 新しい値（完了していれば空欄）を提案する。現状 → 提案を並べて見せる。

## 3. 商談ステージ（`dealstage`）

**確認：** 直近のやり取りから、商談がステージを進めた（提案書送付、契約締結、競合に敗北 など）と読み取れないか。

**フラグの証拠：** メールや打ち合わせメモに「進めましょう」「契約しました」「〇〇社にお願いすることにしました」のような明示的な言葉があるか、打ち合わせの頻度が変わった。

**提案する対応：** **フラグのみ。ステージを自動で変えない。** 証拠を示し、経営者に判断してもらう。

## 4. 完了予定日（`closedate`）

**確認：** 最新のメールや打ち合わせで、現在の `closedate` と矛盾する時期の変更が言及されていないか。

**フラグの証拠：** 「第3四半期にずれ込みそうです」「月末までに契約します」「来期に延期になりました」のような言い回し。

**提案する対応：** 更新後の日付を提案する。現状 → 提案を見せる。

## 5. 金額（`amount`）

**確認：** 最新のメールや打ち合わせで、異なる商談規模が言及されていないか。

**フラグの証拠：** 見積メールでの明示的な価格改定、打ち合わせでの範囲拡大、顧客が受け入れた範囲縮小。

**提案する対応：** 更新後の金額（税抜か税込かを明記）を提案する。現状 → 提案を見せる。

## 6. 関連付けられた連絡先

**確認：** 商談の連絡先との直近のメールや打ち合わせに、商談に関連付けられていない人物がいないか。

**フラグの証拠：** メールの CC や打ち合わせの参加者のうち、既存の商談連絡先とドメインが一致するのに商談に載っていない人。

**提案する対応：** 不足している連絡先を商談に追加することを提案する。CRM にまだ存在しなければ先に連絡先を作成する（Salesforce：`Contact` を作り、次に `OpportunityContactRole`。どちらも書き込む前に告知する）。

## 7. メモの整備

**確認：** 90 日より古いメモや活動のうち、現在の商談の状態と明確に矛盾するものはないか。

**フラグの証拠：** 進行中ステージの商談に「失注」と書かれたメモがある、または古い契約金額が書かれたメモがある。

**提案する対応：** 現在の状態を補足する新しいメモを追加する。古いメモは**編集も削除もしない**。追記するのであって、履歴を書き換えない。

## 出力形式

結果を番号付きリストで提示し、各項目に次を示す：
- 何にフラグを立てたか
- 証拠（メールの件名と日付、または打ち合わせのタイトルと日付）
- 提案する対応（ステージ変更は「フラグのみ」）

その後、項目ごとの承認か一括承認かを聞く。承認されたものだけ書き込む。
