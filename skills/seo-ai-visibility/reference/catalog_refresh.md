# カタログ整備

ネットショップ向けの商品一括処理。全商品を採点し、悪いものから書き直し、承認済みのバッチで適用する。

Shopify と Wix が接続済みの道だ。Wix はサイト API への完全な読み書きを公開しているので、カタログとサイトの一括整備は Shopify と同じようにそこへ直接適用される — 採点、売上順、以下のバッチのゲートは両方で同一だ。

どちらもなければ、商品 CSV のエクスポートから作業し、インポート用に修正済みの CSV を返す — 採点と書き直しはやはり同一だ。

---

## 何を採点するか

商品ごとに 4 項目、それぞれ理由付きで合否を付ける。

| 項目 | 合格の条件 |
|---|---|
| 商品名 | 何の商品かを平易に言う。素の SKU でも、キーワードの山でもない。全角 35 文字前後まで |
| 説明文 | 何か、何に合うか、何が含まれるか、何が違うかに答える。本当の文が少なくとも数文 |
| 画像の alt テキスト | すべての画像に存在し、画像を説明している。商品名のコピーではない |
| SEO 用の title と description | 存在し、一意で、文字数の上限内で、商品名と別物 |

5 つ目として実行する価値がある確認：**説明文の重複**。ショップには 40 商品に同じ段落が載っていることが日常的にある。クラスターにフラグを立てる。

日本のネットショップでは、さらに **税込価格（総額表示）、送料と送料無料ライン、配送日数の目安、レビュー** が商品ページからたどれるかを見る。価格・送料そのものは書き換えない（下のルール）が、「送料が特定商取引法の表記にしかない」「価格に税込の明記がない」は所見だ。

---

## 採点の実行

何かを書く前に、まずカタログ全体に実行する。経営者は問題の大きさを見る必要がある。

```
カタログ診断 — 412 商品

SEO 用 description なし              318   77%
alt テキストなし・重複               287   70%
説明文が 80 字未満                   201   49%
説明文の本文が重複                    94   23%  (11 クラスター)
商品名が素の SKU                      38    9%
税込の明記がない                      57   14%

完全に揃っている                      41   10%

売上上位 25 のうち：19 は SEO 項目がなく、22 は alt テキストがない。
売上を取りこぼしているのはこれらなので、先に直す。
```

**スコアではなく、売上で並べる。** 年に 1 個売れる商品を直すのは、経営者の承認の注意力の無駄だ。直近 90 日の販売数または売上で並べ、上から始める。そうしていると言う。Shopify なら注文は `list-orders` で読み、`processedAt` で期間を絞る。

## 書き直し

[共有ボイスプロファイル](../../../shared/voice-profile.md)を読む。商品文はメールと同じくらいショップの声を背負う。

**商品名。** 何か、次に区別する詳細。買い手にとって意味のあるブランド、産地、内容量、素材。

```
悪い例：  ETH-YIR-200-W
悪い例：  【最安】高品質 プレミアム コーヒー豆 エチオピア 自家焙煎 スペシャルティ 送料無料 激安
良い例：  エチオピア イルガチェフェ（ウォッシュド）中煎り 200g
```

**説明文。** 最初の一文で何か、誰向けかを言う。次に具体 — 内容量、焙煎度、挽き方の選択、焙煎日からの飲み頃、保存方法。次に本当に他と違うこと。

```
エチオピア イルガチェフェ地区のウォッシュド精製豆を、神戸の自社工房で
中煎りに仕上げました。紅茶のような軽やかさと柑橘系の酸味、はちみつを
思わせる甘い余韻が特徴で、朝のハンドドリップに合わせやすい味わいです。
200g（約 14 杯分）1,620円（税込）。豆のまま・ペーパー用・フレンチ
プレス用から挽き方を選べます。焙煎日は毎回ラベルに記載。焙煎から
3 日目〜3 週間が飲み頃で、開封後は密閉して冷暗所で保存してください。
```

**alt テキスト。** 見えない人のために、画像を説明する。まずアクセシビリティの要件であり、検索の利点は二の次だ。

```
悪い例：  エチオピア コーヒー豆 通販 最安値
良い例：  ひかり珈琲焙煎所のクラフト紙袋に入ったエチオピア イルガチェフェ
          200g の正面写真。ラベルに焙煎日の記載がある
```

**商品の事実を決して創作しない。** 内容量、産地、原材料、賞味期限、認証、生産国は既存の商品データか経営者から取る。欠けているときは、推測するのではなく、それを避けて書き、フラグを立てる — 「14 商品で原材料表示の確認が必要」。誤った産地やアレルゲン表示は返品と法令違反（食品表示法）を生む。

「No.1」「最安」「効く」を書き加えない — 景品表示法と、食品・美容なら薬機法・健康増進法の問題になる。もとの説明文にあれば、削る候補として所見に挙げる。

## バッチ承認

**一度に 20〜25 商品。すべてのバッチにそれぞれの「はい」をもらう。** 3 つのサンプルでは良く見えた書き直しの型が 400 商品で間違っていれば、取り消しに午後がまるごと消える。

最初のバッチの前に、完全な before/after を 3 例見せ、型について合意を得る。3 商品で方針を直すのは何も失わない。

```
バッチ 3 / 17 — 商品 51〜75、直近 90 日の売上順

変更するもの：  商品名 25、説明文 25、alt テキスト 61、SEO 用 description 25
サンプル：      <完全な before/after を 3 組>
触らないもの：  価格、在庫、バリエーション、コレクション、公開状態
元に戻せるか：  はい — 元の値を catalog-backup-2026-07-27.csv に保存済み

この 25 件を適用しますか？
```

これを安全に保つルール：

- **最初の書き込みの前に元の値を保存する。** 現在の値の CSV を、必ず、例外なく。
- **価格、在庫、バリエーション、公開状態に決して触らない。** このスキルは商品の説明のされ方を編集する。それ以外は何も。
- **最初の異変で止まる。** 書き込みがエラーになる、または項目が送った内容と違って返ってきたら、残りのバッチを続けず、実行を止めて報告する。
- **バッチごとに報告する。** 適用、スキップ、失敗を商品名付きで。
- **Shopify・Wix への書き込みは承認後だけ。** 「はい」のないバッチは、たとえ前のバッチと同じ型でも適用しない。

## 商品の構造化データ

説明文がきれいになったら、`Offer` 付きの `Product` schema を追加する。ほとんどのショップ基盤（Shopify、Wix、BASE、STORES など）は自動生成する — 二つ目の矛盾するブロックを足す前に、すでにあるものを確認する。

真実で、見えているものだけをマークアップする：価格（税込、`priceCurrency` は `JPY`）、在庫状況、ブランド、SKU、そしてページ上の本物のレビューに基づく評価。

---

## Shopify も Wix もないとき

商品のエクスポートを頼み — ほとんどの基盤（BASE、STORES、楽天市場、Yahoo!ショッピング、カラーミーショップ）にある — インポート用の修正済みファイルを返す。

道筋を平易に言う：「商品を CSV にエクスポートしてファイルを送ってください。商品名・説明文・alt テキスト・SEO 項目を書き直した版をお返しします。それをインポートし、最初の数件を確認してから全体に流してください。」

同じ採点、同じ売上順、同じバッチでの確認。違いは経営者がインポートをクリックすることだけだ。
