**応答は常に日本語で書く。** 読んだデータや参照ファイルが英語でも、経営者への返答・確認・成果物は日本語にする（`../../shared/response-language.md`）。

# Canvaクリエイター

## 範囲

このスキルはキャンペーンを5つの連続するステージで扱い、各ステージは経営者の
承認でゲートされる：

```
ブリーフ → カレンダー → アセット棚卸し → Canva デザイン → 文章 → HubSpot への準備
```

| パス | 媒体 | このスキルが作るもの |
|------|----------|--------------------------|
| Canva（SNS） | Instagram、X、Threads、Facebook（補助）、LINE公式アカウント（リッチメッセージ画像が要る行のみ） | Canva デザイン＋キャプション＋HubSpot に予約として準備した投稿（HubSpot 非対応の媒体は手動投稿用コピー） |
| テキストのみ | メール（メルマガ、販促メール、ステップメール）、LINE公式アカウントのテキスト配信 | 件名＋プレヘッダー＋本文をインラインで示し、経営者が自分のツールから送る |

**Canva はメール行には一切使わない** — テンプレートも、オートフィルも、
デザインのコピーも、アセットアップロードも、エクスポートもない。メール画像は
このスキルの範囲外だ。メールテンプレートのオートフィルは、画像スロットが
写真の数を超えるとプレースホルダー画像を生成し、候補のサムネイルはチャットの
プレビューに表示されないからだ。経営者が Canva のメールデザインを求めたら、
`reference/gotchas.md` の誘導文を使う。

---

## 事前確認

ステージ1の前に確認する：

1. **ブリーフ。** 経営者が承認済みのブリーフを参照または貼り付けている。
   なければ：「キャンペーンを組むにはキャンペーンブリーフが必要です。
   販促戦略（`content-strategy`）で作ったものはありますか？ それとも
   今ここで書きますか？」

2. **Canva のプラン。** Pro／Teams は経営者のライブラリから手動でテンプレートを
   選ぶ必要がある（オートフィル API がない）。Enterprise はブランドテンプレート
   からオートフィルできる。どのプランでも、テンプレートに日本語フォント
   （Noto Sans JP、BIZ UDPGothic など）が設定されているかを確認する — 欧文
   フォントだけのテンプレートに日本語を流し込むと、文字化け（□）や意図しない
   代替フォントになる。

3. **HubSpot のプラン。** ソーシャル投稿の準備には Marketing Hub Professional が
   要る。Starter または Free → ステージ5を飛ばし、代わりに CSV を出す
   （[reference/hubspot-staging.md](reference/hubspot-staging.md) を参照）。
   LINE公式アカウントは HubSpot のチャネルにないので、プランに関わらず
   手動投稿用コピーか `build-connector` になる。

4. **ブランドアセット。** ネットショップ・POS（Shopify または Square —
   同格、`../../shared/connector-neutrality.md`）が接続されていれば、まず
   商品一覧を読む：ブリーフが挙げるすべての商品の商品名、画像 URL、価格
   （円、税込）。読むだけ — ステージ2のステップ5まで Canva には何も
   アップロードせず、その時点でも承認済みカレンダーのスロットに必要な画像
   だけ。この一覧が写真棚卸しの出発点で、店に画像がない商品についてだけ
   聞く。取得ルール — どの項目を読むか、価格表示のルール — は
   [../social-content-engine/reference/shopify-assets.md](../social-content-engine/reference/shopify-assets.md)
   にある（Shopify 向けに書かれている。Square のカタログ画像もツール一覧から
   同じ手順で読む）。ネットショップがなければ、商品写真のディスク上の
   パスか、ブランドキットが Canva 上で使える状態（`list-brand-kits` で
   確認できる）であることを確認する。

5. **生成予算。** キャンペーンの Canva 生成量を見積もり、ステージ1が始まる前に
   示す。既定は Canva 行ごとに候補3つ。1デザインあたり約5 API コール
   （オートフィル＋エクスポート＋ポーリング）。

   ```
   このキャンペーンの生成予算:
     Canva（SNS）行:      8
     1行あたりの候補数:   3   （既定 — 1 にするなら「候補は1つ」と言う）
     デザイン総数:        24
     API コール（概算）:  約120  （オートフィル＋エクスポート＋ポーリング）

   Canva の上限は毎分 100 リクエストです。生成は約 2〜3 分で、
   プランの上限に余裕を持って収まります。進めてよいですか？
   ```

   デザイン総数の見込みが 30 を超えるなら、最初から候補1つのモードを勧める —
   大きなキャンペーンは余裕がすぐ尽きる。経営者はステージ1が始まる前に、
   既定を行ごと 1、2、3 のどれかに変えられる。選んだ値をセッション全体で
   固定する。

## ワークフロー

### ステージ1 — 投稿カレンダー

ブリーフから引き出す：コンテンツのテーマ、媒体、頻度、固定の日付
（発売、セール、季節行事）。

すべての行を Canva かテキストのみの下書きのどちらかに振り分ける `パス` 列を
持つカレンダー表を組む：

| 日付 | 媒体 | パス | テーマ | アセット種別 | キャプション／件名の切り口 |
|------|---------|------|-------|------------|-----------------------|
| 9月2日 | Instagram フィード | Canva（SNS） | 秋の新作 | 正方形投稿 | 「やっと見つけた、秋の一枚」 |
| 9月4日 | LINE公式アカウント | Canva（SNS） | 秋の新作 | リッチメッセージ | 「友だち限定、先行のご案内」 |
| 9月5日 | メール | テキストのみ | 秋の新作 | メール本文 | 「秋の新作、店頭とオンラインで揃いました」 |

メール媒体の行はすべて、提示する前に `テキストのみ` にタグ付けする。ブリーフに
指定がなければ 30 日で区切る。予定の衝突（同じ商品の投稿が同じ日に2本）は
最初にフラグを立てる。日付は JST で、祝日・連休（お盆、年末年始、GW）と
店の定休日を確認する。

**チェックポイント1。** カレンダーを提示する。聞く：「計画と合っていますか？
ずらす日付、足す媒体、入れ替えるテーマはありますか？」承認されるまで
繰り返し、承認されたら内訳を声に出して言い直す —「N 行が Canva を通り、
M 行がテキストのみの下書きです」— それから先へ進む。分類ミスをここで
見つけるのはタダだ。デザイン生成後に見つけるのはタダではない。

---

### ステージ2 — アセットの棚卸し（Canva 行のみ）

メール行はこのステージを丸ごと飛ばす。`Canva（SNS）` の各行について、
テンプレートが必要とするものと、すでにあるものの一覧（マニフェスト）を作る。

1. **画像スロットを名前で1つずつ列挙する。** 正方形の Instagram 投稿は通常
   1〜2 スロット。カルーセルや商品グリッドは 5 以上ある。個別に列挙する
   （`Header_Image`、`Product1_Image`、`Product2_Image`、…）— 「商品画像」と
   まとめない。
   - Enterprise：ブランドテンプレートの `dataset[].label` から項目名を読む
     （`GET /v1/brand-templates/{id}`）。
   - Pro／Teams：テンプレート内の画像の矩形を1つずつ数える。
   - テキストスロットも確認する：縦書きのテキストボックスは使わない
     （SNS では読まれない）。英字だけの見出しスロットには、日本語の補助
     テキストが入るスロットが別にあるかを見る。

2. **使えるアセットを棚卸しする。** ブリーフの文章（商品名、オファーの文言、
   キャッチコピー、税込価格）、事前確認で接続ネットショップから読んだ商品
   画像 URL（ステップ5で、ギャップ表が必要とするスロットの分だけアップロード
   し、その時点で `asset.id` を記録する）、すでに Canva にアップロード済みの
   商品写真（`GET /v1/assets`）または経営者のディスク上の写真、ブランドキット
   の色とフォント（Enterprise）。キャプションの価格は、ネットショップが
   返した値かブリーフから取る。記憶からは決して取らない。価格は円の税込
   表示（総額表示義務）で、税抜だけの表示にしない。

3. **スロットごとのギャップ表を作る。** デザインごとではなく、デザイン×
   スロットごとに1行。

   | 日付 | スロット名 | 種別 | 使えるアセット | 状態 |
   |------|-----------|-----------|-----------------|--------|
   | 9月2日 | Hero_Image | image | autumn_knit.jpg → asset_id 取得待ち | アップロード |
   | 9月2日 | Headline | text | 「秋の新作、届きました」 | 準備済み |
   | 9月9日 | Product1_Image | image | — | **不足** |

4. **スロットとアセットの不一致を経営者と解決する。** テンプレートの画像
   スロットがブリーフの写真より多ければ、止まって聞く：

   ```
   「秋の新作カルーセル」テンプレートには画像スロットが5つあります。
   ブリーフでもらった写真は1枚（autumn_knit.jpg）です。残り4つはどう埋めますか？

     1. 同じ写真を5つのスロットすべてに使い回す
     2. あと4枚の写真を送ってもらう（ファイルパス）
     3. スロットの少ない簡単なテンプレートに変える
   ```

   経営者が選ぶまで生成コールを打たない。空のスロットのまま生成すると、
   Canva 既定の風景プレースホルダーだらけのデザインになる。

5. **不足する写真をアップロードし、検証済みのアセット ID を取る。**
   `POST /v1/asset-uploads` でアップロードし、`GET /v1/asset-uploads/{job_id}`
   を `status == "success"` までポーリングする。応答の `asset.id` を記録
   する — オートフィルの画像項目で使えるのはこの値だけだ。空文字、URL、
   ファイルパス、古い ID を渡すと、写真の代わりに Canva のストック風景画像が
   黙って描画される。

6. **マニフェストを確認する。** すべてのスロットが解決し、すべての画像の
   `asset.id` が確認済みのスロット別の表を経営者に見せる。ここが Canva API
   コール前の最後の停止点だ。

---

### ステージ3 — Canva デザインの生成

Canva API を呼ぶ前に、カレンダーを読み直し、`パス` が `Canva（SNS）` でない
行をすべて落とす。メール行はこのステージを通らない。

デザインは **カレンダー1行ずつ** 生成し、1行あたり候補3つ（または事前確認で
選んだ値）。各行は同じループをたどる：候補を生成 → 検証 → エクスポート →
目視確認 → 失敗を再試行 → 提示 → 経営者の選択を待つ → 次の行。行の間は
30 秒待つ。これでバーストは 30 秒あたり生成3＋エクスポート3に抑えられ、
Canva の毎分 100 リクエストの上限を大きく下回る。複数行を並列にしない。
1行ずつ進めることが、キャンペーンの途中で経営者が上限に当たらないための
防御だ。

**ポーリングの間隔。** ジョブ状態は 3〜5 秒ごとに確認し、それより速くしない。
間隔を詰めても完了は早まらず、上限を消費するだけだ。

**プレビュー URL — 埋め込んで安全なのは1種類だけ。** オートフィルの応答が
返す `design.canva.ai` のサムネイルは数分で失効する。Markdown 画像として
埋め込むと壊れた「Show Image」のプレースホルダーになる。恒久エクスポート
URL（`export-download.canva.com`、または MCP ツール `export-design`）は失効
しない。Cowork のネイティブなカルーセルはコネクタの認証済みセッションで
オートフィル結果を直接描画する — 勝手に描画させ、貼り直さない。

#### 行のループ

1. **テンプレートを決める。**（セッションに1回 — カレンダーがアセット種別を
   混ぜていない限り、全行で同じテンプレート。）
   - Enterprise：`GET /v1/brand-templates` をアセット種別で絞る。
   - Pro／Teams：`GET /v1/designs?ownership=any&query={template name}` で
     上位3件を経営者に示し、生成前に1つ確認する。

2. **行の候補を並列で生成する。** 行の3候補（または事前確認の N）を同時に
   投げる。
   - Enterprise：候補ごとに `POST /v1/autofills` にテンプレート ID と項目値を
     渡す。全ジョブを並行してポーリングする。
   - Pro／Teams：`POST /v1/designs` でコピーを作る。経営者が Canva 上で行う
     文字と画像の編集を説明し、デザイン ID を受け取る。

3. **ジョブ状態を検証する。** 候補ごとに `GET /autofills/{job_id}` が
   `status == "success"` を返し、`result.design.id` があることを確認する。
   エラーはデザインごとに処理する：
   - `JOB_FAILED` → `job.error.message` を読み、項目値かアセット ID を直して
     1回だけ再試行。
   - `RATE_LIMIT_EXCEEDED`（セッション中の初回）→ 60 秒待ち、その候補1つを
     1回だけ再試行。一時的なスパイクへの対処だ。
   - `RATE_LIMIT_EXCEEDED`（セッション中の2回目）**または** `quota_exceeded`
     ／日次上限のエラー → 生成を直ちに止める。再試行しない。進捗を示して
     聞く：

     ```
     Canva がキャンペーンをレート制限しています。ここまでの状況:
       ✓ 生成済み:  投稿 1〜4（12 デザイン）
       ⏸ 残り:      投稿 5〜8（12 デザイン、未生成）

     どう進めますか？
       1. 残りの行を候補1つに切り替える（合計4デザイン）— 今すぐ終わる
       2. キャンペーンを一時停止 — 60 分後に上限が回復したら再開
       3. 生成を止める — あるもので進め、キャプションに移る
     ```

     経営者の選択を待つ。再試行をループしない。

4. **成功した候補を恒久 PNG にエクスポートする。** 行のエクスポートは並列で
   投げる。
   - REST：`POST /v1/exports` に `format.type: "png"` を付け、
     `GET /v1/exports/{job_id}` を成功までポーリングし、`urls[0]` を取る。
   - Canva MCP：デザイン ID で `export-design`。

   この恒久 URL が、プレビューに埋め込まれ、あとで HubSpot 投稿に添付される
   ものだ。オートフィル応答のサムネイルは以降どこでも使わない。

5. **エクスポートを1つずつ目視で確認する。** 画像を見て、次のいずれかが
   あれば却下する — どれも未充填のスロットか間違ったアセットの印だ：
   - 雲と緑の丘の一般的な風景（Canva 既定のプレースホルダー）
   - 写真が入るべき場所の灰色の四角
   - Lorem ipsum やテンプレート既定の文字
   - 日本語の文字化け（□）、欧文フォントに置き換わって崩れた日本語、
     縦書きになった見出し
   - 税抜だけの価格、「PR」表記のない対価付き投稿、根拠のない「No.1」「最安」
   - ブリーフと合わない被写体（別の商品、別のブランド）

   候補が検証に落ちたら：該当スロットのマニフェストを見直し、`asset.id` を
   直し、その候補1つだけを再生成し、再エクスポートし、再確認する。

6. **一部失敗は候補単位で再試行する。** 行の N 候補のうち1つがステップ3か5で
   失敗したら、その1つだけを再生成する — 行全体をやり直さず、一部が壊れた
   カルーセルを提示しない。2回目も失敗したら：

   ```
   9月9日の投稿の3つ目の候補が失敗し続けています — Canva が
   [エラー／プレースホルダーの描画] を返しました。どう進めますか？

     1. 飛ばす — 残り2つを提示して先へ進む
     2. この候補だけ簡単なテンプレートに変える
     3. 別の写真でもう1回だけ試す
   ```

7. **行の候補を提示する。** Cowork のネイティブなカルーセルにオートフィルの
   ツール結果を描画させる。その下に文章で促す：

   ```
   9月9日の候補ができました — 上のカルーセルをスクロールしてご覧ください。
   9月9日の投稿にはどれを使いますか？
   ```

   カルーセルが描画されない、または1枚が壊れているときは、代わりにステップ4
   の恒久エクスポート PNG URL を埋め込む。最後の手段は、デザインの Canva
   編集 URL（`https://www.canva.com/d/{design_id}`）へのリンク。
   `design.canva.ai` の URL は決して貼り直さない。

8. **30 秒待って、次の行へ。**

**チェックポイント2。** 経営者がカレンダーの行ごとにデザインを1つ選んだら
満たされる。再生成の希望があれば、その候補1つだけを再生成する。

---

### ステージ4 — 文章の下書き

カレンダーの行ごとに文章を下書きする。SNS 行はキャプション、メール行は
メール全文。

**SNS のキャプション** — Instagram、X、Threads、Facebook、LINE公式アカウント：

- 長さ：媒体に合わせる（Instagram は 2,200 文字以内、Facebook は 500 文字
  以内推奨、X は 140 字以内（全角は2文字として数えられる）、Threads は
  500 文字以内、LINE の配信は 200 字以内でリンク1つ）。
- 構造：つかみ → 商品の利点1つ → 行動の呼びかけ → ハッシュタグ 3〜5 個
  （30 個ではない。日本語と英語を混ぜる。例：`#秋の新作 #大阪セレクトショップ #ootd`）。
- 声：ブリーフのトーン指標に合わせる。ブリーフが「気さくで親しみやすく」と
  言っているなら、会社案内のような文章を書かない。
- 埋め草なし。「お知らせです！」「この度、〜することとなりました」は使わない。
  価値から入る。
- 法規の確認をキャプションごとに行う：対価を伴う投稿（インフルエンサー依頼、
  モニター提供、アフィリエイト）には「PR」「広告」の表記（景品表示法のステマ
  規制）。「No.1」「最安」「日本一」は根拠資料がなければ書かない。美容・
  健康・食品は薬機法・健康増進法に触れる効能表現（「治る」「痩せる」
  「若返る」）を避ける。価格は税込の総額表示。該当しそうな表現はフラグを
  立て、経営者に判断を仰ぐ。

**メールの内容** — Claude がメール全文を書く。Canva は使わない：

- 件名：30 字以内、具体的に、釣りにしない。「秋の新作、店頭とオンラインで
  揃いました」は「お見逃しなく！」に勝る。
- プレヘッダー：50 字以内、件名を繰り返さず補う。
- 本文：平文で 200〜400 字。読む価値を最初の一行で示す → 中身のある段落を
  1〜2 つ → 明確な行動の呼びかけ1つ → 結び。
- 声：SNS と同じトーン指標。経営者はメールが自分らしく聞こえてほしいので
  あって、テンプレートのメルマガのようには聞こえてほしくない。
- 画像への言及なし。「上の画像をご覧ください」と書かない。経営者が
  ビジュアルを望むなら、自分のメールツールで足す。
- 行動の呼びかけはメール1通に1つ。最も重要な行動を選び、それを前に出す。
- 特定電子メール法：配信は同意済み（または取引関係のある）相手に限り、
  送信者名・住所・配信停止の方法を本文か署名に含める。

キャプションは各 SNS 行の下にインラインで示す。メールは各メール行の下に
全文をインラインで示す：

```
件名: <件名>
プレヘッダー: <プレヘッダー>

<本文>
```

実例は
[reference/examples/boutique-brief-campaign.md](reference/examples/boutique-brief-campaign.md)
を参照。

**チェックポイント3。**「書き直すキャプションやメールはありますか？ 日付と
直したい点を教えてください。」承認されるまで繰り返す。

### ステージ5 — HubSpot への準備＋メールの引き渡し

SNS 投稿を HubSpot に準備する。メールの内容は準備しない — 経営者が自分の
メールツールに貼れるようインラインで示す。API の項目リファレンスは
[reference/hubspot-staging.md](reference/hubspot-staging.md) を参照。

このスキルにスケジューラはない。予約投稿は HubSpot 側、または各媒体の管理
画面（Meta Business Suite、LINE Official Account Manager、X の予約機能）の
機能だ。このスキルがするのは、承認済みの投稿をそこに置くことだけ。

1. **キャンペーンを作る。** `POST /marketing/v3/campaigns` にカレンダーの
   キャンペーン名と開始日・終了日を渡す。

2. **SNS 投稿を1つずつ準備する。** `Canva（SNS）` 行ごとに HubSpot Social API
   へ `POST`：
   - `channel`：カレンダーの媒体を HubSpot のアカウント ID に対応付ける
   - `scheduledAt`：ISO 8601 の日時（`+09:00`）— 呼ぶ前に未来であることを
     確認する
   - `content.body`：承認済みのキャプション
   - `attachments`：ステージ3の恒久 Canva エクスポート PNG URL
   - `status`：`SCHEDULED`（決して `PUBLISHED` にしない）

   LINE公式アカウント、Threads など HubSpot のチャネルにない媒体の行は、
   `build-connector` で接続していなければ手動投稿用コピー（本文＋恒久画像
   URL＋配信時刻）にまとめる。

3. **キューを確認する。** `GET /marketing/v3/social/posts?status=SCHEDULED`
   を呼び、一覧を示し、HubSpot のキャンペーン画面への直接リンクを添える。

4. **メールの内容を引き渡す。** メール行ごとに、承認済みの件名＋プレヘッダー
   ＋本文を配信日ごとにまとめてインラインで示す。経営者がこれを自分のメール
   ツール（HubSpot のマーケティングメール、Mailchimp、Gmail または
   Microsoft 365）に貼る。

**最終チェックポイント。**

```
SNS 投稿は HubSpot に予約として準備しました: [リンク]
時刻になると自動で公開されます — 公開前なら HubSpot 上でどの投稿も
取り消し・編集できます。LINE の配信は下の手動投稿用コピーを
LINE Official Account Manager の予約配信に貼ってください。

メールの文章は下に下書きしました — 送る準備ができたら、
お使いのメールツールに貼ってください:

  9月5日  — 「秋の新作、店頭とオンラインで揃いました」
  9月19日 — 「秋のアウター、全サイズ揃っています」

仕上げる前に直すところはありますか？
```

この要約と並べて — 置き換えではなく — キャンペーンをハウススタイル
（`../../shared/artifact-style.md`）の HTML アーティファクトとして描画する：
投稿カレンダーを表に、各行に媒体別の状態ピル（準備済み／下書き／引き渡し）、
行ごとに承認済みのキャプションまたはメール文面とエクスポート PNG のリンクを
持つ準備済み投稿パネル。

**締めの提案。** キャンペーンに今何が入っているかを一行で述べ、次に最も
関連する一手をトリガー語句付きで示す — 通常は、投稿が出始めたら
「マーケティングは効いている？」（`growth-pulse`）。ほかに最大2つ：継続
カレンダーの「コンテンツを作って」（`social-content-engine`）や「広告の状況」
（`ad-manager`）。最大3つ。このセッションで経営者が断ったものは出さない。

## 承認ゲート

- **メール行のために Canva を呼ばない。** API コールのたびに `パス` 列を
  確認し直す。
- **公開しない。** すべての HubSpot 投稿は `SCHEDULED` として準備する。
  公開のタイミングは経営者が握る。
- **スケジューラを自作しない。** 予約は HubSpot か各媒体の機能。このスキルが
  時刻を監視して投稿することはない。
- **生成予算は必ず事前確認で示す。** 経営者がデザイン総数を見て承認して
  から、ステージ1を始める。
- **ステージ3は1行ずつ。** 行内の候補は並列で投げるが、行同士は 30 秒空けて
  順に進める — これが上限対策だ。
- **2回目の上限エラーで止まって聞く。** 再試行をループしない。
- **提示前に必ず恒久 PNG にエクスポートする。** ジョブの成功は、デザインが
  正しく描画されたという意味ではない。
- **`design.canva.ai` の URL をメッセージに埋め込まない。** 失効する。
- **候補1つの失敗で行全体を再生成しない。** 候補単位の再試行だけ。
- **Pro／Teams でテンプレートを自動選択しない。** 必ず確認する。
- **スロット単位の棚卸しを飛ばさない。** 複数スロットのテンプレートは、
  どれか1つでも空だとプレースホルダーの風景を描画する。
- **チェックポイント1を飛ばさない。** カレンダー承認前の生成は、このスキルで
  最大の無駄な作業の発生源だ。
- **価格・割引・商品の効能をでっち上げない。** 税込表示と「PR」表記を
  落とさない。

## 一覧にないツールを使うとき

このスキルに書かれたコネクタは検証済みの経路であって、壁ではない。経営者が接続されていない、または一覧にないツールでこの流れを回したいなら、`build-connector` を提案する — まずコネクタディレクトリを確認し、なければ Zapier 経由で接続し、生の API に対して手組みはしない。接続ができれば、そのツールは他の任意コネクタと同じく、同じ承認ゲートのもとでこのスキルに加わる。
