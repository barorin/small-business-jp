# 営業メール作成

経営者が自分の名前で本当に送れる営業メールを書く。

経営者が最も繰り返す条件は、何らかの形の「AI っぽくならないように」だ。経営者は自分が恥ずかしくなる文面を送らない。生成物だと読める文面は、どれだけ構成が良くても価値がない。声の忠実さがここでの製品であり、仕上げの一手間ではない。

## ステップ1 — 書く前に声を学ぶ

まず [共有のボイスプロフィール](../../shared/voice-profile.md) を読む。プロフィールがすでにあればそれを使い、ステップ2 へ進む — 毎回作り直すのは経営者の忍耐を浪費し、声がぶれる原因になる。

プロフィールがなければ、証拠から作る:

- **Gmail または Microsoft 365** — 経営者本人が顧客や見込み客に送った送信済みメールを 15〜30 通引き出す。これが群を抜いて最良の情報源だ。先にそのメールボックスが経営者本人のものであることを確認する（`../../shared/tenant-scope.md`）。別のテナントの送信済みメールでは、間違った声を学んでしまう。
- **CRM（HubSpot など）** — 記録されたメールとメモ
- **Web サイトと公開している文章** — 弱いが、本物
- **貼り付けてもらった例** — 気に入っているメールを 3 通もらう

次に、具体的で真似できる特徴を抽出する: 文の長さ、書き出しと結びの癖、敬語の水準（「です・ます」か「でございます」か）、「！」を使うか、お願いまでどれだけ直接的か、自社の商品・サービスを何と呼ぶか、方言や業界の言い回し、そして絶対にやらないこと。プロフィールを保存し、以後の実行がすべて引き継げるようにする。

**サンプルが一つもなければ、そう言って 3 通求める。** 推測した声で書くと、経営者が避けたい汎用的な文面がそのまま出てくる。

## ステップ2 — 一通ごとに実在の事実に根ざす

パーソナライズされたメールとは、テンプレートに社名を差し込んだものではない。その人にしか送れないメールのことだ。

見込み客ごとに、固有のフック（切り口）を探す。強い順に:

1. `lead-finder` の購買シグナル — 建築計画のお知らせ、新店舗の開店、求人の掲載
2. 共通の知人・顧客
3. 相手の事業について経営者が本当に語れる具体的なこと
4. 似た顧客で経営者が実際に出した結果

業種が合う以外のフックがなければ、短く、率直に冷たいメールを書き、それが冷たいものだと伝える。温かいふりをした書き出しは正直な冷たさより悪い。差し込み印刷に読めて、一行目で信用を壊すからだ。

**Apollo または Clay が接続されていれば、薄いフックを使えるものにする担当者・会社の詳細を補える** — 役職、在任期間、会社の規模、使用中のシステム — メールが汎用に読まれないようにする種類の具体性だ。補完データであって、それ自体はフックではない。国内企業の網羅率は限定的なので、ヒットしなくても書けないことにはならない。

## ステップ3 — 一連のメッセージを書く

シナリオ別の構成は `reference/sequence_patterns.md` を読む。既定値:

- **新規（コールド）** — メール 3 通＋電話 1 回、3 週間
- **紹介・つながりあり** — 3 通、2 週間
- **商談後のフォローアップ** — 2 通、10 日
- **休眠顧客の掘り起こし** — 3 通、4 週間

一連の中の各メッセージは、必ず何か新しいものを足す。中身が「念のため再送いたします」だけのフォローアップは、相手に送信者を無視することを教える。接触ごとに新しい存在理由を与える: 別の切り口、関連する実績、本当に役に立つ情報、あるいはきれいな締め。

長さのルール: 初回は 400 字以内。この規模の経営者の相手は、現場の合間にスマホで読む人だ。

## ステップ4 — AI 臭チェックで自己点検する

何かを見せる前に、すべての下書きを `reference/slop_test.md` にかける。機械が書いたと読ませる特定のパターンを捕まえる。

最速のチェック:

- 経営者はこの文を声に出して言うか？ 言わないなら書き直す。
- 社名を入れ替えれば他の会社にも送れるか？ 送れるなら、パーソナライズされていない。
- 相手の事業への褒め言葉で始まっているか？ 削る — 誰もがやっていて、誰もが見抜く。
- 経営者が人生で一度も使ったことのない言い回しがあるか？ 削る。

このステップは省略不可で、形式でもない。送られる文面と、手で書き直される文面の分かれ目であり、後者こそこのスキルが防ぐために存在する結果だ。

## ステップ5 — 承認のために提示する

何かを送信待ちにする前に、一連の全体を見せる。`reference/output_template.md` に従う。

1 通目は全文を、残りは件名と各通の切り口を提示する。経営者は 1 通目を精読し、残りは形を流し読みしたい。

**保存されている経営者の出力形式で納品する — 既定で markdown ファイルにしない。** `## Business context` ブロックの `出力形式` を確認する（共有スタイルガイドのルール、`../../shared/artifact-style.md`）:

- **visual artifacts（既定）:** ハウススタイルの HTML ページ — 見込み客または一連のメッセージごとに 1 枚のカード、各メッセージはコピーブロックにして、どの一通でも単体でコピーして手で送れるようにする。
- **docx / md / notion / canva の指定:** 同じ内容をその形で納品する — DOCX または markdown ファイル、コネクタ経由で作る Notion ページ（指定された保存先に、上書きはしない）、または Canva コネクタで作る Canva Doc（実行ごとに新しいデザイン、日付を名前に含める。表はリストに変換）。Notion や Canva が未接続なら visual artifacts に戻し、その理由を言う。
- **best for skill:** visual artifacts を使う — コピーブロックが要点だ。

どの場合もチャットには要約と承認の質問を残す。

そして何を変えるか聞く。修正は当然あるものと考える — 初回は提案であって納品ではない。すべての修正をボイスプロフィールに戻す。一度された修正を二度させてはならない。

## ステップ6 — 承認を得て送信待ちにする。ゲートは一つずつ

経営者の名前でメールを送ることは、このスキルで最も結果の重い行為だ。

- **そのバッチに対する明示的な「はい」なしに送らない**
- **聞く前に、何が起きるかを正確に述べる**: 何通、誰に、どの日程で、どのアカウントから
- **「推定」と印の付いた連絡先には、別途フラグを立てずに送らない。** 大量のバウンスは経営者の送信ドメインを何か月も傷つけ、その損害は本物の顧客メールにも及ぶ
- **1 通目の承認は、一連全体の承認ではない。** フォローアップは別に確認するか、下書きにしておいて経営者が一通ずつ出せるようにする
- **特定電子メール法の表示を確認する。** 送信者の名称、住所、受信拒否の連絡先が署名にあるか。広告宣伝メールは原則オプトインで、送ってよい相手は、同意がある、名刺交換した、取引関係がある、または Web サイトにアドレスを公開している（営業お断りの表記がない）事業者に限る。受信拒否が来た相手には二度と送らない

**Mailchimp は下書きの保存先であって、送信経路ではない。** 接続されていれば、承認済みの一連のメッセージをキャンペーン内容として Mailchimp に保存し、経営者がそこで配信予約できる。これを決めるのは三つ:

- **送信はできない。** このスキルが Mailchimp に入れたものは、勝手には出ていかない。経営者が Mailchimp で送信ボタンを押す。
- **プランナーは単発のキャンペーンを拒否する。** Mailchimp のキャンペーンプランナーはマルチチャネルの計画 — メール＋SMS＋SNS — しか作らない。単発のメールはここで、経営者の声で書き、内容として保存する。単発のメッセージをプランナーに通さず、拒否を失敗として報告しない。
- **オーディエンスリストを読めると仮定しない。** 実際に呼び出して返ってこない限り、連絡先リストは利用不可として扱う。受信者リストは従来どおり CRM か経営者自身のファイルから作る。

**メールコネクタがなければ、下書きのみで動く。** どこにでも貼り付けられる形式で文面を出す。これは完全な成果であって、劣化した成果ではない — 自分のメールソフトから送りたい経営者は多い。

## ステップ7 — 記録する

CRM（HubSpot など）が接続されていれば、接触ごとに記録する: 何を送ったか、いつ、誰に、一連の中のどこか。CRM がなければファイルに記録し、次回の実行が誰にすでに連絡済みかを分かるようにする。

同じ書き出しで同じ人に二度連絡するのは、目に見える、避けられる失敗だ。

## やってはいけないこと

- **声を学ぶ前に書かない。** 下流のすべてがそれに依存する。
- **相手の事業への褒め言葉で始めない。** 最も分かりやすい AI の印だ。
- **「念のため再送」だけのフォローアップを送らない。** すべての接触に存在理由を。
- **テンプレートに社名を差し込んで「パーソナライズ」と呼ばない。**
- **そのバッチへの明示的な承認なしに何も送らない。**
- **経営者が実際に出していない実績を書かない。** 営業メールの中の架空の事例は、誇張ではなく深刻な問題だ。

## 送信の後

一連のメッセージが承認され、送信待ちまたは下書きになり、接触はすべて記録された。自然な次の一手は「CRM を整えて」— `crm-autopilot` が返信の来るたびに次のアクションの一覧を最新に保つ。近くにあるもの: 「リードが冷めてきた」（`speed-to-lead`）で返信を素早く捕まえる、「お客さんを探して」（`lead-finder`）でこのリストが尽きたとき。提案は最大 3 つまで。このセッションで経営者がすでに断ったものは出さない。

## 載っていないツールを使いたいとき

このスキルに名前のあるコネクタは検証済みの経路であって、壁ではない。経営者が未接続・未記載のツールでこの流れを回したいなら、`build-connector` を提案する — まずコネクタディレクトリを確認し、なければ Zapier 経由で接続する。生の API に対して手組みはしない。接続ができれば、そのツールは他の任意コネクタと同じく、同じ承認ゲートの下でこのスキルに加わる。
