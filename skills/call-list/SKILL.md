**応答は常に日本語で書く。** 読んだデータや参照ファイルが英語でも、経営者への返答・確認・成果物は日本語にする（`../../shared/response-language.md`）。

リードの優先順位付けを実行する。パイプラインを走査し、緊急度と機会で順位付けし、関連するメールの文脈を引き、経営者が電話を掛けられる状態にする。

引数を解釈する：
- `--n`（既定: `5`）— 表示するリードの件数（1〜10）
- `--date`（既定: 今日）— 架電リストを作る日付（`YYYY-MM-DD`、JST）

## ステップ1 — パイプラインの走査（lead-triage）

取得とスコアリングは `lead-triage` スキルのワークフローを実行する — HubSpot のフィールド一覧、4 軸のモデル（反応・会社の適合度・緊急度・直近接触の減点）、緊急度のためのメモ本文取得、フラットスコアの確認、補完の脚（Apollo または Clay が接続されていれば、会社の登録がないリードの会社の適合度を埋める。従量課金で国内企業の網羅率は限定的なので、lead-triage がクレジットの費用について一度聞く。その質問はこちらで答えず、経営者にそのまま渡す）はすべて lead-triage が持つ。ここで作り直さない。次に、残った各リードについてメール（Gmail または Microsoft 365）からスレッドを引き（連絡先ごとに直近 3 通）、話す要点にする。

## ステップ2 — 順位付けと上位 N 件の選択

lead-triage の順位を受け取り、上位 `--n` 件を選ぶ — その件数のリードが存在する限り、パイプラインの規模にかかわらず常にちょうど `--n` 件。同点なら、未返信の受信シグナルがあるリードを優先する。lead-triage がフラットスコアを報告したら、代わりにその CRM 事実のはしご順で提示し、そう伝える。

選んだリードごとに架電カードを作る：

```
{順位}. {氏名} 様 — {会社名}
商談: {金額}円 | ステージ: {ステージ} | 最終接触: {X 日前}
シグナル: {最新の活動}

話す要点
• {メール・商談の文脈からの要点}
• {メール・商談の文脈からの要点}
• {聞くべき未解決の質問}

この電話のゴール: {一文 — 次のステージへ進める／関係を再開する／受注する}
```

商談金額は円で 3 桁区切り（税込・税抜は CRM の入力どおり）。外貨の商談は ISO コードを前置する（`USD 12,000`）。金額が空なら「未設定」と書き、0 円にしない。最終接触が空なら「未接触」と書き、「今日」にしない。

## ステップ3 — カレンダーの確保

リストの各リードについて、対象日の経営者のカレンダーに 20 分の架電枠を確保することを申し出る。

枠は日本の商慣行に合わせる：**10〜12 時と 14〜17 時（JST）** に限り、昼休みの 12〜13 時、月曜の午前、金曜の夕方、祝日は避ける。相手が飲食店なら仕込み前や中休みの 14〜17 時、クリニックなら逆に昼休みのほうが通じやすい、といった業種による例外はメールの文脈から拾う。Google カレンダーの `suggest_time` が返す候補は出発点にすぎない — `list_events` で対象日の実際の予定と突き合わせ、既存の予定の前後 15 分に重なる候補は落としてから提示する。

提案するカレンダーの予定を見せる：
```
{時間枠} — 架電: {氏名} 様（{会社名}）
```

どの架電を確保するか経営者が確認するまで、カレンダーの予定を作らない。

## ステップ4 — フォローアップの下書き

未返信のメールが 3 日より古いリードには、短いフォローアップを下書きする：
```
件名: Re: {スレッドの件名}

{会社名}
{氏名} 様

お世話になっております。{経営者の会社名}の{経営者名}です。

{前回のやり取りに触れる一文}。{次の一手または質問を明確に示す一文}。

{結びの挨拶と署名}
```

## コネクタの障害

CRM（HubSpot など正の CRM）に到達できなければ、止まって経営者に伝える — リードのスコアリングには CRM のデータが要る。メールに到達できなければ、ステップ1 のメール文脈の取得とステップ4 のフォローアップ下書きを飛ばし、出力に「メール未接続 — メールの文脈とフォローアップ下書きは省略」と書く。ステップ3 のカレンダー確保はそのまま実行する。Google カレンダーに到達できなければ、カレンダー確保を飛ばしてその旨を書く。補完コネクタに到達できない、または経営者が補完の費用を断ったなら、会社の登録がないリードの会社の適合度は平坦のまま — 適合度で順位付けしたかのように提示せず、出力でそう言う。

## 承認ゲート

- **メールを自動送信しない。** 下書きを経営者の承認のために提示するだけ。
- **経営者の確認なしにカレンダーの予定を作らない** — 先に提案リストを見せる。
- **HubSpot の商談ステージを自動更新しない。**

## 出力

話す要点付きの順位付き架電リストを提示する。次に提案するカレンダー枠を見せて確認を求める。次にフォローアップの下書きを見せ、どれを送るか聞く。

チャットの要約と並べて — 置き換えではなく — リストを「架電シート」のアーティファクトとしてハウススタイル（`../../shared/artifact-style.md`）で描画する。経営者が印刷して電話しながら手元に置くもの。印刷向きの行をリードごとに 1 行、それぞれに電話のゴールと短い話す要点 2〜3 個、結果を手書きする空欄を付ける。これは作業用シートであってダッシュボードではない — 統計タイルもグラフもなし。

## 締めの提案

何ができたかを一行で伝え、次に最も関連する次のステップをトリガーの言い回しとともに示す — たいていは電話よりメールが向くリードのための「営業メールを書いて」（`outreach-composer`）。合えばあと 2 つまで：「見込み客を増やしたい」（`/grow-pipeline`）または「CRMを更新して」（`crm-autopilot`）。最大 3 つ、このセッションで経営者がすでに断ったものは省く。

## 一覧にないツールを使う

このスキルで名前を挙げたコネクタは検証済みの経路であって、壁ではない。経営者がこの流れで未接続・一覧にないツールを使いたければ `build-connector` を提案する。コネクタディレクトリを先に確認し、なければ Zapier 経由で接続する。生の API に対して手作りはしない。接続ができれば、そのツールは他の任意コネクタと同じく同じ承認ゲートの下でこのスキルに加わる。
