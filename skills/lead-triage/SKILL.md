# リードの優先順位付け

## クイックスタート

HubSpot から問い合わせリードを取得し、スコアリングし、話す要点付きの順位付き架電リストを出す。フォローアップを下書きし、カレンダーの空き枠を提案する。経営者の承認なしに送信も予約もしない。

```
経営者：「リードに優先順位を付けて」
→ 連絡先を取得：ライフサイクルステージが Lead または MQL、ステータスが Unqualified 以外
→ 各リードを 反応・会社の適合度・緊急度・直近接触 の4軸でスコアリング
→ 順位付きリスト（件数は量に応じて調整）を話す要点付きで返す
→ フォローアップの下書きとカレンダー枠の提案を申し出る
```

## ワークフロー

1. **HubSpot からリードを取得する。** `lifecyclestage` = `Lead` または `MQL`、かつ `hs_lead_status` ≠ `Unqualified` の連絡先を取得する。フィールド一覧は [reference/hubspot-scoring.md](reference/hubspot-scoring.md)。HubSpot が使えない（未インストール、未接続、エラー）ときも止まらない。その旨を率直に伝え、このファイル末尾の「HubSpot がない？」の経路を実行する。CSV エクスポートか、ざっくり貼り付けたリストをもらい、それをスコアリングする。kintone、Monday.com、Salesforce、Zoho CRM が正の CRM なら、同じスコアリングを各 CRM の相当するフィールドに当てはめる（kintone はアプリ設計が事業者ごとに異なるので、接続後に `build-connector` でフィールド構成を確認する）。
   - **空のポータルの確認。** 取得結果がどのライフサイクルステージでも 0 件なら、絞り込みの間違いではなくポータルが空だ。一行でそう伝え、HubSpot 自身の初期設定（`manage_onboarding`、アクション `SET_GOAL`）か「HubSpot がない？」の経路を提案する。何も入っていないポータルでライフサイクルステージの診断をしない。判定はカウントで行う。`get_user_details` は `onboarded` フラグを返すが、連絡先が数百件あっても `onboarded: false` を返すことがあるので、フラグだけでは決めない。

2. **トリガーがあいまいなら確認する。** 経営者が修飾語なしに「パイプライン」とだけ言ったら聞く：*「パイプラインの概況（商談ステージごとの件数と合計金額）ですか、それとも優先順位付きの架電リストですか？」* そのうえで振り分ける。「パイプライン」だけでリードのスコアリングをしない。

3. **各リードをスコアリングする。** [reference/hubspot-scoring.md](reference/hubspot-scoring.md) の4軸モデルを適用する：
   - **反応** — HubSpot 上のメール返信、開封、サイト訪問（直近 30 日のみ）
   - **会社の適合度** — 業種と従業員数を経営者の理想顧客像（ICP）と照合（既定：業種不問、従業員 1〜50 名）。連絡先レコードではなく、リードに紐づく会社レコードから読む。スコアリング参照を見ること。会社が紐づいていないリードがあり、企業情報の補完コネクタ（Apollo または Clay）が接続されていれば、スコアリング参照の補完の脚がメールドメインから業種と規模を埋める。従量課金であり、国内企業の網羅率は限定的だ。何件を補完し、クレジットで何がかかるかを伝え、この実行に対する経営者の「はい」があるときだけ動かす。補完した内容をここから CRM に書き戻すことはしない。
   - **緊急度** — リードの経過日数、ステージ滞在期間、メモに「至急」「急ぎ」「期限」「予算確保済み」（英語のメモなら "urgent / ASAP / deadline / budget approved"）が含まれるか。キーワード判定には、連絡先 → メモの関連付けを通じて実際にメモ本文を取得する必要がある。スコアリング参照の「メモ本文を取得する」節に従う。メモの件数だけでは発火できない。
   - **直近接触の減点** — 最終活動が 24 時間以内（今日すでに接触済み）なら減点する

   **次に、スコアが実際に分かれたかを確認する。** 最高と最低の合成スコアの差が 10 点未満なら、CRM に順位付けの根拠となるシグナルがない。その並びを順位として提示しない。スコアリング参照のフラットスコアの経路を実行し、シグナルが空だと率直に伝え、代わりに CRM 上の事実で並べる。偽の順位は経営者を間違った相手への電話に向かわせる。

4. **順位付きリストを作る。** 合成スコアの降順に並べる。件数は量に応じて調整する：
   - 10 件以下 → 全件表示
   - 11〜30 件 → 上位 5 件
   - 30 件超 → 上位 8 件

   各リードに：氏名、会社名、スコア、話す要点（1段落）、最終活動の要約。反応のシグナルがすべて 30 日より古ければフラグを立てる：*「反応のシグナルが古い — 新規アプローチとして接する。」*

5. **フォローアップの下書きを申し出る。** 聞く：*「この中でフォローアップを下書きしますか？」* はいなら、選ばれたリードごとにメールを1通、[共有の文体プロファイル](../../shared/voice-profile.md)に従って経営者の文体で書く。プロファイルがまだなければ、その「サンプルがないとき（When there is no sample）」の指示に従う。経営者が満足したメールを3通もらい、断られたら平易で中立な文で書き、下書きは文体未反映だと伝える。人格を創作しない。下書きを見せる。送信しない。メールが使えなければ、件名と本文をチャットで渡して経営者が貼り付けられるようにする。それで完結した成果だ。

6. **仕分けボードをアーティファクトとして描画する。** 短いチャットの回答の後に（代わりにではなく）、ハウススタイル（`../../shared/artifact-style.md`）で HTML ページを作る。各リードの合成スコアを等幅で示す順位表、行ごとの緊急度ステータスピル（good / warn / critical）、各リードの下に話す要点の行。フラットスコアの経路が発火したならページ上でそう伝え、ピルの色を中立に落とす。

7. **カレンダー枠を提案する。** 聞く：*「この中で架電の時間枠を提案しますか？」* はいなら、Google カレンダーで翌2営業日の 30 分の空き枠を探す（既存の予定の前後 15 分は避ける）。日本の商慣行に合わせ、**10〜12時と 14〜17時（JST）** に限り、昼休みの 12〜13時、月曜の午前、金曜の夕方は避ける。リードごとに2つの候補を提案する。経営者の明示的な承認なしにカレンダーの予定を作らない。カレンダーが使えなければ、経営者に提示できる時間帯を2〜3つ聞き、時刻を創作せずそれを使う。

## 承認ゲート

- **メールを送らない。** 下書きのみ。経営者が自分のメールから送る。
- **経営者が承認するまでカレンダーの予定を作らない。**
- **経営者が明示的に求めない限り、ライフサイクルステージを変えず、リードを Unqualified にしない。**
- **`Customer` や `Evangelist` のライフサイクルの連絡先をリード一覧に含めない。**
- **絞り込みに一致するリードが 0 件なら**、理由を説明し、使われているライフサイクルステージの確認を申し出る。リストを捏造しない。

## 締めの提案

仕分けで何ができたかを一行で伝え、次に最も関連する次のステップをトリガーの言い回しとともに示す。たいていは「架電リスト」（`/call-list`）で順位にカレンダーのブロックを加えること。合えばあと2つまで：「営業メールを書いて」（`outreach-composer`）または「CRMを更新して」（`crm-autopilot`）。3つを超えず、このセッションで経営者がすでに断ったものは再提案しない。

## HubSpot がない？

リードのリストを貼り付けるかアップロードしてもらう。CSV エクスポートでも、ざっくりしたリストでも動く。スコアリングと話す要点は同じ手順で作り、順位付きの架電リストは CRM に書き込む代わりにチャットとファイルで返す。

## 一覧にないツールを使う

このスキルで名前を挙げたコネクタは検証済みの経路であって、壁ではない。経営者がこの流れで未接続・一覧にないツールを使いたければ `build-connector` を提案する。コネクタディレクトリを先に確認し、なければ Zapier 経由で接続する。生の API に対して手作りはしない。接続ができれば、そのツールは他の任意コネクタと同じく同じ承認ゲートの下でこのスキルに加わる。
