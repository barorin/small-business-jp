# 落とし穴 — lead-triage

---

## 落とし穴：「パイプライン」だけのトリガーで、状況確認が欲しいだけの経営者にフルスコアリングを走らせる

**なぜ重要か：** 「パイプライン」単独はあいまい — 経営者が欲しいのは商談ステージごとの合計であって、スコア付きの架電リストではないかもしれない。

### ✗ 悪い例
```
経営者：「パイプラインはどう？」
Claude：[フルスコアリングを実行し、12 件の順位付きリストを返す]
```

### ✓ 良い例
```
経営者：「パイプラインはどう？」
Claude：「パイプラインの概況（商談ステージごとの件数と合計金額）ですか、それとも
         今日の優先順位付き架電リストですか？」
```

## 落とし穴：古い反応データがスコアを水増しする

**なぜ重要か：** `hs_email_open` は累積値 — 1 年前のキャンペーンの開封が、冷めたリードを熱く見せる。

### ✗ 悪い例
```
リードに開封 20 回（すべて 11 か月前）。反応で 25/25 点。
1 位に表示。経営者が電話すると、相手は会社名すら覚えていない。
```

### ✓ 良い例
```
反応のシグナルは 30 日で打ち切る。すべてのシグナルが 30 日より古ければ
反応スコア = 0 とし、話す要点に書く：
「反応のシグナルが古い（最終: [日付]）— 新規アプローチとして接する。」
```

## 落とし穴：顧客がリード一覧に混ざる

**なぜ重要か：** `Customer` や `Evangelist` に見込み客として電話するのは気まずい。既存の保守契約先に「初めまして」と掛ければ信用を失う。

### ✗ 悪い例
```
ライフサイクルの絞り込みを適用せず → 既存顧客が 2 位に表示される。
```

### ✓ 良い例
```
厳密に絞る：lifecyclestage = Lead または MQL のみ。
ライフサイクルステージが空の連絡先は、警告フラグ付きで含める：
「⚠ ライフサイクルステージ未設定 — 電話の前にリードであることを確認。」
```

---

## 落とし穴：既存の予定と重なるカレンダー枠を提案する

**なぜ重要か：** 経営者がすでに埋まっている時間を提案すると、信頼が即座に崩れる。

### ✗ 悪い例
```
Claude がカレンダーを確認せずに「火曜 14:00–14:30」を提案。
経営者はその時間に顧客との打ち合わせが入っている。
```

### ✓ 良い例
```
枠を提案する前に、翌 2 営業日のカレンダーを取得する。
既存の予定の前後 15 分の余白を含めて空いている時間帯だけ提案する。
10〜12 時・14〜17 時（JST）に限り、昼休みの 12〜13 時、月曜の午前、金曜の夕方、
祝日は避ける。空きがなければそう言い、さらに先を探すことを申し出る。
```
